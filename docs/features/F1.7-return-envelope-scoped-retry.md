# F1.7 - Return Envelope / scoped retry

**Status:** implemented; real-Codex demo executed 2026-11-17 (`docs/validation/F1.7-real-codex-demo.md`); independent review not recorded (ADR-0015)
**Priority:** P0
**Target phase:** Phase 1 - Agent Loop
**Depends on:** F1.5, F1.6

## Problem

A correction loop can retry one failed node, but a batch producer could still
rerun accepted sibling units after one unit fails. That wastes work and hides
which result was already accepted.

## Goal

Represent feedback as a Return Envelope and retry only the rejected logical
unit. Preserve accepted A/B/D runtime outputs while correcting C, with a
bounded attempt history.

## Non-goals

- Cross-unit replanning, automatic rollback of filesystem writes, Git
  worktrees or general distributed transactions.

## Functional requirements

1. A typed Return Envelope contains unit ID, verdict, reason, evidence,
   scope and attempt ID; it links to its Check Result and source execution.
2. A red envelope identifies exactly one retryable unit. A green envelope
   freezes that unit's accepted runtime output for the current run. Duplicate
   or conflicting unit IDs fail rather than overwrite accepted values.
3. A per-unit retry creates a new attempt only for the rejected unit. The
   scheduler does not re-execute accepted sibling units or the entire batch
   unless a separately declared replan transition exists in a later feature.
4. Downstream data bindings read accepted outputs only. A red attempt cannot
   replace a prior accepted value or leak as a successful graph output.
5. Envelope serialization and trace preserve unit/check/attempt correlation.
   Define the graph authoring contract and durable envelope shape in an ADR.
6. The F1.7 guarantee is about scheduler state and in-memory accepted output
   values. It is not a guarantee that shared repository files remain unchanged.
   Overlapping declared scopes must be reported as a potential conflict;
   F1.8 checks actual changed paths, and F3.1 owns isolated worktrees and
   filesystem-level accepted-output protection.

## Data / API contracts affected

Return Envelope type, unit identity, scoped attempt transition, accepted
runtime output map and event payload. The ADR must specify how a batch
declares units and how edge bindings select their accepted values without
creating ordering-only dependencies.

## Failure behavior

Missing/duplicate unit ID, contradictory verdict and Check Result, invalid
scope, unknown attempt or conflicting accepted output fail closed. A unit
exhausting its budget ends needing intervention without rerunning siblings.
Shared workspace side effects are surfaced as a limitation, not silently
represented as isolated success.

## Acceptance criteria

- [x] In a deterministic A/B/C/D test, a red C then green C runs C twice and
      A/B/D once each; A/B/D accepted output values and IDs are unchanged.
- [x] Downstream of C receives only its green result; downstream of accepted
      siblings is not repeated due to C's retry.
- [x] Return Envelope round trips with unit, verdict, reason, evidence, scope
      and attempt correlation intact.
- [x] Duplicate unit IDs, a red overwrite of accepted data and an exhausted C
      budget fail with traceable, actionable outcomes.
- [x] A shared-workspace test/documentation explicitly demonstrates that
      file edits are outside the F1.7 immutability guarantee; no test asserts
      filesystem isolation before F3.1.
- [x] `make check` and `go test -race ./...` pass.

## Required tests

- Unit: envelope validation, serialization and accepted-value immutability.
- Integration: barrier-controlled A/B/C/D retry counts and ordering,
  downstream visibility, budget exhaustion and overlapping declared scopes.
- CLI/e2e: machine-readable trace shows only C's additional attempt.

## Security / trust considerations

Scope is advisory until F1.8 and not a filesystem boundary. Do not use
model-reported changed paths to certify accepted sibling files. Avoid running
concurrent Agent writers against one checkout unless a declared conflict rule
can safely prevent overlapping intended scopes; F3.1 is the isolation layer.

## Observability

Emit per-unit verdict, envelope, attempt and acceptance facts. Preserve
accepted sibling IDs and their event history. Record declared-scope conflict
diagnostics without presenting them as proof of actual file changes.

## Resolved implementation decisions

ADR-0015 defines optional top-level units as an unordered set of loop Agent
node IDs; unit_id=node_id. Static sibling nodes are the retryable batch;
multi-item producers must be authored as separate nodes. No dynamic fanout.
Enrolled unit/node IDs are at most 256 UTF-8 bytes and fail preflight above
that bound; legacy IDs retain their existing contract. Absent units preserves
F1.6 behavior/hash/large scopes. Enrolled scopes are
normalized, bounded and complete (not silently truncated). ReturnEnvelope v1
links source/check/attempt and immutable accepted provenance. Unit-mode
serializes all Agent cycles unless distinct physical workspaces are proven;
declared overlap/unknown potential conflicts are diagnostic, never filesystem
isolation. Emit schema7/read prior schemas, reuse F1.6 red-only bounded retry.

## Out of scope for this iteration

F1.8 Git-derived scope check, F3.1 workspace isolation and explicit
cross-unit replanning.
