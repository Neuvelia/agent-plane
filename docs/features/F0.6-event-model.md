# F0.6 - Event model and stable execution IDs

**Status:** implemented
**Priority:** P0
**Target phase:** Phase 0 - Execution Core

## Problem

A scheduler that only mutates in-memory status is difficult to debug and cannot support the later Run Inspector, recovery, audit, or local/cloud synchronization.

## Goal

Represent observable execution transitions as structured events with stable correlation identifiers.

## Functional requirements

1. Stable IDs for graph run and node run; reserve attempt ID semantics for later loops.
2. Minimum events:
   - run_started;
   - node_ready;
   - node_started;
   - log_chunk;
   - node_finished;
   - run_finished.
3. Each event has timestamp, per-run sequence, graph run ID, graph version context, and typed payload.
4. Relevant node events have node run ID and node definition ID.
5. Event ordering within one run is monotonic.
6. Event payloads must be serializable.
7. Provide a redaction seam before events leave the execution boundary.

## Implemented contract

- Each started run has a UUID v4 run ID. Each defined node has a UUID v4 node
  run ID, including nodes that never start. Attempt IDs are reserved and absent
  until bounded loops exist.
- Event JSON uses `event_schema_version: 1`. `(run_id, sequence)` identifies an
  event; sequence begins at 1 and is assigned by one in-memory collector.
- `graph_version` is a `sha256-v0:` fingerprint of the normalized semantic
  definition. Name, metadata, and authoring order of edges and graph input
  bindings do not affect it.
- `node_finished` applies only to a node that entered running. A node that
  fails, skips, or cancels before starting emits `node_terminated` instead.
- `RunResult.Events` exposes the complete ordered event stream after `Run`
  returns. Shell stdout/stderr arrive as distinct, bounded `log_chunk` events
  with bytes encoded as base64 in JSON. A caller-provided log sanitizer runs
  before those bytes enter the collector.

## Acceptance criteria

- [x] A completed run can be ordered from emitted events without consulting console logs.
- [x] Event sequence is strictly monotonic within a run.
- [x] Node start/finish events correlate to stable node run IDs.
- [x] Run has exactly one terminal run event in normal completion paths.
- [x] Raw configured secrets are not intentionally included in test event payloads.
- [x] `make check` passes.

## Required tests

- event ordering;
- correlation IDs;
- concurrent node event sequencing;
- serialization;
- terminal event invariant.

## Out of scope for this iteration

- durable event persistence;
- snapshots;
- distributed event bus;
- cloud streaming protocol.
