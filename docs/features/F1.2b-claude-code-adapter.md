# F1.2b - Claude Code adapter (addendum to F1.2)

**Status:** in progress (registry status `in_progress`). The adapter, CLI wiring and fake-CLI tests are implemented; the
protocol is assumed, not verified: the spike (`docs/validation/F1.2b-claude-code-spike.md`) and the real-CLI smoke
(AC10, `docs/validation/F1.2b-claude-code-smoke.md`) are both NOT RUN.
**Priority:** P1
**Target phase:** Phase 1 - Agent Loop
**Depends on:** F1.1, F1.2, F1.3, F1.6
**ADR:** ADR-0046 (accepted, pending spike); builds on ADR-0009, ADR-0010, ADR-0034
**Registry:** `docs/roadmap/features.yaml` entry F1.2b (derived from F1.2)

## Problem

Codex is the only real coding-agent adapter. F1.2 deferred a second adapter until the F1.1 contract was
stable; F1.1-F1.8 are now done. The capability report (ADR-0025) already detects `claude` as
`detected_no_adapter`, so a person sees the CLI and cannot run it. Without a second adapter the neutral
contract (ADR-0034) has only been proven against one provider.

## Goal

Execute the installed Claude Code CLI (`claude -p`) through the unchanged F1.1 contract, modify a temporary
Git repository, and report the same observable result and evidence as Codex: normalized summary and
artifacts, Git-derived changed paths, F1.3 progress, and process-tree cancellation. Opt in from the CLI with
`agentplane run --adapter claude --claude-bin ABSOLUTE_PATH`.

## Non-goals

See "Out of scope for this iteration". In particular this feature does not change the adapter interface, the
graph schema or the event schema.

## Functional requirements

1. A package `internal/agent/claudecode` implements `AgentAdapter` and `NormalizedProgressAdapter` for `claude -p`
   (adapter ID `claude`). It does not import the `codex` package; shared process helpers live in a neutral
   package (ADR-0046 D2).
2. `Detect` requires an absolute executable `Binary`, reads `--version` and `--help` for the required flags
   with 10 s bounded probes, each run in a fresh private `HOME` with the same fixed adapter environment as `Execute` (D5)
   and no `environment_refs`, and fails closed outside Darwin and Linux. Declared
   capabilities: correction feedback, cancellation, streaming and workspace true; usage reporting false.
3. `Execute` validates the workspace through `internal/gitstate` (root of a worktree with HEAD), snapshots
   before, runs `claude` with explicit argv and an environment made only of the node's `environment_refs` plus
   adapter constants and a private `HOME`/`CLAUDE_CONFIG_DIR` outside the workspace (removed afterwards), and
   snapshots after. Task, advisory `allowed_paths`, `context_refs` and correction feedback go on stdin as
   untrusted data, never in argv.
4. Permissions follow the ADR-0046 invariant mapping: no prompts, `acceptEdits`, file tools only
   (`Read,Edit,Write,Glob,Grep`), **Bash OFF in v1**, no MCP or slash commands, never `bypassPermissions` or any
   `--dangerously-*` flag.
5. The result is the `structured_output` of the final `result` record: a non-empty `summary` and `artifacts`
   with non-empty `ref`. A missing, malformed or oversized result fails with `claude_result` and accepts no
   outputs. `Usage` and `RawMetadata` are `nil`.
6. Progress is projected from `stream-json` onto the existing F1.3 event types without a schema bump.
   Reasoning (`thinking`), tool contents, stderr, API error text and task text are never projected. An
   oversized optional record is skipped without buffering it whole.
7. Changed files are Git-derived (before/after snapshot, ADR-0010 baseline rules); tool-reported paths are at
   most `reported` progress and never changed-path evidence.
8. Context cancellation terminates the process group (`internal/proctree`), waits a bounded interval and
   returns `claude_cancelled`; descendants of the invocation do not survive the bounded shutdown.
9. CLI: `--adapter` is repeatable (an empty `--adapter ""` is a usage error), `--claude-bin` configures the binary
   (a bare `--codex-bin` without `--adapter codex` fails with `--codex-bin requires --adapter codex`), `serve --claude-bin` is detection
   only. Missing or unregistered adapter errors name the adapter and the flags to pass. The capability row
   `claude` is `agent_adapter` when configured (with desktop texts), otherwise `detected_no_adapter`.

## Data / API contracts affected

CLI (`--adapter claude`, `--claude-bin`, repeatable `--adapter`; ADR-0046). `node_evidence` gains the value
`adapter_id = "claude"`; `diagnostic_codes` gain the `claude_*` values: `claude_detection`,
`claude_unsupported_platform`, `claude_unsupported_capability`, `claude_environment`, `claude_workspace`,
`claude_git`, `claude_start`, `claude_shutdown`, `claude_cancelled`, `claude_process_exit`, `claude_result`,
`claude_progress` (reserved: declared but not produced by the current implementation). Capability API: the `claude` row can be `agent_adapter` (additive in version 1). Unchanged:
adapter interface (ADR-0034), graph schema (`adapter: claude` is a value of the existing field), event types
and event schema version.

## Failure behavior

Missing or too old CLI, unsupported platform, bad workspace, Git inspection failure, start or exit failure,
malformed or oversized result, progress projection failure and cancellation each have a distinct `claude_*`
code and a node-scoped error without panic. A failed invocation never publishes accepted outputs. A dirty
baseline is never presented as an agent change. Raw stderr, provider error text and tool contents never enter
events or errors. Protocol drift (an unknown record shape for the required result) fails closed.

- [ ] F1.2b-AC2: A path reported by a `tool_use` record and absent from Git does not become a changed path.
- [ ] F1.2b-AC3: A file dirty before the run does not create a false change; the CLI's private configuration

- [ ] F1.2b-AC4: A missing CLI, a bad workspace or an unusable version (no minimum is enforced until the spike sets one; the "old

## Security / trust considerations

CLI output, paths and Git state are untrusted. The Claude boundary is **weaker** than Codex `workspace-write`:
Claude Code has no OS sandbox by default, so a permitted Bash command would run with the user's privileges.
Hence Bash is off in v1 and enabling it needs an ADR-0046 amendment after the spike confirms a fail-closed
sandbox. No secret, reasoning or raw task text is logged.

**Git control files.** In `acceptEdits`, `Edit` and `Write` can write `<workspace>/.git/config`,
`.git/hooks/*` and `.git/info/attributes`. `internal/gitstate` snapshots exclude `.git`, so such a write is
invisible as evidence, yet the user's next plain `git` command can execute it (a hook, `core.fsmonitor`, a
filter driver). With Bash off this is a file write that becomes code execution outside any sandbox. Mitigation:
the adapter hashes `.git/config`, `.git/hooks/**` and `.git/info/attributes` (the resolved real git directory
for linked worktrees) before and after the run and returns `claude_git` on any change. A permission deny rule
(`Edit(.git/**)`, `Write(.git/**)`; ASSUMED syntax) is a spike item as defense in depth. `allowed_paths` stays advisory; Git-derived paths are
evidence, not F1.8 enforcement. Network use is limited to model traffic; WebFetch, WebSearch, MCP, plugins,
telemetry and the autoupdater are off.

## Observability

Adapter identity `claude` and detected version in `node_evidence`, process lifecycle statuses, bounded
normalized progress, correlated Git-derived changed paths and the terminal `claude_*` failure category.

## Open questions

Resolved by the owner (D1-D9, ADR-0046). Still open until the spike runs: the `stream-json` record shapes, the
exact `HOME`/config and telemetry variable names, whether `--bare` keeps API-key auth working, file-tool path
confinement, the Bash sandbox, and the minimum CLI version.

## Risks

- No OS sandbox for Bash in Claude Code: the largest security risk (D4); mitigated by Bash off in v1.
- Git control files (`.git/config`, hooks, `info/attributes`) writable by file tools yet invisible to snapshots:
  mitigated by the before/after hash check (`claude_git`); a deny rule is to be tried in the spike.
- Configuration writes into the workspace when `HOME` is missing: false evidence or a dirty repo (D5, AC3).
- `stream-json` record size: `tool_result` can be huge; the reader must be streaming and bounded.
- Protocol drift: `stream-json` is not formally versioned; detection checks flags, not record shapes, so the
  result is required and fails closed; the minimum version is recorded in ADR-0046.
- npm or script-based installs (`#!/usr/bin/env node`) cannot pass `Detect`: probes use the adapter environment
  without `PATH`, so `env node` fails. Remedy: install the native binary. Reported as `claude_detection`.
- Network traffic: the model is remote by definition; disable WebFetch/WebSearch, MCP, telemetry, autoupdater.
- Background processes: owned by the process group and reaped after the leader exits; `setsid` escapes are out
  of contract, as in ADR-0010.
- Test cost: the real smoke needs paid authentication; CI uses only the fake CLI.

## Implementation notes

- `claude_progress` is reserved and currently not produced.
- No minimum CLI version is enforced until the spike sets one.
- The plan's `.agents/graphs/` Claude template was replaced by `docs/examples/claude-agent.yaml`:
  `cmd/agentplane/templates_test.go` (S7 rule and `allowedRequires`) allows only Codex in templates, and a Claude
  template would need that rule changed by an owner decision.
- The desktop copy keys `cap.meaning.claude.notConfigured` and `foundOnPath` are unreachable from `serve` (without
  `--claude-bin` the row stays `agent_cli`); they are dead until the desktop can configure adapters (F2.14).
