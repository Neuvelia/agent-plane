# F0.1a - Import agentctl YAML v1 graphs

**Status:** draft
**Priority:** P1
**Target phase:** Phase 0 - Execution Core (derived from F0.1; delivered as an adoption enabler)
**Registry:** `docs/roadmap/features.yaml` entry F0.1a
**Depends on:** F0.1, F0.2, F0.3
**ADR:** ADR-0050 (proposed)
**Issue:** #206

## Problem

Both this repository and `agent-control-plane` (the reference project in the
adoption analysis; fork `kacwojdev/agent-control-plane`) implement the same
architecture plan. The reference project kept the plan's §11 sketch as its
graph format, "agentctl YAML v1":

- `version: 1` and a `nodes` map;
- `type: shell | agent | human | remote`;
- `run:` shell scripts with `depends_on`;
- `{{ nodes.X.output.* }}` and `{{ inputs.x }}` interpolation;
- `foreach`, `run_always`, `expect_status`, `strict`, `workdir: run`,
  `network`, `timeout_s`, `cwd`.

ADR-0033 made our schema v0 canonical and excluded exactly these constructs.
Its users keep a set of production graphs in that format. Rewriting them by
hand is the largest single switching cost, and a hand rewrite tends to lose
safety properties silently, such as `network: false`.

## Goal

A deterministic command translates an agentctl v1 graph into a schema v0 graph
that passes `agentplane graph validate`. It also produces a complete report of
every translation decision. It never drops a construct silently, and it never
produces a graph that is weaker than its source without an explicit flag.

## Non-goals

- Running agentctl graphs directly: no second parser in the runtime and no
  compatibility mode.
- Reverse export to agentctl format.
- Importing run state, events, approvals, the scoreboard or the ledger of the
  other tool.
- Translating `agent` nodes before F1.6b exists, `remote` nodes, or dynamic
  `foreach` (FX.1).
- Shell script parsing beyond locating `{{ ... }}` placeholders.

## Functional requirements

1. **Command:**

   ```text
   agentplane graph import --from agentctl-v1 SOURCE [--output FILE] [--allow-weaker] [--json]
   ```

   `--from` is required, and `agentctl-v1` is the only value in v1. Without
   `--output`, the graph goes to stdout. The report goes to stderr, or as JSON
   with `--json` (`{graph_path, translations[], warnings[], unsupported[],
   weakened[]}`).
2. **Determinism.** The same input bytes give byte-identical output: sorted
   keys, stable node order, no timestamps. `metadata.import` records
   `{format: agentctl-v1, source_sha256}`, and nothing about the machine.
3. **No partial output.** If any construct is unsupported, the command writes
   no graph, lists every unsupported construct with its location
   (`node.field`) and the feature that would enable it, and exits 3 (invalid
   graph).
4. **Mapping** (decided in ADR-0050):

   | agentctl v1 | schema v0 |
   | --- | --- |
   | `name` | graph `id` (sanitized to the identifier grammar; the original kept in `metadata.import.name`) |
   | `type: shell`, `run: SCRIPT` | `shell` node, `command: /bin/sh`, `args: ["-c", SCRIPT']` |
   | `strict: true` | `command: /bin/bash`, `args: ["-euo", "pipefail", "-c", SCRIPT']` |
   | `{{ nodes.X.output.stdout }}` in `run` | X declares output `stdout`; edge `X.outputs.stdout → N.inputs.from_X_stdout`; `input_env` maps it to `AP_FROM_X_STDOUT`; the placeholder becomes `"${AP_FROM_X_STDOUT}"` |
   | `{{ inputs.k }}` in `run` | graph input `k` (string), graph input binding, `input_env` `AP_INPUT_K`, the placeholder becomes `"${AP_INPUT_K}"` |
   | `depends_on: [X]` with no data reference to X | X declares `exit_code`; edge `X.outputs.exit_code → N.inputs.after_X` (number, required) |
   | `timeout_s` | node `timeout_seconds` (F3.4; values above 86400 are unsupported) |
   | `cwd` (absolute) | `config.cwd`; a relative `cwd` is resolved against `--workdir DIR` if given, else unsupported |
   | `foreach: [literal list]` | one node per item, `ID_ITEM` with a sanitized suffix; `{{ item }}` substituted literally in `run`, recorded as a translation |
   | `type: human`, `prompt`, `blast_radius` | `human` node with the prompt; `blast_radius` kept in `metadata.import.blast_radius` until F3.9 consumes it (#187) |
   | `network: true` / absent | nothing (today's default) |
   | `network: false` | weakened: allowed only with `--allow-weaker`, recorded in `weakened[]` and in `metadata.import.weakened` |
   | `workdir: run` | weakened (per-run directory not available until F3.1c, #189): allowed only with `--allow-weaker` |

5. **Unsupported in v1**, each listed with its enabling feature:
   - `run_always` (no "run after failure" semantics);
   - `expect_status` (a candidate for a `test_command` loop, F1.4b; not
     translated automatically);
   - `foreach` over `{{ inputs.* }}` (FX.1);
   - `type: agent` (F1.6b);
   - `type: remote` (no feature);
   - `secret://` references, `{{ nodes.X.state }}`, and placeholders outside
     `run`.
6. **Placeholder rewrite is textual and reported.** Each rewrite is listed with
   the node, the original placeholder and the variable. Quoting the
   replacement means a value containing shell syntax is no longer executed.
   This is a deliberate semantic change toward safety, and the report says so.
7. The output passes `agentplane graph validate` with no errors. Warnings
   expected from the mapping (the F0.2 unused-input warning for `after_X`
   inputs, #180) are listed in the report as expected.

## Data / API contracts affected

- **CLI:** the new `graph import` subcommand; exit codes 0, 2 (usage) and 3
  (unsupported or invalid source).
- **Graph files:** `metadata.import` (free-form metadata, no schema change; the
  semantic hash ignores metadata per F0.1).
- No runtime, event or store change.

## Failure behavior

| Situation | Result |
| --- | --- |
| Source is not YAML, `version` ≠ 1, unknown top-level key | exit 3 with location |
| A node ID that sanitizes to a duplicate | exit 3 naming both source IDs |
| A cycle in `depends_on` | exit 3 (as F0.2 would report it) |
| Weakening constructs without `--allow-weaker` | exit 3, `weakened[]` lists them, no output |

## Roadmap criteria

F0.1a is a derived entry with no roadmap criteria of its own. It does not
change F0.1 criteria or the canonical format (ADR-0033).

## Acceptance criteria

- [ ] F0.1a-AC1: A synthetic fixture corpus covering every row of the mapping table imports
  to graphs with zero `graph validate` errors. Expected warnings match the report.
- [ ] F0.1a-AC2: A fixture with two independent shell branches feeding a third via
  `{{ nodes.X.output.stdout }}` produces, when run, the same final stdout as a reference
  file. Both branches overlap, proven with barriers, as in the Phase 0 exit test.
- [ ] F0.1a-AC3: Each unsupported construct gives exit 3, no output file, and an entry
  naming its location and enabling feature.
- [ ] F0.1a-AC4: `network: false` and `workdir: run` without `--allow-weaker` give exit 3;
  with it they import and are listed in `weakened[]` and `metadata.import.weakened`.
- [ ] F0.1a-AC5: Importing the same file twice yields byte-identical output.
- [ ] F0.1a-AC6: An upstream stdout of `$(touch pwned)` reaches the downstream node as data;
  after the run, `pwned` does not exist.

## Required tests

- **Unit:** the parser for agentctl v1 (strict keys), placeholder scanner,
  identifier sanitizer, every mapping row.
- **Integration:** import then `graph validate` then `run` on the fixture
  corpus in a temporary directory.
- **CLI:** exit codes, `--json` report shape, stdout and `--output` modes.

Fixtures are synthetic. No graph, path, cluster or project name from the
reference project or its users is copied into this repository.

## Security / trust considerations

- Source files are untrusted. The importer only reads and writes text; it
  never executes or resolves anything.
- Weakening is never silent (FR4, FR5).
- The imported graph runs scripts through `/bin/sh -c`, which the source
  already did. The report and the graph's `metadata.import` make this visible.
  Moving scripts to argv form is the author's follow-up.

## Observability

The report is the evidence. Imported graphs are recognizable in run history
by `metadata.import.format`, which lets usage of the importer be counted.

## Open questions

1. Ordering-only `depends_on`: the `exit_code → after_X` edge (recommended,
   ADR-0050 alternative A) or a control-dependency type in schema v0
   (alternative B, needs an ADR-0033 amendment)?
2. Should `expect_status: OK` translate into an F1.6a Shell loop with a
   `test_command` Gate that checks the last line? Recommended: no automatic
   translation in v1; the report suggests it.
3. Should `--allow-weaker` require naming each weakened kind
   (`--allow-weaker network,workdir`)? Recommended: yes, if owners prefer
   explicit consent per kind.

## Out of scope for this iteration

Agent and remote nodes, dynamic `foreach`, `run_always`, `expect_status`,
exporting back, importing run history.
