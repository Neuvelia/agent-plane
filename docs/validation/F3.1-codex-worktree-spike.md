# F3.1 spike - Codex in a linked Git worktree

**Status:** executed; verdict PASS (reported 2026-11-16). See "Recorded result".
**Gate for:** ADR-0024 (`proposed` -> `accepted`, done).
**Script:** `scripts/spike-f3-1-codex-worktree.sh`

## Question

ADR-0024 isolates each Agent node in a *linked Git worktree*. In such a
worktree `.git` is a file pointing at a gitdir inside the **source**
repository's `.git/worktrees/<name>/`, which is outside the directory Codex's
`workspace-write` sandbox treats as writable. Can the installed Codex CLI, run
exactly as the AgentPlane adapter runs it, edit files in that worktree and use
Git read-only commands there?

The ADR's fallback if the answer is no is an isolated local clone (ADR-0024,
Alternative A), which keeps its own gitdir inside the workspace.

## What is and is not covered

The script starts Codex with the same argv, sandbox mode and explicit
environment as `internal/agent/codex/adapter.go`
(`--no-daemon --ask-for-approval never exec --sandbox workspace-write
--ignore-user-config --ephemeral --json --color never --cd <worktree>
--output-schema ... --output-last-message ... -`; only `HOME`, `PATH` and, if
present, `CODEX_HOME`). It does **not** run AgentPlane code, so it can run
before any F3.1 implementation exists. It uses a disposable repository in a
fresh temporary directory and never touches the AgentPlane checkout.

| Step | What it exercises | ADR-0024 claim it supports |
| --- | --- | --- |
| Preflight | Git >= 2.38; every Codex flag the adapter needs exists | Minimum Git version; adapter compatibility |
| Layout | Hardened `git worktree add --detach` produces a `.git` *file* and an absolute gitdir under the source `.git` | Section 1, section 7 |
| T1 | Codex edits `a.txt` in the worktree; exact content and exact `git status` on the host | Section 1 (Agent runs in the worktree) |
| T2 | Codex runs `git status`, `git diff --name-only` and `git add -A` inside its sandbox; host git still healthy, no stale `index.lock` | The acceptance gate: Git usable in the sandbox |
| T3 | Codex tries one absolute-path write into the **source** checkout (informational) | Section 9 (a worktree is not a sandbox) |
| T4 | Two concurrent Codex runs rewrite the same `shared.txt` in two worktrees | Feature criterion 1 (no race on the same file) |
| T5 | Host-side snapshot commits, `git merge-tree --write-tree` (clean and conflicting), `worktree remove`, refs kept | Section 3 and section 8 mechanics on real Codex output |
| Source checks | Fingerprint (HEAD, status, every non-`.git` file hash) of the source after T1/T2, after T4 and at the end | Source tree and branch are never modified |

Not covered, by design: hooks and filter-driver rejection (deterministic Go
tests later), the AgentPlane scheduler, events, retention flags, Codex model
quality, Windows, large repositories and repositories using LFS.

## Preconditions

- A supported installed and authenticated Codex CLI, with an absolute
  `CODEX_BIN`. Authentication and network access come from the host account.
- Run it from a normal terminal on the host. If it only works from an outer
  development sandbox with an authorized escalation, say so in the result, as
  F1.2 did (`F1.2-codex-smoke.md`); do not add writable roots, bypass flags or
  weaken Codex rules to make it pass. Those would invalidate the result.
- `/usr/bin/git` 2.38 or newer, `bash`, `find`, `sha256sum` or `shasum`.
  Works on Linux and macOS (bash 3.2 compatible).
- The run makes about six short Codex calls (two concurrently) and may consume
  model quota.

## How to run

```bash
CODEX_BIN=/absolute/path/to/codex scripts/spike-f3-1-codex-worktree.sh
```

Optional: `SPIKE_DIR=/empty/dir` (default is a fresh `mktemp -d`),
`SPIKE_TIMEOUT=900` (seconds per Codex call), `CODEX_HOME` (forwarded only when
set and present).

The script prints one line per check (`PASS`, `FAIL` or `INFO`), writes
`results.tsv` next to the disposable repository and exits non-zero if any check
failed. Raw Codex stdout/stderr and result files stay in
`$SPIKE_DIR/private` (mode 0700). They may contain provider output: **never
commit or paste them.** Share only `results.tsv`.

## Reading the result

PASS/FAIL rows decide the gate. INFO rows are data for the follow-up decision.

| Outcome | Meaning | Action |
| --- | --- | --- |
| Every row PASS | Codex works in a linked worktree and Git read commands work in its sandbox | Accept ADR-0024 as written; start F3.1 implementation |
| `t2_git_status_in_sandbox` or `t2_git_diff_in_sandbox` FAIL | The sandbox cannot read the gitdir stored in the source `.git` | Switch the mechanism to ADR-0024 Alternative A (isolated local clone) and amend the ADR before any code. Re-run the script adapted to a clone to confirm |
| All PASS but `t2_git_add_in_sandbox` INFO shows a non-zero exit | Codex can read but not write the worktree's index (its gitdir is outside the writable root) | Acceptable: AgentPlane snapshots from the host and does not need the agent to stage or commit. Record it in ADR-0024 consequences and in the Agent prompt guidance ("do not stage or commit") |
| `t1_*` or `t4*_codex_exit` FAIL with non-sandbox symptoms (authentication, network, usage limit) | Environment problem, not a verdict | Fix the environment (authorized escalation as in F1.2) and rerun the whole script |
| `t2_probe_file` FAIL (no `git-probe.txt`) | The model did not follow the instruction | Rerun once. Two failures are a finding to record, not a pass |
| `t4_same_file_isolated` FAIL | Content crossed between worktrees | Stop: the isolation premise is broken; do not proceed |
| `t5_*` FAIL | A Git assumption in ADR-0024 (`merge-tree`, snapshot commit, cleanup) does not hold on this system | Record the Git version and error; amend the ADR |
| `source_unchanged_*` FAIL | The source checkout changed | Investigate before anything else; it may be a script or Git-version problem |
| `t3_outside_write` = WRITTEN | Codex's sandbox did not stop an absolute-path write into the source checkout | Confirms ADR-0024 section 9: the source guard is the only detection. Feed this into F3.9 |
| `t3_outside_write` = blocked | The Codex sandbox refused it | Informative only. F3.1 must still not rely on it (other adapters, other versions) |
| `t4_overlap` = did NOT overlap | Runs finished too quickly or one started late | Not a failure (second granularity); rerun if timing evidence matters |

Reading:

- Codex edits files in a linked worktree and its read-only Git commands
  (`status`, `diff`) work inside the `workspace-write` sandbox. This is the gate.
- `git add -A` exited 128 and staged nothing: the agent can read but not write
  the worktree's index, whose gitdir is in the source `.git`. The script does
  not capture Git's stderr, so the exact message is unrecorded; the pattern
  (read works, index write fails, no stale lock, host state intact) is
  consistent with a read-only gitdir. Treated as the "acceptable" row of the
  decision table above.
- The sandbox refused an absolute-path write into the source checkout on this
  Codex version. Informative only; ADR-0024 does not rely on it.
- Same-file edits in two concurrent worktrees stayed isolated; `merge-tree`
  gave a clean result for disjoint units and a named conflict for the same file
  under Apple Git 2.50.1 (the ADR spike used Git 2.43).

- [ ] Mechanism switched to Alternative A

## Limitations

- One model, one run, nondeterministic: a PASS shows the mechanism can work, not
  that every agent behaviour will. T2 and T3 rely on the model executing the
  commands it is told to run.
- Timing for T4 has one-second granularity and proves overlap only as far as the
  start/end timestamps do.
- The script cannot prove that Codex wrote nothing outside the worktree except
  through the source fingerprint, which also catches only the files it hashes
  (everything outside `.git`). Writes into the source `.git` are expected
  (worktree metadata) and are not hashed.
- It is a manual, authorized spike. It is not part of `make check`, CI or the
  merge gate for unrelated changes.
