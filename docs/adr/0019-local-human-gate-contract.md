# ADR-0019 - Local Human gate contract

**Status:** proposed
**Date:** 2026-11-11

## Context

ADR-0017 reserves Human node and event changes for this ADR. The roadmap
requires F2.10 to define a local pause/approval contract before UI coding.
Today `human` is only recognized by the safe-view projection; the runtime has
no waiting state, no decision record and no event for it. Event schema is 8.
ADR-0018 persists completed runs only and treats a crashed active run as
`interrupted`.

Constraints from AGENTS.md: human approval is driven by consequence, not model
confidence; trace is part of correctness; retry/rerun only the smallest unit;
accepted output is immutable; execution inputs are untrusted; local-first.

## Decision

1. **Node semantics.** `type: human` is a first-class node. When its inputs are
   ready it enters a new non-terminal state `waiting`, runs no process and
   occupies no scheduler slot. Independent branches continue.
2. **Decision model.** One decision per request. A request is identified by
   `(run_id, node_run_id, request_id)`, where `request_id` is generated by the
   runtime at `human.requested`. Decisions are `approved` or `rejected` with an
   optional bounded comment.
3. **Outcome mapping.** `approved` -> node succeeded, output `decision`.
   `rejected` -> node failed, reason `human_rejected`, normal failure
   propagation. Explicit reject transitions are not part of this ADR.
4. **Durability before continuation.** The decision is committed to local
   durable storage (fsync'd) before the `human.decided` event is emitted and
   before any dependent starts. If the commit fails the node stays `waiting`.
5. **Idempotency.** The decision call carries a client idempotency key. Same
   key and same decision returns the original result with no new event; a
   different decision for a decided request returns `decision_conflict`.
6. **Events.** Event schema 9 adds `human.requested` and `human.decided`.
   Older consumers that see schema < 9 are unaffected; schema 9 streams are
   rejected by readers that do not understand them, per existing version policy.
7. **Waiting is not durable execution.** Sidecar/app death while waiting makes
   the run `interrupted` (ADR-0018). Resumable waiting is Phase 3.
8. **Consequence classes.** `blast_radius` (`L1|L2|L3`, default `L3`) is
   declared metadata, shown to the approver and recorded in the event. It does
   not auto-open gates in this iteration. Model confidence is never an input.
9. **Trust.** Comment, prompt and evidence are untrusted: bounded, redacted of
   configured secrets, rendered via safe-view. Decisions travel over the
   existing authenticated local sidecar protocol; no new listener.
10. **Non-interactive CLI.** Without a decision channel a Human node fails with
    `human_required_no_channel` instead of blocking forever.

## Alternatives considered

### Alternative A - Block the node as a long-running process

Pros:

- No new node state.

Cons:

- Holds a scheduler slot and a goroutine; invisible in the trace; no
  idempotency; unusable from a UI.

### Alternative B - Human approval as a Gate variant

Pros:

- Reuses CheckResult plumbing.

Cons:

- Gates are deterministic, read-only checks (ADR-0012). A person's decision is
  an external, durable fact and must not masquerade as a deterministic check.

### Alternative C - Durable resumable waiting now

Pros:

- Survives restart.

Cons:

- Requires durable execution (Phase 3); would expand F2.10 beyond scope and
  threaten the 15.11 deadline.

## Consequences

### Positive

- Human decisions are explicit, idempotent trace facts.
- UI can be built against typed protocol methods and reconstructed from events.
- Consequence-based vocabulary is in place without model-judgment gating.

### Negative / trade-offs

- New node state and event types touch scheduler, event schema, SQLite
  projection, desktop protocol and safe-view.
- Waiting runs are lost on crash (shown as `interrupted`).
- CLI-only users cannot approve until a decision command is added.

## Compatibility and migration

Graph schema 0 stays valid for graphs without Human nodes. Event schema moves
8 -> 9; the history projection adds request/decision rows without changing
completed-run rows. Desktop protocol gains typed methods; mismatch fails safely
before launch (ADR-0017).

## Validation

Scheduler tests with explicit barriers proving sibling progress while waiting;
ordering test (`human.requested` < `human.decided` < dependent start);
commit-failure injection; same-key/conflicting-key decisions; cancel then late
decision; forced sidecar death -> `interrupted`; redaction in events, SQLite
DB/WAL and files; packaged-app approve/reject e2e with fake adapters.

Feature: F2.10 Human Gate UI.
