# F0.3 - Explicit data bindings

**Status:** implemented
**Priority:** P0
**Target phase:** Phase 0 - Execution Core

## Problem

The scheduler must know why one node depends on another. Ordering alone is insufficient because independent work should be able to run concurrently.

## Goal

Resolve declared graph inputs and node outputs into node inputs using explicit bindings, with no hidden shared context.

## Functional requirements

1. Bind graph input -> node input explicitly.
2. Bind node output -> node input explicitly through edges.
3. Represent missing required values as deterministic errors.
4. Preserve typed scalar/JSON values without stringifying everything.
5. Define how artifact references flow without loading artifact contents into the binding layer.
6. Node readiness must be derivable from declared dependencies and resolved required inputs.

## Acceptance criteria

- [x] A graph input can resolve into two independent node inputs.
- [x] Output from A can resolve into a declared input of B.
- [x] Missing required input prevents B from becoming ready.
- [x] Two nodes that consume only graph inputs and not each other have no dependency between them.
- [x] Binding resolution is deterministic.
- [x] `make check` passes.

## Required tests

- graph input to node;
- node output to node;
- multiple consumers;
- missing value;
- type mismatch delegated consistently between validator/resolver;
- artifact reference pass-through.

## Out of scope for this iteration

- map/filter/join expression language;
- hidden global context;
- model-assisted transformations;
- dynamic fan-out.
