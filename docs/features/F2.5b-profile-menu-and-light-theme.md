# F2.5b - Profile menu, light theme, Keyboard shortcuts and About

**Status:** implemented
**Priority:** P1
**Target phase:** Phase 2 - Local IDE
**Depends on:** F2.5a
**ADR:** [ADR-0046](../adr/0046-desktop-light-theme-and-profile-menu.md)
**Registry:** `docs/roadmap/features.yaml` entry F2.5b
**Design:** design canvas artboards "Profile menu", "Profile menu · light" and
"Shortcuts, About and Soon" (presentation reference, drawn 1:1)

## Problem

The desktop shows a hard-coded avatar in the global bar that does nothing. The
design moves the profile to the foot of the sidebar and gives it a menu with
the app-wide choices a local app has (language and appearance), the keyboard
shortcuts and About. The app also has only a dark theme, while every artboard
of the design has a light variant.

## Goal

The profile row at the foot of the sidebar opens the designed menu; Language
and Appearance switch the interface at once and persist; the light theme
covers every screen; Keyboard shortcuts and About open as windows.

## Non-goals

- Accounts, sign-in, Log out, Upgrade, plans or organisations (no account exists).
- A per-person display name: the name and initials stay hard-coded until the
  welcome screen asks for them (issue #219).
- A Help/documentation surface: the item is shown as unavailable ("Soon").
- New shortcuts beyond Ctrl/Cmd+, (Settings) and Ctrl/Cmd+/ (this list).
- A run-store path in About (the renderer never receives filesystem paths).
- Any change to the Go sidecar, HTTP API, events, run store or Electron IPC.
- User-selectable accent colours.

## Functional requirements

1. The sidebar foot (below a hairline, after Welcome and Settings) holds the
   profile row: initials avatar, name and "Local". It is a menu button
   (`aria-haspopup="menu"`, `aria-expanded`). The global bar no longer shows
   an avatar.
2. The menu opens above the row, 248 px wide: header (name; "Local profile ·
   stored on this computer"), then Settings (`Ctrl ,`) and Keyboard shortcuts
   (`Ctrl /`), then Language and Appearance (current value and a chevron),
   then Help and documentation ("Soon", unavailable) and About Tarmind (app
   version). Cmd replaces Ctrl on macOS.
3. Language and Appearance open a 200 px submenu to the right whose last item
   is level with its trigger. Choices are `menuitemradio` with one checked:
   System, English, Polski / System, Light, Dark. Picking applies at once,
   persists, closes the submenu and returns focus to its trigger; the menu
   stays open.
4. Appearance: System follows `prefers-color-scheme` live; Light and Dark pin
   the theme. The choice is in `localStorage` and painted before the first
   render. Settings shows the same choices for Appearance and Language
   (System, then each language). Language: System removes the saved language.
5. Keyboard: ArrowDown/ArrowUp on the button open on the first/last item;
   Enter/Space/click open on the first item. In the menu, arrows rove and wrap,
   Home/End jump, ArrowRight/Enter/Space on a trigger open its submenu on the
   checked item, also when a pointer already opened it; a pointer click on an
   open trigger closes it; ArrowLeft/Escape close a submenu; Escape closes the menu and
   returns focus to the button; Tab and a press outside close it.
6. Motion: the menu fades and scales in from its bottom-left corner (160 ms)
   and out (120 ms); a submenu slides in from the left (140 ms) and out
   (100 ms); the chevron of an open trigger nudges right; the check mark
   scales in; windows fade and rise in (160 ms) and out (140 ms) with their
   backdrop; a theme change cross-fades colours (240 ms). All are off under
   `prefers-reduced-motion`.
7. Keyboard shortcuts window (also Ctrl/Cmd+/): the shortcuts the app has,
   grouped (Anywhere, Editor, Menus and dialogs), keys written as text. It says
   that in the YAML editor Ctrl/Cmd+/ comments the line instead (CodeMirror's
   binding is kept).
8. About window: "Everything stays local", App version, Engine version and
   os/arch (from `GET /capabilities`), Runs stored (from `GET /runs`); each
   shows "Checking…" while loading and "Engine not connected" on failure (the
   run count says "Not available" when only the run list fails). Copy
   diagnostics is disabled while checking and puts only those versions and the
   count on the clipboard.
9. Windows are modal `<dialog>`s: Escape, Close or a press that starts and
   ends on the backdrop close them and focus returns to what opened them. A
   window that is closing never closes the window opened after it.
10. Ctrl/Cmd+, opens Settings from anywhere. App shortcuts do nothing while a
    modal window is open, and close the profile menu when they fire from it.

## Data / API contracts affected

- `desktop/src/design/tokens.json`: a `light` theme for every colour token;
  `tokens.css` emits it under `:root[data-theme="light"]` (ADR-0046).
- Renderer `localStorage`: new key `agentplane.theme` (`light` | `dark`;
  absent = system). `agentplane.locale` may now be removed by "System".
- No API, event, IPC or run-store change.

## Failure behavior

- Unreadable or unknown saved theme: System. Unavailable storage: the choice
  lasts for the session.
- No `matchMedia`: System resolves to dark.
- About with the engine unreachable: "Engine not connected" for the engine and
  the run count; Copy diagnostics writes "unknown" for them. A clipboard
  failure says so and suggests copying by hand.

## Security / trust considerations

No new input crosses a trust boundary. Copy diagnostics writes only version
strings and a count, never a path, environment value or run content. The
theme and language are renderer-local; nothing is sent anywhere.

## Observability

Presentation only: no execution transition, so no event. The painted theme is
observable as `data-theme` on `<html>`.
