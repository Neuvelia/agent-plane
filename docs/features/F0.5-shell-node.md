# F0.5 - Shell Node

**Status:** implemented
**Priority:** P0
**Target phase:** Phase 0 - Execution Core

## Problem

The runtime needs a deterministic real executor to validate process lifecycle, logs, exit codes, and scheduler integration without depending on an LLM.

## Goal

Execute a local process with explicit argv/cwd/env configuration and convert its result into structured node output.

## Functional requirements

1. Prefer structured command + args over concatenated shell strings.
2. Support explicit working directory.
3. Support explicit environment additions/allowlist semantics.
4. Capture stdout, stderr, exit code, start/end timestamps.
5. Stream output through the runtime event seam once F0.6 is available.
6. Non-zero exit is a node failure.
7. Child process can be terminated by cancellation.
8. Define a minimal mechanism for producing JSON-compatible output without parsing arbitrary prose.
9. Explicitly map declared string node inputs to child environment variables when requested by `config.input_env`.
10. Bound the retained capture (ADR-0039, issue #181). `Result` keeps at most
    `DefaultCaptureLimit` (1 MiB) leading bytes of stdout and, separately, of
    stderr. Excess output is still drained, so the child never blocks on a full
    pipe, and is still passed to the log observer in 16 KiB chunks, but it is
    not retained. `Result.StdoutOmitted` / `StderrOmitted` count the omitted
    bytes, and the retained text of a truncated stream ends with the marker
    `[agentplane: N bytes of <stream> omitted; capture limit L bytes]`. A
    declared `stdout`, `stderr` or `json` output whose stream was truncated
    fails as an output failure (`CaptureLimitError`, diagnostic code
    `E_SHELL_OUTPUT_TRUNCATED`); `exit_code` reads no stream and is unaffected.

## Acceptance criteria

- [x] Successful process returns succeeded with exit code 0.
- [x] Non-zero exit returns failed with captured evidence.
- [x] stdout and stderr are captured separately.
- [x] argv containing spaces/special characters is passed without unsafe string concatenation.
- [x] cancellation does not intentionally leave the direct child process running.
- [x] Cancellation terminates the whole process tree on Unix (request, grace, force) through `internal/proctree` (F3.4; `TestExecuteCancellationKillsGrandchild`). Windows still terminates only the direct process until Job Objects land.
- [x] A bound string input reaches only its explicitly mapped child environment variable.
- [x] Invalid input mappings fail before process launch.
- [x] Stdout and stderr beyond the capture limit are not retained; the retained text ends with the omission marker and the omitted byte counts are reported, while the log observer still receives every byte (`TestCaptureBeyondLimitKeepsPrefixWithMarkerAndStreamsEverything`, `TestDefaultCaptureLimitBoundsRetainedOutput`).
- [x] Output exactly at the limit carries no marker (`TestCaptureAtLimitIsCompleteWithoutMarker`).
- [x] A declared output reading a truncated stream fails the node with `E_SHELL_OUTPUT_TRUNCATED`; outputs that do not read it succeed (`TestDeclaredOutputFromTruncatedStreamFailsWithCaptureLimitError`, `TestOutputsNotReadingTruncatedStreamSucceed`, `TestTruncatedDeclaredOutputFailsTheRunWithDiagnosticCode`).
- [x] `make check` passes.

## Required tests

Use portable helper test processes where possible instead of assuming platform-specific external commands.

Test success, stderr, non-zero exit, argv fidelity, cwd, environment, explicit
input mapping, invalid mapping, and cancellation.

## Security / trust considerations

Commands are untrusted execution instructions.

Do not silently invoke a system shell unless the graph explicitly requests shell semantics in a future feature.

Do not inherit arbitrary secrets into a process by accident.

## Out of scope for this iteration

- containers;
- sandboxing;
- command allow/deny policy;
- secret store;
- resource quotas;
- keeping the complete stdout/stderr as a run artifact: it depends on the
  artifact store and is deferred to F3.5 (ADR-0039);
- a graph-level setting for the capture limit.
