# F2.3 - Edge / Data Mapping Editor (with recorded run values)

**Status:** draft (section B, engine slice E6, implemented opt-in: `F2.3-E6-recorded-run-values.md`)
**Priority:** P0
**Target phase:** Phase 2 - Local IDE
**Depends on:** F2.1, F2.2, F2.4, F0.3 (bindings), F1.7 (accepted values and provenance), F2.5 (run stream)
**ADR:** ADR-0020 (operations), ADR-0023 (recorded run values), both proposed; ADR-0023 has one open decision
**Plan:** `docs/superpowers/plans/2026-11-14-graph-editor.md` (slices E5a, E6, E5b)

## Problem

Data dependencies are the contract of a graph (AGENTS.md rule 4), but they are hard to see and change: an edge
is two strings in YAML, graph inputs and outputs are separate lists, and nothing shows what actually flowed
along an edge during a run. The roadmap criterion for this feature is that a user can point to the concrete
value that passed through an edge, which no event or API provides today.

## Goal

A person can see, add, replace and remove every data binding of a graph (edges, graph inputs and their
bindings, graph outputs) in one place, with types visible and incompatible choices explained, and, for a run
that recorded values, select an edge and see the value that crossed it.

## Non-goals

- Ordering-only edges or any control dependency (schema v0 has none, and AGENTS.md rule 4 forbids them).
- Transformations on an edge, expressions, or a visual ETL (complex transformation belongs in a code node).
- Showing values for runs that did not record them, or inventing a value (unknown is unknown).
- Recording values of rejected attempts, of failed or skipped nodes, or the contents of artifacts.
- Editing node configuration (F2.2) or creating nodes (F2.1).

## Functional requirements

### A. Static mapping editor (slice E5a)

1. **Operations added by this spec** (`ops_version: 1`; `add_edge` and `remove_edge` are F2.1):

   | `op` | Fields | Effect |
   | --- | --- | --- |
   | `replace_edge` | `from`, `to` | Makes the given output the provider of `to`, removing the input's previous provider edge or graph input binding in the same batch |
   | `add_graph_input` / `remove_graph_input` | `name`, `type`, `required` | Declares or removes a graph input; removal also removes its bindings |
   | `set_graph_input_binding` / `remove_graph_input_binding` | `from` (`inputs.NAME`), `to` (`NODE.inputs.PORT`) | Binds a graph input to a node input of equal type with no other provider |
   | `set_graph_output` / `remove_graph_output` | `name`, `from` (`NODE.outputs.PORT`) | Declares or removes a graph output |

2. **Suggestions (Go).** The `open` and `edit` responses carry, per diagnostic of the two relevant kinds,
   deterministic candidates: for `W_DECLARED_OUTPUT_UNUSED`, the required inputs of equal type that have no
   provider; for `E_REQUIRED_INPUT_UNBOUND`, the outputs and graph inputs of equal type. Candidates are the
   engine's, sorted by node id and port, capped at 20, and exclude any choice `can_connect` refuses.
3. **Bindings panel.** A card listing every edge as `source node . output -> target node . input` with the
   declared type, status badges from the diagnostics (F2.4), and Remove. Selecting a row selects the edge on
   the canvas and the reverse. Rows are ordered by target node then input, stable.
4. **Add and replace.** "Add binding" opens a form with a source output list and a target input list. Each
   incompatible choice is disabled with the engine's reason (type mismatch, already provided, would create a
   cycle, same node). Choosing a target that already has a provider offers "Replace" (`replace_edge`) and says
   what is removed. The same form is the keyboard path for connecting.
5. **Graph inputs.** A card listing graph inputs (name, type, required) with add and remove, and for each its
   bindings to node inputs, with the same compatibility rules and reasons.
6. **Graph outputs.** A card listing graph outputs (name to `NODE.outputs.PORT`) with add and remove, offering
   only existing outputs.
7. **Unused output and unbound input hints.** An output with `W_DECLARED_OUTPUT_UNUSED` shows its suggestion
   candidates as one-click bindings; a required unbound input shows its candidates the same way. Nothing is
   applied without a click. The v0 contract cannot express an empty binding, so there is no "empty binding"
   hint; the independence list of F2.2 is the parallelism information.
8. **Types are visible.** Ports on the canvas and rows in every list show their type; edges on the canvas are
   labelled with it on selection.

### B. Recorded run values (engine, slice E6)

These requirements implement ADR-0023 and stay behind its open decision (default off unless the product owner
decides otherwise).

9. **Event.** A new event `value_recorded` (event schema 10, additive) per accepted output port when a node's
   output is accepted, ordered before the node's terminal event, and per graph input at run start.
   Payload: `node_run_id`, `attempt_id` (both empty for a graph input), `port` (`inputs.NAME` for a graph
   input), `type`, `size_bytes`, `sha256` (of the full value), `truncated`, `redacted`, `value`.
10. **Bounds.** At most 16 KiB of the value per event, cut at a valid boundary with `truncated: true` and the
    full `size_bytes` and `sha256`; at most 1 MiB of recorded values per run, after which ports are recorded
    without `value` and with `truncated: true`; an `artifact_ref` records its reference string only.
11. **Redaction.** Values pass through the same redactor as logs and events (configured secret values replaced,
    matches across the cut handled), with `redacted: true` when changed. `serve` gains `--redact-env` with the
    same meaning as `agentplane run`, before recording can be enabled from the desktop.
12. **Opt-in.** `agentplane serve` and `agentplane run` record values only with `--record-values`. The desktop
    passes it only when the user has switched on "Record values for edge inspection" in Settings, which is off
    by default and explains that values are user data and that redaction covers only configured secrets. The
    setting applies to runs started afterwards.
13. **Store and replay.** Events are persisted with the existing run store; replay after a restart gives the
    same recorded values as the live stream. Schema 1-9 streams contain no values and remain readable.
14. **Run summary.** `GET /runs` entries gain `graph_version` (the semantic version hash) so the editor can
    tell whether a run belongs to the graph version on screen.

### C. Edge values in the editor (slice E5b)

15. **Reducer.** The renderer's reducer derives, from `value_recorded` events, the recorded value of each
    `(node, port)` of a run. An edge's value is the value of its source port; a graph-input binding's value is
    the recorded graph input. Nothing is stored in components.
16. **Run picker.** In the editor, "Show values from run" lists runs of the open graph (same `graph_id`), newest
    first, marking those whose `graph_version` equals the open document's version; a run of another version is
    shown with a "different version" tag and its values are shown only with an explicit confirmation, labelled
    as from another version. The latest matching run is chosen by default.
17. **Edge inspector.** Selecting an edge shows the source output, the target input, the declared type and, for
    the chosen run: the value (string as text, number and boolean as is, json pretty-printed and
    collapsible, `artifact_ref` as the reference), its size, and the `truncated` and `redacted` marks. States
    are explicit and distinct: **not recorded** (feature off, older schema, or cap reached), **no such run**,
    **node not finished** (no value yet), **node failed or skipped** (no accepted value), and **different
    version**. An empty string or `null` is shown as an empty value, never as "not recorded".
18. **Live runs.** While the chosen run is going, values appear as their events arrive; the connection-lost
    banner and stale handling of F2.5 apply.
19. **Static units.** For a source that ran as several static units, the picker shows the value of the unit
    that matches the selected node; ambiguity is shown, not guessed.
20. **Localisation, accessibility and stories** as in F2.1: PL and EN, keyboard operable (the bindings list
    and the edge inspector are reachable without a pointer), stories (EN and PL, axe clean) for each state in
    requirement 17, the bindings panel, graph inputs and outputs, the add form with disabled reasons.

## Data / API contracts affected

New operations (ADR-0020 vocabulary), suggestion candidates in `open` and `edit`, event schema 10 with
`value_recorded` (ADR-0023), `--record-values` and `--redact-env` on `serve`, `--record-values` on `run`, the
`graph_version` field on run summaries (additive), and a Settings entry. Graph schema v0 is unchanged. ADR-0023
must be accepted (its open decision answered) before section B is implemented.

## Failure behavior

- A refused operation changes nothing and explains itself (F2.1 error shape).
- A value that cannot be shown (invalid UTF-8 in a string, an oversized number) is shown as a hex or "binary"
  summary with its size and hash, never dropped silently.
- A store write failure while recording stops the run as ADR-0019 already does; no value is forwarded that is
  not on disk.
- A run from schema 1-9, or recorded with the switch off, shows "not recorded", never an empty value.
- If redaction cannot be configured (`--redact-env` names a missing variable), `serve` refuses to start with
  recording enabled.

## Acceptance criteria

- [ ] **Compatibility is the engine's:** `replace_edge`, `set_graph_input_binding` and the form's disabled
      reasons agree with `graph.Validate` for every pair of ports of the corpus graphs (Go).
- [ ] After any sequence of operations in this spec on the corpus graphs, `graph.Validate` reports no dangling
      reference; tree and typed implementations give equal semantic versions; comments and order are preserved.
- [ ] Suggestions are deterministic (same input, same list), capped at 20, and every candidate passes
      `can_connect` (Go).
- [ ] A person can bind an unused output to a compatible unbound required input in two actions from the
      warning, and the warning disappears (e2e).
- [ ] Keyboard only: add a binding, replace a provider and remove an edge with no pointer use (e2e).
- [ ] **Recording off:** no `value_recorded` event appears in any stream, store or CLI JSON of the recorded demo
      graphs (Go and e2e).
- [ ] **Recording on:** one event per accepted output port and per graph input; values above 16 KiB are
      truncated with correct `size_bytes` and `sha256`; the per-run cap yields `truncated: true` without a
      value; a configured secret never appears in an event, including across the cut (Go).
- [ ] A failed, skipped or cancelled node, and a rejected attempt, record nothing (Go).
- [ ] **Replay equals live:** reducing the stored events gives the same edge values as the live stream, after an
      app restart (reducer unit and e2e).
- [ ] **Run demo:** after running `demo-vertical.yaml` with recording on, selecting the edge `fast.stdout ->
      approve.summary` shows the string `fast branch done`; the edge `flaky.json -> approve.evidence` shows its
      JSON (e2e).
- [ ] Every state of requirement 17 is reachable and distinct; an empty string value is not shown as "not
      recorded" (renderer unit and stories).
- [ ] A run of a different graph version is never presented as the open version's run without the label and
      confirmation (renderer unit and e2e).
- [ ] `serve` refuses `--record-values` without a working redaction configuration when `--redact-env` names a
      missing variable; the Settings switch is off by default and its text is localised (e2e).
- [ ] Stories exist for every state listed, EN and PL, zero axe violations, no external requests;
      `npm run check`, `make check`, `make desktop-e2e` pass.

## Required tests

- **Go, operations:** table tests for each operation and failure, tree/typed agreement, compatibility parity,
  suggestions.
- **Go, engine:** event emission on and off, bounds, redaction including across the cut, store round trip,
  schema 1-9 readability, `graph_version` on summaries, `serve` flag handling.
- **Renderer unit:** reducer for `value_recorded`, the state machine of requirement 17, run picker rules.
- **e2e:** static editing, keyboard path, run with recording on and off, restart, different-version run.
- **Stories:** as above.

## Security / trust considerations

Recorded values are user, repository and model data and may contain secrets the redactor does not know. That is
why recording is opt-in, bounded and explained next to its switch, and why it ships only after `serve` can
redact. Events stay in the 0600 files of the 0700 run directory; there is still no retention or deletion tool
(F3.2), which the Settings text says. Values are rendered as text, never as HTML, and never leave the machine.
Graph and port names are untrusted text.

## Observability

Recording a value is an observable fact in the event stream (AGENTS.md rule 8). Editing emits no run events.

## Open questions

- **ADR-0023 decision 5:** opt-in (proposed, off by default) or default-on. Section B does not start until it is
  answered; sections A and the reducer work do not depend on it.
- Whether the per-run cap of 1 MiB and the per-value cap of 16 KiB suit real graphs; both are constants to be
  confirmed against the demo and a real agent run.

## Out of scope for this iteration

Ordering edges, expressions and transformations, value diff between runs or attempts (F2.8), artifact content
viewing, retention and deletion of recorded values (F3.2), Hosted sync of values.
