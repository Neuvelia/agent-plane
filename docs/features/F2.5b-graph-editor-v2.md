# F2.5b - Graph editor v2 and light theme (desktop, presentation)

**Status:** implemented (awaiting owner review)
**Priority:** P1
**Target phase:** Phase 2 - Local IDE
**Depends on:** F2.1, F2.2, F2.3, F2.4, F2.5a
**ADR:** ADR-0046
**Registry:** `docs/roadmap/features.yaml` entry F2.5b
**Design source:** canvas "Tarmind Dashboard UX", artboards *Graph editor v2: step cards*
(light, dark), *error blocks run*, *graph menu*, *step menu*, and the *Sidebar* component.

## Problem

The F2.1 editor stacks a toolbar of buttons, the canvas, a node list, the Bindings,
graph inputs/outputs and inspector cards, and the Issues panel down one long page.
Nodes show only ports, so reading a graph means opening every node. The app has a
dark theme only, while the approved v2 design is light-first.

## Goal

The desktop editor matches the v2 artboards: one header row, a full-bleed canvas of
self-describing step cards, the inspector on the right, and problems in a status bar
that opens a drawer, in a light and a dark theme, with short eased motion.

## Non-goals

- Any change to the sidecar, graph schema, operations, events, run store, file grants
  or the preload bridge.
- Testing one step, running from a step, canvas comments, copying or duplicating a
  step, renaming, duplicating, revealing, copying the path of or deleting a graph
  file: shown disabled with "Soon" (ADR-0046 §4).
- The design's recent-runs list and profile row in the Sidebar.
- Redesigning screens other than the editor beyond what the light theme and the
  shared Sidebar need.

## Functional requirements

1. **Header row.** The file name opens the graph menu; a Visual / YAML / Split switch
   with a sliding thumb; save state; Undo and Redo; Save; one primary action, Save and
   run. When the engine reports errors, "N errors block run" sits next to it, opens
   the drawer and takes the person to the first error. Other block reasons are shown
   as text there. Cmd/Ctrl+S saves and Cmd/Ctrl+Enter runs.
2. **Graph menu.** Find field; recent graphs with the current one ticked and its step
   count; New graph; Open; "This graph" actions; Close graph; Delete file last.
3. **Step cards.** Kind above the card; the node id in the card; an error or warning
   count badge; a "…" button (also right-click) for the step menu; the prompt (first
   text field), up to two key settings (path lists first, then required values, by
   descriptor order and label); one row per input saying where it comes from or "Not
   connected" (error-styled only when the engine reports an error there); the loop's
   maximum attempts; one row per output with a warning mark when the engine warns.
   Every port is a handle on the card edge. The selected card has a 2 px border and a
   ring, and shows "Test this step" (Soon).
4. **Edges** are labelled with the output port they carry when there is room, always
   when selected (with the type) or when the engine reports an issue (dashed).
5. **Step menu.** Test this step and Run from this step (Soon); Connect to…; Rename
   (F2); Copy and Duplicate (Soon); Delete step (⌫), with the existing confirmation
   when it takes connections with it.
6. **Canvas chrome.** Bottom left: zoom out, level, zoom in, fit, Auto-layout, minimap.
   Bottom right dock: Select, Pan (or hold Space), Comment (Soon), Find a step (lists
   steps, selects and centres one), Add step (menu of the four kinds).
7. **Inspector panel** (340 px): a step shows the F2.2 inspector with a Name field,
   sections in the order execution, retries and gate, inputs, outputs, Advanced
   (collapsible, open when it has entries) and the node's connections; an edge or a
   graph input binding shows the edge inspector and the Bindings panel; nothing
   selected shows the graph: run inputs, Bindings, graph inputs and outputs. Escape
   or the close button clears the selection.
8. **Problems.** The status bar always shows the counts (or "No problems"), the graph
   version and how fresh the engine's check is; the counts open a drawer listing the
   issues errors first, each a button that goes to its element. The drawer opens by
   itself when a graph opens with errors; the person's later choice is remembered.
9. **Empty graph.** The canvas offers the first step by kind, the YAML view, and the
   two tips; the inspector says no step is selected.
10. **Themes.** Settings › Appearance: System (default), Light, Dark; every colour token
    has both values; both meet the F2.5a contrast rules.
11. **Motion.** Menus scale and fade in and out; floating panels slide; cards pop in;
    the drawer, chevrons and the view thumb animate; everything stops under
    `prefers-reduced-motion`.
12. **Storybook.** A theme toolbar; stories for each artboard state; the smoke renders
    every story in EN and PL (dark) and EN (light) with axe, and fails a story whose
    play function throws or does not finish.

## Data / API contracts affected

None of the engine's. New renderer `localStorage` keys: `agentplane.theme`,
`agentplane.editor.view`, `agentplane.editor.problems`. New recorded fixtures
`graph-open-fix-issue*.json` / `graph-validate-fix-issue*.json`
(`AP_RECORD=editor-v2 node scripts/record-graph-fixtures.cjs`).

## Failure behavior

Unchanged from F2.1-F2.4: a refused operation, a conflict, a parse error (canvas
read-only with its reason in a toast) and an unreachable engine (status bar and
drawer) are shown as before. A "Soon" control does nothing and sends nothing.

Presentation only. No new IPC, network or filesystem access; graph text, diagnostics
and values stay untrusted display data. Preferences stay on this computer.
