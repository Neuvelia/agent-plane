# F2.3 E6 - Recorded run values (engine)

**Status:** implemented (Go engine, CLI, server); desktop presentation is slice E5b
**Priority:** P1
**Target phase:** Phase 2 - Local IDE
**Depends on:** F0.6 (events), F1.7 (accepted values and provenance), F2.9 (run store), F2.5 (loopback API)
**ADR:** ADR-0023 (proposed; its open decision only selects the default, see Open questions)
**Refines:** `F2.3-edge-data-mapping-editor.md`, section B (requirements 9-14)
**Plan:** `docs/superpowers/plans/2026-11-14-graph-editor.md`, slice E6

## Problem

F2.3 must let a user point to the concrete value that crossed an edge in a given
run. No event, store file or API carries values: accepted runtime values and
their provenance live only in memory and in `RunResult`.

## Goal

When value recording is explicitly enabled for a run, the event stream carries
one bounded, redacted `value_recorded` fact per graph input and per accepted
output port. The facts are persisted with the existing run store, replay
identically after a restart through the existing run-events API, and are never
emitted when recording is off.

## Non-goals

- Desktop Settings switch, reducer and edge inspector (slice E5b).
- A side store, a second read path or a dedicated values endpoint (ADR-0023
  alternative A and decision 6).
- Values of rejected attempts, failed, skipped or cancelled nodes, target-side
  (resolved input) values, or artifact contents (ADR-0023 decisions 2, 3, 8 and
  alternative C).
- Retention or deletion of stored values (F3.2).
- Secret discovery beyond the explicit configured redaction list.

## Functional requirements

1. **Event.** Event schema **10** adds `value_recorded`. Readers accept schemas
   1-10 with their historical shapes; `value_recorded` is rejected in a stream
   that claims schema 1-9. Payload fields:
   - `node_run_id`, `attempt_id`: equal to the event envelope's fields; both
     empty (omitted) for a graph input; `attempt_id` is the accepted attempt for
     loop producers and enrolled units and empty for a node without a loop.
   - `port`: the output port name, or `inputs.NAME` for a graph input.
   - `type`: one of `string`, `number`, `boolean`, `json`, `artifact_ref`.
   - `size_bytes`, `sha256`: size and lowercase hex SHA-256 of the full recorded
     text (requirement 3) before any cut.
   - `truncated`: true when `value` is shorter than the full text or omitted.
   - `redacted`: true when redaction changed the text.
   - `value`: the carried text; omitted only when nothing could be carried.
2. **Which values.** One event per supplied graph input, in input-name order,
   immediately after `run_started` and before any other fact. One event per
   output port present in a node's accepted outputs, in port-name order, after
   the node's other acceptance facts and immediately before its
   `node_finished` with status `succeeded`. For an enrolled unit the accepted
   values are the unit's immutable accepted values. An optional input or output
   with no value records nothing.
3. **Text form.** `string` is its text, `number` its JSON decimal text,
   `boolean` `true` or `false`, `json` its JSON bytes as received, and
   `artifact_ref` the reference string only. Redaction runs on this text
   first; `size_bytes` and `sha256` then describe the redacted full text, so no
   digest of an unredacted secret is published.
4. **Bounds.** At most 16 KiB (16384 bytes) of text is carried per event, cut at
   a UTF-8 rune boundary. A run carries at most 1 MiB (1048576 bytes) of value
   text in total; when the remaining budget is smaller than the text, the text
   is cut to the budget; when nothing (not even one whole rune) fits, `value` is
   omitted and `truncated` is true. Absence of `value` is never used for an
   empty value: an empty string is `"value":""` with `truncated:false`.
5. **Not representable.** A text that is not valid UTF-8 after redaction is
   recorded with `value` omitted and `truncated: true` (size and hash still
   describe it), because JSON would otherwise rewrite the bytes.
6. **Redaction.** The runtime's configured exact-value redactor
   (`Options.LogRedactions`) is applied to the whole text before cutting, so a
   secret spanning the cut is replaced. Recording requires UTF-8 redaction
   values and a UTF-8-safe marker; otherwise preflight fails before
   `run_started`.
7. **Opt-in.** `runtime.Options.RecordValues` is false by default. `agentplane
   run` and `agentplane serve` set it only with `--record-values`. Without it no
   `value_recorded` event is emitted anywhere.
8. **Server redaction.** `agentplane serve` accepts `--redact-env NAME`
   (repeatable) with the same meaning and validation as `agentplane run`; an
   unset variable refuses to start the server. A graph containing a configured
   secret value is refused before a served run starts, because the store keeps
   a byte copy (ADR-0019).
9. **Persistence and replay.** `value_recorded` is an ordinary retained,
   non-progress event: it is synced to `events.jsonl` before `Append` returns
   and is never subject to progress retention limits. `GET /runs/{id}/events`
   replays it from the hub or, for a run of an earlier process, from the store.
10. **Run summary.** Store summaries (`GET /runs`, `GET /runs/{id}`, `runs
    list --json`) gain `graph_version` from the first event (additive; F2.3
    requirement 14).

## Data / API contracts affected

- Event schema 10, new type `value_recorded` and its payload; constants
  `events.MaxValueBytes` and `events.MaxRunValueBytes`.
- `runtime.Options.RecordValues`.
- CLI: `run --record-values`; `serve --record-values` and `serve --redact-env`.
- Store `Summary.GraphVersion` (JSON `graph_version`).
- No graph schema change, no new HTTP route.

## Failure behavior

- Recording off: no event, no extra work.
- Invalid redaction configuration with recording on: preflight error, no run.
- Store write failure: unchanged ADR-0019 behavior (serve stops the run; CLI
  reports a persistence error).
- Malformed `value_recorded` JSON (unknown field, wrong type, value longer than
  16 KiB, inconsistent size/hash for an untruncated value, value missing
  without `truncated`, mismatched envelope identifiers, schema below 10) is
  rejected by the reader.

## Acceptance criteria

- [x] Recording off: the demo graph's stream, store file and CLI JSON contain no
      `value_recorded` (runtime, CLI and serve tests).
- [x] Recording on: one event per supplied graph input and per accepted output
      port, ordered as requirement 2 (runtime test).
- [x] A value above 16 KiB carries exactly 16384 bytes or fewer at a rune
      boundary, `truncated: true`, and `size_bytes`/`sha256` of the full text.
- [x] After 1 MiB of carried text, further ports have no `value` and
      `truncated: true`; the carried total never exceeds 1 MiB.
- [x] A configured secret never appears in an event, store file or API
      response, including when it spans the 16 KiB cut; `redacted` is true.
- [x] Failed, skipped and cancelled nodes and rejected attempts record nothing.
- [x] Stored events read back after a fresh process equal the live events, and
      the API replays them from the store.
- [x] Schema 1-9 streams remain readable; `value_recorded` with schema 9 is
      rejected; payload round trips and malformed payloads are tested.
- [x] `serve` refuses an unset `--redact-env` variable and a graph containing a
      configured secret.
- [x] Store summaries carry `graph_version`.

## Required tests

- Unit (`internal/events`): payload validation, JSON round trip, schema gating,
  historical decoding, copy isolation.
- Runtime: emission on/off, ordering, bounds, budget, redaction across the cut,
  invalid UTF-8, failed/rejected nodes, preflight of redaction values.
- Store: round trip of `value_recorded`, `graph_version` summary.
- API: auth unchanged; stored-run replay includes values without secrets.
- CLI: `run --record-values --store-dir`, `serve` flags.

## Security / trust considerations

Values are untrusted repository, user and model data. Redaction is explicit-list
only, so an unknown secret in a value is recorded; this is why recording is
opt-in. `events.jsonl` keeps 0600 permissions in a 0700 directory. The API stays
loopback-only, token-checked and without CORS.

## Observability

`value_recorded` is itself the observable fact; it does not change any state
transition.

## Open questions

- **Default on or off** (ADR-0023 open decision): implemented as opt-in, off by
  default, which is the ADR's proposal and the conservative choice. Only
  requirement 7 changes if the product owner chooses default-on.
- **Digest of the full value**: ADR-0023 says `size_bytes` and `sha256`
  describe "the full value". This implementation computes them over the
  redacted full text (requirement 3), so a digest of an unredacted secret is
  never published. Confirm or change in the ADR.
- **Value encoding**: the ADR does not fix the JSON shape of `value`. It is
  always a string in the text form of requirement 3; clients interpret it with
  `type`. A truncated `json` value is not valid JSON.
- **Invalid UTF-8 text**: not covered by the ADR; recorded without `value`
  (requirement 5). F2.3 asks the UI to show size and hash in that case.

## Out of scope for this iteration

- Desktop Settings, reducer and inspector (E5b); the desktop passing
  `--record-values` or `--redact-env` to the sidecar.
- Rendering `value_recorded` in `run --watch` text output.
