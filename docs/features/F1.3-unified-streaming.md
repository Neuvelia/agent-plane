# F1.3 - Unified Streaming

**Status:** implemented (ADR-0011)
**Priority:** P0
**Target phase:** Phase 1 - Agent Loop
**Depends on:** F1.1, F1.2

## Problem

The real adapter can expose progress, but F0.6 log chunks and synchronous live
delivery do not provide a provider-neutral event vocabulary or bounded
retention for long agent sessions.

## Goal

Show Agent progress in the CLI before completion through correlated,
provider-neutral events while keeping memory bounded and scheduler transitions
independent of a slow progress consumer.

## Non-goals

- Reconstructing private model reasoning, a UI, durable event storage, or
  normalizing every provider-specific payload.

## Functional requirements

1. Define event types for `text_delta`, `tool_call_started/finished`,
   `command_started/finished`, `file_changed` and `status`, with typed payloads
   and F0.6 run/node correlation. Attempt IDs remain empty until F1.6.
2. Normalize supported provider messages in the adapter boundary. Unknown
   provider data is discarded; no raw debug data is retained (ADR-0011),
   and it is never an instruction to the runtime.
3. Set explicit byte and item bounds for per-run retained progress and live
   delivery queues. On overflow, expose a count/marker of omitted progress
   instead of silently claiming a complete trace. Preserve lifecycle events.
4. A slow or absent progress reader must not block scheduler state transitions.
   Cancellation must still terminate the run under backpressure.
5. CLI progress is flushed before the agent exits in a synchronization test.
6. Specify a new event schema version or additive compatibility rule in an
   ADR before changing serialized events.

## Data / API contracts affected

Event schema, adapter progress callback, emitter retention and live delivery,
CLI event rendering. `RunResult.Events` currently holds all events; its bounded
behavior and truncation evidence must be explicitly migrated.

## Failure behavior

Malformed provider events are ignored or recorded as bounded diagnostic
evidence without failing an otherwise valid task unless they prevent result
decoding. A consumer disconnect, queue overflow or cancellation cannot deadlock
the scheduler. Truncation is visible in trace and CLI machine-readable output.

## Acceptance criteria

- [x] A fake adapter emits each normalized type; serialized events preserve
      order, type, run ID, node ID and node-run ID.
- [x] A barrier-controlled CLI test observes a progress event before the fake
      adapter is allowed to finish.
- [x] With a nonreading consumer and at least 100 MiB of generated progress,
      retained payload and queue bytes stay under documented fixed limits;
      lifecycle terminal events remain available and omission is reported.
- [x] Cancellation under a full queue reaches a terminal run state.
- [x] Unknown provider payloads cannot expose task/environment secrets in
      standard events; schema compatibility tests pass.
- [x] `make check` and `go test -race ./...` pass.

## Required tests

- Unit: normalization, serialization round trip, redaction, size limits and
  overflow markers.
- Integration: slow/no consumer, cancellation under backpressure, live CLI
  progress barrier, preserved lifecycle ordering.
- CLI/e2e: JSON and human progress rendering from a fake Agent invocation.

## Security / trust considerations

Progress may contain secrets or model reasoning. Redact configured sensitive
values across chunk boundaries, cap raw debug metadata, and never expose
private reasoning fields. Do not parse provider prose as control commands.

## Observability

Emit normalized progress, explicit omissions and terminal lifecycle facts.
Trace consumers must be able to tell complete from truncated progress.

## Resolved implementation decisions

ADR-0011 fixes schema 3 with v1/v2 decoding, retained progress limits of 4 MiB
encoded event bytes / 4096 items, and live FIFO limits of 1 MiB / 1024 items
including in-flight delivery. Drop-new retention and live-prefix sealing expose
separate omission counters. Lifecycle/evidence remain retained independently;
final marker and run_finished replay after delivery-pump shutdown. Progress
payloads are bounded, redacted and private-reasoning-free; malformed optional
provider records are skipped without weakening required result validation.

## Out of scope for this iteration

F3.2 durable event store, F3.5 artifact storage and run inspector UI.

Text-redaction source state admits at most 16 simultaneously unresolved source
IDs, releasing a slot whenever its secret-prefix/UTF-8 tail is empty. Admission
exhaustion ignores new sources while full and emits one `progress_limited`
status. Structural oversize/invalid optional progress is ignored at normalization;
collector omissions count validated admitted event facts. Configured secret
lengths bound each unresolved tail.

Observed executors require valid UTF-8 redaction values and a valid UTF-8
secret-absent replacement marker. Unsafe configurations fail preflight before
execution; normalized payload strings reject invalid UTF-8 before JSON can
replace bytes with U+FFFD. Legacy byte-only logs retain their byte redaction
contract. See ADR-0011 for the serialization security invariant.
