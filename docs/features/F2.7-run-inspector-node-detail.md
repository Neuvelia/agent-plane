# F2.7 - Run Inspector: Node Detail (remaining gap)

**Status:** draft (gap spec: part of the roadmap item is already delivered; see "Already delivered")
**Priority:** P0
**Target phase:** Phase 2 - Local IDE
**Depends on:** F1.5 (check results), F1.6 / F1.6a (attempts), F2.5 and F2.5a (reducer, node panel), F2.8a
(compare), F2.9 (run store), F2.3-E6 (`value_recorded`, ADR-0023). Roadmap lists F2.6 and F1.6; there is no hard
dependency on the F2.6 additions, but both specs change `desktop/src/reducer.ts`, so they land in either order.
**ADR:** none for the renderer work. The additive `graph_summary` fields of FR10 amend the ADR-0019 API contract:
see Open question 3.
**Companion:** `F2.6-run-inspector-overview.md`

## Problem

The roadmap wants "full evidence for a single execution decision": resolved input, normalized agent and tool
events, output and artifacts, check results with reason and evidence, changed files and a diff summary, and an
attempt selector. Today a loop node shows its attempt selector, check results, per-attempt log and (through
Compare) feedback and changed paths. Everything else the engine records about a node is dropped by the
renderer or never shown: normalized progress events fall into the event log as bare type rows, the check
result of a standalone Gate node is discarded, changed files of a node without a loop are discarded, accepted
input and output values (recorded when the user opts in) are not shown anywhere in a run, and attempt input
summaries are only used for feedback linkage. For a plain node (shell, agent without a loop, gate, human) the
panel shows little more than status and log.

## Goal

For any node of a live or stored run, a person opens its detail and sees from recorded events only: the facts of
the execution (duration, node-run ID, adapter), the check result with reason and evidence, what the node was
given and what it produced (when values were recorded), what the agent reported doing, which files Git observed
as changed (and which the agent merely claimed), and for each attempt the summary of its input. Every value
that was not recorded says so and why; unknown is never shown as empty, zero or green.

## Gap analysis

| Capability | State | Evidence in code |
| --- | --- | --- |
| Resolved input | Lacks | No event records a target-side input (ADR-0023 decision 3). Accepted source-side values exist as opt-in `value_recorded` events, but `reducer.ts` ignores them (`summarize` drops them) and `GraphSummary` has no port-level bindings, so the renderer cannot map a value to a node's input. `attempt_input` is reduced only for `previous_attempt_id` and `previous_check_id` |
| Output | Lacks | Same: accepted outputs are recorded when enabled and never shown in a run. Only a human node's decision is shown |
| Artifacts | Lacks, and no store | `artifact_ref` values are opaque references; the local artifact store is F3.5 |
| Normalized agent and tool events | Lacks | `text_delta`, `tool_call_started/finished`, `command_started/finished`, `file_changed`, `status`, `progress_omitted` (ADR-0011, carry the attempt ID) reach the `default` branch of `reduce`; `summarize` turns each into a bare EventLog row, so an agent run can push lifecycle rows out of the 200-row tail |
| Check result of a standalone Gate node | Lacks (defect) | The engine emits `gate_check` without an attempt ID for a Gate node (`internal/runtime/accept.go`); `reduce` attaches a check only to an existing attempt (`if (a)`) and a Gate node has none, so verdict, reason and evidence are dropped and the panel says "no correction loop" |
| Checked-input scope of a check | Lacks | `scope.checked_inputs` and the `changed_files_scope` details (mode, allowed paths, observed count) are in `gate_check`; `CheckView` does not keep them |
| Changed files, per attempt | Partial | Kept per attempt but shown only in Compare; the Attempts tab does not show them |
| Changed files, node without a loop | Lacks (dropped by design) | `node_evidence` without an attempt ID is explicitly ignored in `reducer.ts` (and pinned by a test that asserts the ignore) |
| Provider-reported file changes | Lacks | `file_changed` events (provenance `reported`) are not reduced; they must stay visibly separate from observed files |
| Diff summary | Partial | Counts follow from the file list; contents are never recorded. Patches are F2.8b (ADR-0026, proposed) |
| Adapter ID and version, node-run ID, start and end time, duration | Lacks | `node_evidence.adapter_*`, `node_run_id`, `startedAt`, `finishedAt` and `durationMs` are in `NodeView` or events but the panel shows none (duration only on the map node) |
| Attempt input summary | Lacks | `attempt_input` carries a task fingerprint, intended scope (up to 32 entries) and flags; not shown, so "did the retry get the same task?" cannot be answered |
| Truncation and omission markers | Lacks | the 64 KiB log cap drops the head silently; `progress_omitted` is not shown |
| Resolved prompt or command | Out of scope by design | the engine never records the raw task or argv (ADR-0011, F1.6); the panel says so |

## Non-goals

- Patch content or a diff viewer (F2.8b); this feature shows paths, counts and badges only.
- Opening, previewing or fetching artifacts, or any path on disk (F3.5).
- Recording new engine facts: no target-side resolved-input event, no raw prompt, command arguments or private
  model reasoning. Everything shown is already in the event stream or `graph_summary`.
- Token and cost figures (F3.10), replay or rerun of a node, workspace isolation facts (`workspace_*`, F3.1 UI),
  return-envelope and unit views.
- Editing the graph from node detail, a "show in YAML" jump, the check command text (not in events).
- The UI deciding status, retry or acceptance.

## Functional requirements

### A. Check result and execution facts

1. **Facts header.** The panel shows the node-run ID, started and finished times (locale formatted), duration,
   and, when a `node_evidence` event exists, adapter ID and version. A running node shows "running" and no
   duration. Unknown values read unknown.
2. **Standalone Gate.** A `gate_check` without an attempt ID is kept on the node (`NodeView.check`) and shown with
   the same `CheckResultView` as an attempt's check. A node with neither a loop nor a check shows the existing
   "no correction loop" text only when it truly has no check.
3. **Check scope.** The check view additionally shows the checked inputs (`scope.checked_inputs`, machine names)
   and, for `changed_files_scope`, the mode (`warn` or `deny`), the observed count and the allowed paths (or
   "redacted" when `scope_redacted` is set). Evidence presentation (omitted counts, `unavailable` references,
   indeterminate scope) is unchanged.
4. **Attempt labels.** Attempt tabs show the number and the outcome in text; the selected attempt is announced
   to assistive technology. Default selection is unchanged (follows the latest attempt unless chosen).

### B. Changed files and diff summary

5. **Changed files.** The Attempts tab shows, for the selected attempt, the sorted observed paths with count and
   the label "observed by Git"; for a node without a loop, `node_evidence` without an attempt ID is kept on the
   node and shown the same way. A node with no `node_evidence` shows "not observed" with the reason (shell
   node, producer failed, still running, not recorded; the reasons already defined by F2.8a), never "0 files".
   Paths are shown as received, repository-relative, as text; nothing opens them.
6. **Diff summary.** Beside the list: the number of observed files, how many of them an engine
   `changed_files_scope` result lists as out of scope (never evaluated in the UI), and the statement "file
   contents are not recorded" until F2.8b provides patches. Never an empty diff.
7. **Reported versus observed.** Provider-reported `file_changed` items are listed under a separate label
   "reported by the agent (not verified)" with their action; they never count toward, and are never merged into,
   the observed list.

### C. Activity (normalized events)

8. **Activity model.** The reducer builds a bounded `activity` per attempt (per node when the events carry no
   attempt ID) from `text_delta`, `tool_call_started/finished`, `command_started/finished`, `file_changed`,
   `status` and `progress_omitted`: text merged by source ID in arrival order; a tool call or command merged by
   its ID into one item with its latest status and exit code; reported file items; status codes. Bounds: at most
   200 items and 64 KiB of text per node; older items are dropped first and a counter keeps how many were dropped.
   `progress_omitted` is shown as "some progress was not recorded" with its retained and live counts.
9. **Activity view.** An Activity tab lists the items in order with the attempt they belong to, as text. For an
   old schema (below 3) or a node with no progress it says progress was not recorded rather than showing an
   empty list. Normalized progress events no longer produce EventLog rows (the Activity view owns them);
   `progress_omitted` still does, and every event still counts toward the event total.

### D. Inputs and outputs (values)

10. **Binding data.** `GET /runs/{id}` `graph_summary` gains, additively: per node the declared `inputs` and
    `outputs` (name, type, required) and a top-level `bindings` list of `{source, target}` where source is a node
    output (`node`, `port`) or a graph input (`name`) and target is `(node, input)`. Order is deterministic.
    Existing fields and the node-level `edges` are unchanged; a renderer that does not know the new fields works
    as before, and one that finds them absent (older engine) says bindings are unavailable.
11. **Value reducer.** One renderer module, shared with the edge inspector of F2.3 slice E5b so there is a single
    reduction, derives from `value_recorded` the recorded value of each `(node, port)` and each graph input
    (`inputs.NAME`), with type, size, `truncated`, `redacted` and the producing attempt and node-run IDs. Nothing is
    stored in components; stored and live streams reduce equally.
12. **Inputs and Outputs sections.** A "Data" tab lists each declared input of the node with its source (graph
    input or `node.port`) and the recorded value of that source, and each declared output with its accepted
    value. Rendering: string as text, number and boolean as is, `json` pretty-printed and collapsible, an
    `artifact_ref` as its reference string with the note that contents are not stored. Values over 2 KiB start
    collapsed. Size, `truncated` and `redacted` are shown. An empty string is shown as an empty value.
13. **Value states.** Each value shows exactly one of: recorded; not recorded (recording off, schema below 10,
    or budget reached, with a link to Settings, "Record run values"); source not finished yet; source failed,
    skipped or cancelled (no accepted value); optional input not bound; bindings unavailable; ambiguous (a source
    that ran as several static units: the value of the unit matching the selected node, or the ambiguity shown,
    never guessed). Only accepted values exist; a rejected attempt has none.
14. **Resolved prompt or command.** The Data tab states, for Agent and Shell nodes, that the raw task and command
    arguments are not recorded by design.

### E. Attempt input summary

15. **Summary.** Each attempt shows from `attempt_input` the first 12 characters of the task fingerprint, the
    intended scope entries (or "scope omitted"), and whether context or environment references were present.
    Compare gains one additive row, "Task input", stating whether the two chosen attempts had the same
    fingerprint (a statement of equality only; the fingerprint is a hash and says nothing about content).

### F. Completeness

16. **Markers.** When the 64 KiB log cap dropped earlier output the log shows "earlier output not shown" with the
    dropped size; an interrupted run labels its unfinished attempt "interrupted" (existing rule); a lost stream
    keeps the last state under the existing banner.

## Data / API contracts affected

- **Wire:** additive `graph_summary` fields (FR10), documented in the API package docs and ADR-0019. No new
  route, no event or schema change, no change to the bridge, preload surface, route allowlist or CSP.
- **Renderer:** `Attempt` gains input-summary fields; `CheckView` gains `checkedInputs` and scope details;
  `NodeView` gains `check`, `adapter`, node-level `changedFiles`, `activity`, `logTruncated`; a values module;
  `GraphSummary` type gains the optional fields; EventLog summarizer excludes normalized progress.
- i18n: new keys in `en` and `pl`; the Settings text for "Record run values" also names the run inspector.

## Failure behavior

- No `value_recorded` events (default): the Data tab shows binding structure when available and "not recorded"
  per value, never an empty value; an empty string is shown as empty only when the event says so.
- A value with invalid UTF-8 (`value` omitted, `truncated` true) shows size and hash prefix, not a blank.
- A JSON value that does not parse in the renderer shows its text as received.
- `graph_summary` without the new fields (older engine, or a graph that did not parse): bindings unavailable;
  other sections work.
- Activity events for an unknown tool or status: shown by their machine names; a `tool_call_finished` without a
  start becomes its own item.
- A run interrupted mid-attempt: unfinished attempt `interrupted`, tool calls left `in_progress` are shown as
  "unfinished", not completed.
- Lost stream: values show as of the last event; replay after reconnect is idempotent by sequence.

## Acceptance criteria

New fixtures are recorded from the engine runtime with the test fake adapter and documented like
`agent-scope-retry` (companion YAML and the recording command next to it): `gate-red` (a standalone Gate node that
goes red), `agent-progress` (a non-loop Agent node emitting normalized progress, `node_evidence` without an
attempt ID, and a `progress_omitted` marker). Existing fixtures: `demo-approve.json`, `demo-approve-values.json`,
`exhausted.json`, `agent-scope-retry.json`.

- [ ] For `gate-red`, the panel shows the Gate's verdict, check ID, kind, duration, reason, evidence and checked
      inputs, equal to the fields of its `gate_check` event; the "no correction loop" text is absent.
- [ ] For a loop node with a `changed_files_scope` Gate (`agent-scope-retry`), the check view shows mode,
      observed count and allowed paths equal to the event's `changed_files_scope` object, and "redacted" when
      `scope_redacted` is set.
- [ ] Facts header: node-run ID, start, end and duration equal the node's events; a node still running shows no
      duration; adapter ID and version equal the `node_evidence` payload.
- [ ] Attempt tabs read "Attempt N, outcome" in text (PL and EN) and do not rely on colour.
- [ ] `agent-scope-retry` attempt 1 lists `outside.go` and `src/a.go` and attempt 2 lists `outside.go`, `src/a.go`,
      `src/b.go`, each with the count and the "observed by Git" label, in the Attempts tab; a Shell node shows
      "not observed" (shell) and never "0 files".
- [ ] `agent-progress` shows its node-level changed files from the attempt-less `node_evidence` (the existing
      test that ignores it is replaced by one that asserts it is kept on the node and not on any attempt).
- [ ] Provider-reported `file_changed` items appear only under the "reported by the agent (not verified)" label
      and the observed count does not change when they are removed from the stream.
- [ ] Diff summary shows observed count, engine-listed out-of-scope count and "file contents are not recorded";
      no diff rows exist anywhere in the DOM.
- [ ] Activity for `agent-progress`: items equal the stream in order; a tool call with start and finish is one item
      with the final status; a command shows its exit code; `progress_omitted` shows its counts.
- [ ] Bounds: a synthetic stream of 10,000 `text_delta` events keeps at most 200 items and 64 KiB of text, the
      dropped counter equals the number dropped, the EventLog tail holds no normalized progress rows, a
      `progress_omitted` row is still present, and `eventCount` still counts every event.
- [ ] `go test ./internal/api/...`: `summarizeGraph` returns declared inputs, outputs and bindings (node-to-node
      and graph-input) in deterministic order for the demo graph and an unparsable graph returns empty
      collections; a response from an older engine (no new fields) parses in the renderer type test.
- [ ] With `demo-approve-values.json` each node's Data tab shows, for every bound input, the recorded value of
      its source, and for every output the accepted value, equal to the `value_recorded` payloads (value, type,
      size, `truncated`, `redacted`); with `demo-approve.json` every value reads "not recorded".
- [ ] Value states are each produced by a test: not recorded, source not finished (stream cut before the source's
      `node_finished`), source failed or skipped, truncated, redacted, empty string, optional input not bound,
      bindings unavailable, static-unit ambiguity shown and not guessed, json pretty-printed and collapsible,
      `artifact_ref` shown as reference only.
- [ ] A recorded string such as `<img src=x onerror=alert(1)>` appears as text and creates no element (DOM
      assertion); no `dangerouslySetInnerHTML` exists in `desktop/src` (the existing static test).
- [ ] Attempt input summary: for `agent-scope-retry` each attempt shows a 12-character fingerprint equal to the
      prefix of its `attempt_input.task_fingerprint` and its intended scope; Compare's "Task input" row says
      same or different from the two fingerprints.
- [ ] A node log over 64 KiB shows "earlier output not shown" and the dropped size; below the cap it does not.
- [ ] Stored `events.jsonl` replayed, live stream batched, and duplicated delivery produce equal node detail
      models (activity, values, changed files, checks, input summaries).
- [ ] No new bridge or preload method (the existing allowlist and preload surface tests pass unchanged); no new
      HTTP route; the CSP is unchanged.
- [ ] `en` and `pl` catalogues have identical keys and parameter names, including Polish plurals for new counts;
      axe reports zero violations on every new story in EN and PL.
- [ ] `make check`, `go test -race ./internal/api/...`, `npm run check`, `make desktop-e2e` and
      `make desktop-stories` pass.

## Security / trust considerations

- Everything shown is untrusted run data: values, paths, tool and command names, assistant text, reasons,
  evidence, allowed paths. It is rendered as text only, with no HTML, no links built from values, and no action
  that opens, reveals or fetches a path.
- No secret or absolute local path may be introduced by this feature. Values arrive already redacted by the
  engine's explicit redaction list (ADR-0023), so a secret outside that list can appear in a recorded value or in
  agent text; this is why value recording stays opt-in and the Settings text says so. The renderer does not try to
  detect secrets and never requests an unredacted copy.
- Changed-file paths and allowed paths are repository-relative as emitted; the renderer does not resolve them.
  Assistant text and logs are bounded in memory (64 KiB, 200 items).
- Reported file claims are provider data and are labelled as unverified; they never feed counts or scope badges.
- The additive `graph_summary` fields are derived server-side from the run's stored graph snapshot, so no client
  parses YAML; they contain names and types, never values. The loopback API, token and Host checks, the absence
  of CORS, the preload surface and the route allowlist are unchanged.

## Observability

No new events. The detail is a pure reduction of existing events plus the graph summary; a stored and a live run
render the same. Omitted or dropped data is always marked in the view.

## Open questions

Each has a recommended default; the implementation uses it unless the product owner decides otherwise.

1. **Source of "resolved input".** Default: derive it from source-side recorded values and the declared bindings
   (bindings do not transform values, so the source value is the target input), which needs recording to be on
   and no new engine fact. Alternative: record target-side resolved inputs as a new event, which reverses
   ADR-0023 decisions 2 and 3, adds more user data to the store and needs a new ADR.
2. **API shape for bindings.** Default: additive `graph_summary` fields on `GET /runs/{id}`. Alternative: reuse
   the graph-document API for a stored snapshot, which needs a file grant for a file that may no longer exist.
3. **ADR for the additive API fields.** Default: record them in ADR-0019 (consequences and contract note) rather
   than a new ADR. Alternative: a new short ADR if the lead treats every wire addition as one.
4. **Show model text by default.** Default: show `text_delta` text in the Activity tab like logs (it is already
   redacted and bounded). Alternative: collapsed behind an explicit "Show agent text" control because model
   output can echo repository content.
5. **Reported versus observed files.** Default: show both, in separate labelled lists. Alternative: hide
   provider-reported files entirely and show observed files only.
6. **Diff summary scope.** Default: counts and the out-of-scope count now, patches with F2.8b; the roadmap's
   "diff summary" criterion is read as counts plus the explicit "contents not recorded" statement. Alternative:
   hold F2.7 until ADR-0026 is accepted and F2.8b ships.
7. **Compare "Task input" row.** Default: add it (an equality of fingerprints only). Alternative: leave Compare
   as delivered and show the fingerprint only in the Attempts tab.
8. **Artifacts.** Default: show only `artifact_ref` reference strings and no open or preview, because the artifact
   store is F3.5. Alternative: defer the roadmap's "artifacts" line entirely and strike it from this feature.
9. **Check command text.** Default: not shown (events carry kind and check ID only; the YAML view has the
   command). Alternative: add a bounded redacted command summary to `gate_check`, an event contract change that
   needs its own spec and ADR.
10. **Tab layout.** Default: keep Attempts, Compare and Log, and add Activity and Data. Alternative: one scrolling
    detail with anchored sections; the choice is a design call and the tests address elements by test ID.

## Out of scope for this iteration

- Patch rendering, diff viewer, attempt diffs (F2.8b, ADR-0026).
- Artifact store, open or preview of artifacts (F3.5); export (F3.7).
- Token, cost and usage figures (F3.10).
- Raw prompt, command arguments, private reasoning: never recorded.
- Node replay or rerun and other debug operations; cancel (F3.4).
- Workspace isolation facts and return-envelope or unit views.
- Edge inspector in the editor (F2.3 slice E5b), except that it shares the value reducer of FR11.
