# F1.7 real Codex demonstration recipe

This recipe is prepared for an explicitly authorized **after-merge** run. It
has not been executed as part of F1.7 implementation. Deterministic tests use
a fake installed Codex CLI; they do not establish real model obedience.

Use a supported installed and authenticated Codex CLI and an absolute
`CODEX_BIN` environment value identifying it. The graph explicitly references
HOME and PATH for that CLI's existing authentication and tools; no values are
written into the graph or trace. Add a named CODEX_HOME reference only when
that installation actually uses it and it is present. Host authentication or
network access may require the same authorized outer-sandbox escalation used
for F1.2; preserve Codex's workspace-write sandbox and all execution rules.

From the merged AgentPlane checkout on Darwin/Linux:

```sh
export CODEX_BIN=/absolute/path/to/installed/codex
DEMO_DIR=$(mktemp -d /tmp/agentplane-f17-demo.XXXXXX)
mkdir "$DEMO_DIR/repo"
git -C "$DEMO_DIR/repo" init -q
printf 'green\n' > "$DEMO_DIR/repo/expected.txt"
for unit in a b c d; do printf 'initial\n' > "$DEMO_DIR/repo/$unit.txt"; done
git -C "$DEMO_DIR/repo" add .
git -C "$DEMO_DIR/repo" -c user.name=AgentPlaneDemo \
  -c user.email=demo@example.invalid commit -qm baseline
python3 - "$DEMO_DIR" <<'PY'
import json, pathlib, sys
base = pathlib.Path(sys.argv[1])
root = str((base / 'repo').resolve())
template = pathlib.Path('docs/examples/scoped-retry.yaml').read_text()
(base / 'graph.yaml').write_text(template.replace('"__WORKSPACE__"', json.dumps(root)))
PY
go build -o "$DEMO_DIR/agentplane" ./cmd/agentplane
"$DEMO_DIR/agentplane" graph validate "$DEMO_DIR/graph.yaml" --json \
  > "$DEMO_DIR/validation.json"
"$DEMO_DIR/agentplane" run "$DEMO_DIR/graph.yaml" \
  --adapter codex --codex-bin "$CODEX_BIN" --input reference=expected.txt \
  --max-concurrency 4 --json > "$DEMO_DIR/result.json"
python3 - "$DEMO_DIR" <<'PY'
import collections, json, pathlib, sys
base = pathlib.Path(sys.argv[1])
r = json.loads((base / 'result.json').read_text())
assert r['cli_schema_version'] == 1 and r['status'] == 'succeeded', r.get('failure')
events = r['events']
assert all(e['event_schema_version'] == 8 for e in events)
attempts = collections.Counter(e['node_id'] for e in events if e['type'] == 'attempt_started')
assert attempts == {'a': 1, 'b': 1, 'd': 1, 'z_c': 2}, attempts
returns = [e for e in events if e['type'] == 'return_envelope']
assert [e['payload']['verdict'] for e in returns if e['node_id'] == 'z_c'] == ['red', 'green']
accepted = {e['node_id']: e for e in returns if e['payload']['verdict'] == 'green'}
first_red = next(e for e in returns if e['payload']['verdict'] == 'red')
for unit in ('a', 'b', 'd'):
    assert accepted[unit]['sequence'] < first_red['sequence']
for n in r['nodes']:
    if n['node_id'] in accepted:
        e = accepted[n['node_id']]
        p = e['payload']
        assert n['accepted_attempt_id'] == p['attempt_id'] == e['attempt_id']
        assert n['node_run_id'] == p['source_node_run_id'] == e['node_run_id']
        assert p['source_run_id'] == r['run_id']
        assert p['source_graph_version'] == r['graph_version']
for e in returns:
    p = e['payload']
    check = next(c for c in events if c['type'] == 'gate_check'
                 and c['node_run_id'] == e['node_run_id'] and c['attempt_id'] == e['attempt_id'])
    assert all(p[k] == check['payload'][k] for k in ('check_id', 'verdict', 'reason', 'evidence'))
    finish = next(f for f in events if f['type'] == 'attempt_finished' and f['attempt_id'] == e['attempt_id'])
    assert check['sequence'] < e['sequence'] < finish['sequence']
assert sum(e['type'] == 'node_started' and e.get('node_id') == 'join' for e in events) == 1
outputs = {o['name']: o['value'] for o in r['outputs']}
assert outputs == {'a': 'a.txt', 'b': 'b.txt', 'c': 'c.txt', 'd': 'd.txt', 'joined': 'accepted-all'}
for unit in 'abcd':
    assert (base / 'repo' / f'{unit}.txt').read_bytes() == b'green\n'
print('PASS', r['run_id'], r['graph_version'], dict(attempts))
print('Accepted attempt IDs:', {u: e['attempt_id'] for u, e in accepted.items()})
PY
```

Keep `validation.json`, `result.json`, the rendered graph and resulting files
in the disposable directory. Record CLI exit status and the actual run/version/
accepted IDs in a separate validation report after executing the recipe. A
failed assertion is evidence to investigate; do not describe this prepared
recipe as a completed real-provider validation.

Here A/B/D map to node/unit IDs `a`, `b`, `d`; logical C maps to `z_c`.
`units` is unordered. The IDs use the scheduler's stable node order so A/B/D
are accepted before C's first red in this shared-workspace example. Existing
`candidate.outputs.summary` supplies the file-name value to the Gate's actual
port; `node.inputs.reference` supplies `expected.txt` to its reference port.
There are no ordering-only edges. The four loop nodes are the static batch;
only `z_c` gets a second attempt and the join receives green accepted values.

All Agent producer/check cycles in this checkout serialize, even with
`--max-concurrency 4`. Distinct proven Git worktrees may execute concurrently.
The declared scopes remain advisory. This demo inspects final files, but F1.7
immutability covers runtime values/provenance only; C could still modify a
sibling file. F1.8 owns actual-change scope enforcement and F3.1 owns filesystem
isolation. No rollback, new authorization policy or sandbox bypass is added.
