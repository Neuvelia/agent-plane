# F1.4 - Gate Node

**Status:** implemented (ADR-0012)
**Priority:** P0
**Target phase:** Phase 1 - Agent Loop
**Depends on:** F0.1-F0.7; consumes F1.2 Agent output in Phase 1 demo

## Problem

An Agent can modify a repository, but no deterministic graph node can accept
or reject its result before dependent work runs.

## Goal

Add a read-only Gate node with explicit data bindings and deterministic green
or red verdicts for command exit code, a JSON predicate and reported-file
scope. A red verdict blocks downstream execution and carries structured
reason/evidence.

## Non-goals

- Model judgment, correction attempts, Git-derived scope enforcement,
  permission policy or worktree isolation.

## Functional requirements

1. `type: gate` uses declared inputs/outputs and real data edges. It does not
   receive hidden Agent state or create ordering-only dependencies.
2. A command check executes structured argv in an explicit cwd/environment,
   with bounded log evidence and context cancellation. Its exit code determines
   verdict. The Gate never writes to the workspace by contract; a check
   command that may write must be rejected or run in a documented read-only
   execution context before this feature can claim that invariant.
3. A JSON predicate evaluates a specified field/comparison against a bound
   JSON value; missing field, invalid predicate and wrong input type fail
   deterministically. No arbitrary expression evaluator is added.
4. The F1.4 file-scope check compares an explicitly bound, reported
   `changed_files` JSON array to an explicit allowed-path list. It is an
   advisory consistency check on supplied data, not proof of filesystem
   changes. F1.8 owns `git diff --name-only`, warn/deny policy and
   authoritative out-of-scope evidence.
5. Green passes exactly once; red blocks downstream and records check ID,
   verdict, short reason and bounded evidence. F1.5 normalizes the complete
   Check Result shape, serialization, scope and duration.
6. The graph/verdict semantics and any new event payload require an ADR before
   implementation.

## Data / API contracts affected

Schema-v0 Gate config/ports, node state transition on red, structured check
result/evidence, event trace. Define whether red is a failed Gate Node or a
separate terminal state before implementation; never publish a red result as
an accepted success output.

## Failure behavior

Invalid config, unsafe writable command context, missing bound data, malformed
JSON, process start error and cancellation are distinct from a valid red
verdict. No downstream node starts after red. Evidence/logs are bounded and
redacted.

## Acceptance criteria

- [x] A failing command produces red with check ID, exit code and truncated
      log evidence; its dependent node never starts.
- [x] A zero-exit command produces green and the dependent node runs once.
- [x] JSON predicate green/red/missing-field cases are deterministic.
- [x] Reported-file scope rejects a supplied out-of-scope path and labels its
      evidence as reported data; it does not claim Git verification.
- [x] A Gate can be bound to Agent output using ordinary graph edges.
- [x] Invalid config and cancellation produce actionable results without
      accepted downstream data.
- [x] `make check` and `go test -race ./...` pass.

## Required tests

- Unit: Gate config, predicate and normalized path comparisons.
- Integration: red/green downstream scheduling, bounded command evidence,
  cancellation, reported-file scope and read-only command context.
- CLI/e2e: a graph with Agent, Gate and dependent Shell under a fake adapter.

## Security / trust considerations

Gate commands are untrusted process execution. Verify a genuinely read-only
execution mechanism or narrow the command contract explicitly in its ADR;
never label a writable process a read-only check. Redact secrets in evidence.

## Observability

Emit check ID, verdict, reason and bounded evidence with run/node correlation;
do not expose full command output by default. F1.5 makes this a stable
serializable Check Result.

## Resolved implementation decisions

ADR-0012 narrows command checks to the trusted system diff operation over two
regular files with generated argv and controlled environment. Arbitrary
commands/options are rejected; this is not a general subprocess sandbox.
Exit 0 is green, 1 red, and operational failures are errors. Red is a failed
Gate with retained schema-4 gate_check evidence and no accepted outputs.
Predicate missing fields produce red; expected_json supplies an exact JSON
scalar/null literal (mutually exclusive with expected). Floating-point expected
shorthand is rejected to avoid prior YAML rounding; numbers compare exactly without float
rounding. Reported file scope remains advisory. Capture is limited to 8 KiB
per redacted stream; the minimal payload is bounded. Full scope/duration and
reference normalization remain F1.5.

## Out of scope for this iteration

F1.5 full Check Result, F1.6 loop, F1.8 Git-derived enforcement and F3.9
execution policy.
