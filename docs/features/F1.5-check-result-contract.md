# F1.5 - Check Result Contract

**Status:** ready for implementation (ADR-0013)
**Priority:** P0
**Target phase:** Phase 1 - Agent Loop
**Depends on:** F1.4

## Problem

F1.4 creates deterministic Gate verdicts. A correction loop and Run Inspector
need one stable, typed result rather than parsing process logs or provider
prose.

## Goal

Normalize every Gate outcome as a serializable Check Result with verdict,
reason, evidence, scope, check ID and duration. A red result is useful input
for F1.6 without becoming an accepted graph output.

## Non-goals

- Confidence scoring, LLM-as-judge, artifact storage, long-term persistence or
  a correction policy.

## Functional requirements

1. Define typed `verdict` (`green`/`red`), stable `check_id`, short `reason`,
   bounded `evidence[]`, explicit `scope` and nonnegative `duration`.
2. Every red result has a nonempty reason and at least one evidence item. A
   green result may have evidence but may not hide an execution error.
3. Evidence identifies its kind and source; file/line, test, diff and artifact
   references are supported without embedding large raw output. Invalid or
   unavailable references remain distinguishable from empty strings.
4. Result JSON round trips without losing unknown/zero distinctions or field
   order assumptions. Define a version or forward-compatibility rule in an
   ADR before making this a durable event/API contract.
5. A Check Result is linked to run/node and, once F1.6 exists, attempt IDs.
   It appears in trace even when red blocks downstream. Sensitive values are
   redacted before serialization.
6. F1.4 Gate outcomes migrate to this contract without changing their
   deterministic verdict semantics.

F1.4 ADR-0012 supplies a minimal gate_check fact and failed-Gate red semantics.
F1.5 extends/migrates it; it must preserve downstream blocking and distinguish
operational errors from valid red.

## Data / API contracts affected

Typed Gate result, run trace event/evidence payload, failure representation
and future correction input. The ADR must define whether a red verdict is
represented as a failed node plus Check Result, and how a reader retrieves
that result without parsing a human-readable error.

## Failure behavior

Malformed result, missing check ID, red with empty reason/evidence, negative
duration, unsupported verdict or oversized evidence fails validation before
emission. A Gate process error is not silently converted to green or a false
red diagnostic. A trace serialization error fails closed.

## Acceptance criteria

- [ ] Every F1.4 red Gate yields a typed result with nonempty reason and
      evidence; downstream remains blocked.
- [ ] Green and red results JSON round trip with verdict, check ID, duration,
      scope and evidence references intact.
- [ ] A red result is retrievable from the in-memory run trace by run/node ID
      without parsing logs or error strings.
- [ ] Invalid results are rejected before they enter the trace.
- [ ] Large command output is referenced or truncated under the documented
      evidence budget, and configured secrets are redacted.
- [ ] `make check` and `go test -race ./...` pass.

## Required tests

- Unit: validation and JSON round trip, empty reason, zero duration, oversized
  evidence and unknown reference fields.
- Integration: red Gate trace retrieval, green Gate trace, correlation and
  stable downstream blocking.
- CLI/e2e: machine-readable result exposes typed fields rather than prose.

## Security / trust considerations

Evidence is untrusted text and may include paths, command output or secrets.
Bound payload size, redact configured values, and keep raw provider metadata
outside Check Result.

## Observability

Trace includes result identity, verdict, reason, bounded evidence, scope and
duration. The event is append-oriented and associated with the Gate execution.

## Resolved implementation decisions

ADR-0013 defines CheckResult v1, required nonnegative duration_ns, explicit
checked-input scope (not correction filesystem scope), bounded typed evidence
and absent/known/unavailable/invalid reference states. Emit schema5 gate_check;
retain distinct legacy schema4 decoding without invented duration/scope.
Typed trace lookup uses run/node-run identity and detached results. F1.4 red
state/downstream/operational-error semantics remain unchanged. Existing evidence
budgets remain32 items/32768 encoded bytes/8192 bytes per command stream.

## Out of scope for this iteration

F1.6 attempt creation, F1.7 scoped retry and F3.5 artifact storage.
