# F2.5 desktop demo - validation recipe

Covers Demo A (parallel branches), Demo B (loop repairs the unit, not the batch)
and Demo C (inspector with reason/evidence and a human gate) from the roadmap,
with no LLM on the critical path.

## Automated

```bash
make build
make desktop-e2e
```

`desktop/e2e/demo.cjs` drives the real Electron app against the real sidecar and
asserts, in order: renderer isolation (no `require`, `process` or token);
validate + run `.agents/graphs/demo-vertical.yaml`; `fast` and `flaky`
succeeded while `approve` waits (`waiting_human`) and `apply` is pending; two
attempts on `flaky` with a red `predicate mismatch` check then a green one and
none on `fast`; Approve with a comment from the inbox; run succeeded with
`apply` succeeded; application restart with the run still listed and the same
event count and attempts rebuilt from the store; a second run rejected so the
run fails, `approve` fails and `apply` is skipped; finally the sidecar is killed
(SIGKILL) while a run waits for approval and the inspector shows "Connection
lost" with the last received node states and disabled decisions, instead of an
invented run status.

Pass `desktop/e2e/demo.cjs <dir>` a directory to also save screenshots.

## Redesign (F2.5a) checks

Automated (`make desktop-e2e`, `make desktop-stories`, `npm run check` in `desktop/`):
Dashboard lists the pending approval and the active run; run summary, timeline
and event log are rebuilt after a restart; disabled sidebar entries are inert;
the first Tab stop is the skip link and Enter moves focus into the content; the
flowing edge animation stops under `prefers-reduced-motion`; every story passes
axe in English and Polish with no external request; colour pairs meet 4.5:1
(text) and 3:1 (focus ring, selection) from the shipped tokens.

Screenshots of the key screens in both languages are generated from the stories
(`npm run build-storybook && npm run screenshots`) into
`docs/validation/F2.5a-screenshots/{en,pl}/`.

Manual, per screen, in both languages (switch in Settings):

1. Dashboard, Runs, Approvals, New run, Settings: no clipped or overlapping text
   with the longer Polish strings; machine values (ids, event types, paths,
   engine diagnostics) stay as the engine wrote them.
2. Keyboard only: Tab reaches every control in a sensible order, a visible blue
   ring follows focus, Space/Enter operate buttons and segmented controls, Escape
   closes a `?` tip, and the greyed-out Projects/Runners/Docs entries are skipped.
3. Stop the sidecar while the app runs: Dashboard, Runs and Approvals show
   "Cannot reach the engine" with Retry (never an empty list), the top bar says
   "Connection lost", and Retry recovers once the engine is back.
4. macOS: the window has no native title bar, the top strip is black, the traffic
   lights sit in the sidebar corner, and the bar can drag the window.
5. With the system's "reduce motion" setting on, the running-node edge no longer
   animates.

## Manual

1. `make build && cd desktop && npm ci && npm start`.
2. New run -> choose `.agents/graphs/demo-vertical.yaml` -> Validate -> Run.
3. Watch the map; open `flaky` to see both attempts; Approve under Approvals.
4. Quit and reopen the app; the run is listed and fully reconstructed.

## Flaky end-to-end run: found and fixed

Roughly one end-to-end run in five failed with a Playwright click timeout on a
map node. A captured failure showed the node present in the DOM with the right
status but "element is not visible" for the whole 30 s. React Flow keeps a node
`visibility: hidden` until it has dimensions (`nodeHasDimensions`), and the map
replaced every node object on each event batch without declaring a size. The
failure is consistent with the measurement being lost on replacement, after which
`ResizeObserver` does not fire again because the size is unchanged. I did not
isolate that exact trigger inside the library. The map now declares each node's
fixed width and height, which makes visibility independent of measurement.
After the change 40 consecutive end-to-end runs passed (before it: 1 failure in
4 and 1 in 6 on the last two loops). That is strong evidence, not a proof of the
root cause.
