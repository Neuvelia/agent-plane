# F2.5d - Command palette and global shortcuts (desktop)

**Status:** implemented
**Priority:** P1
**Target phase:** Phase 2 - Local IDE
**Registry:** `docs/roadmap/features.yaml` entry F2.5d
**Depends on:** F2.5a (shell, tokens, PL/EN), F2.5b (Inbox and the page header the Search button sits in), F2.5c (light theme, Keyboard shortcuts window), F2.9 (run list)
**Note:** first drafted as F2.5b, then F2.5c; renumbered each time those IDs were taken on `main` (the Inbox redesign, then the profile menu and light theme).
**ADR:** none required (presentation only; no event, API, persistence or trust-boundary change)
**Design source:** Tarmind design canvas, artboard "Command palette" (`Palette.dc.html`) and the
shortcut sheet of "Shortcuts, About and Soon" (`Shell.dc.html`).

## Problem

Reaching a run, the approvals inbox or another screen takes several clicks through the sidebar and the
runs list. The design adds a keyboard-first command palette (Ctrl K / Cmd K) and a few global shortcuts;
the app has neither.

## Goal

From any screen, Ctrl K (Cmd K on macOS) or the global bar's Search button opens a palette that lists
actions, recent runs and screens, filters them as the person types and opens the chosen one. The palette
reproduces the design artboard: 640 px wide, 110 px from the top, dimmed and slightly blurred page behind,
56 px search row, 38 px rows in Actions / Runs / Go to groups with shortcut hints, and a footer that
explains the keys.

## Non-goals

- Searching graph files, node IDs, YAML or event text; running or deciding anything from the palette.
- The "Save and run" shortcut from the design's shortcut sheet. (The sheet itself, Ctrl /, and the
  About window belong to F2.5c; this feature adds its own shortcuts to that sheet.)
- Any change to the Go sidecar, API, events, store or Electron preload surface.

## Functional requirements

1. Ctrl K (Windows, Linux) or Cmd K (macOS) opens the palette from any screen, including while a text field
   has focus; the same chord, Escape or a click outside closes it. The global bar shows a quiet "Search"
   button (accessible name "Search and commands", `aria-keyshortcuts`) that opens it too.
2. The palette is a modal `<dialog>`: focus moves to the search field, stays inside while open and returns
   to where it was on close. The field is a `combobox` controlling a `listbox` of `option`s in labelled
   `group`s; the active option is announced through `aria-activedescendant`.
3. Entries, in order:
   - Actions: New run (Ctrl N), Open graph… (Ctrl O, the editor's guarded open), Review approvals
     (Ctrl Shift A, hint "N waiting" from the approvals list the shell already polls).
   - Runs: from `GET /runs`, read each time the palette opens, newest first; label = graph ID, hint =
     the first 8 characters of the run ID and its localised status. 5 runs without a query, at most 20
     with one.
   - Go to: Inbox (G then I, as in the design), Runs, Editor, Welcome and setup, Settings (Ctrl ,).
4. Typing filters case-insensitively on label, hint, group name and full run ID. A leading `>` limits the
   list to actions; a leading `#` limits it to runs whose ID starts with the rest. Tab cycles
   all → `>` → `#` → all by rewriting that prefix (Shift Tab goes back), keeping the typed text.
   *Divergence:* the implementation also matches the graph name in the `#` scope; the decision is
   tracked in [Neuvelia/agent-plane#218](https://github.com/Neuvelia/agent-plane/issues/218).
5. The first entry is active after every change of the query. Up and Down move the active entry and wrap;
   the pointer makes the entry under it active; Enter or a click performs it and closes the palette.
   The active entry is remembered by id, so runs that arrive while the palette is open never change
   which entry Enter performs. Keys are handled for the whole dialog: pressing on the footer, a
   heading, a row or a gap keeps focus in the field (the listbox, focusable for its scroll region,
   gives focus straight back). The backdrop is judged by pointer position: only a press and a click
   both outside the palette's box close it. A held palette chord (auto-repeat) does not close the
   palette it opened; the chord pressed during the exit animation opens a fresh palette once this one
   has closed. Enter during input-method composition does nothing. The active row is scrolled into
   view when it moves and after every edit of the query.
6. When nothing matches, the palette says "Nothing matches “…”. Try a run id or a graph name." and shows
   no empty listbox. While the run list is loading it says so; when it cannot be read it says so in the
   error colour. A failed read is never shown as "no runs". Each opening reads the list again, and an
   answer belongs to the opening that asked, so runs from an earlier opening are never shown. One
   persistent live region (`role="status"`, visually hidden) announces the number of results and the
   scope, no match, or the run list's state.
7. The shortcuts listed in the palette work outside it: chords anywhere, the G I sequence only while no text
   field has focus and with I within 1 s of G. They are ignored on auto-repeat and while any modal dialog
   is open (the palette handles its own chord); a G pressed in a dialog is forgotten. The editor's
   Ctrl/Cmd S is also ignored while a modal dialog is open.
8. Motion: the dialog enters in 180 ms (opacity, 8 px drop, scale .98 → 1, decelerating curve) while the
   backdrop fades in; it leaves in 120 ms (accelerating) before it is removed; the active row's background
   changes over 120 ms. With reduced motion both animations, including the backdrop's, are removed and the
   palette closes at once. If the exit animation never reports its end (a hidden window), the palette
   closes after 300 ms. The chosen command runs exactly once, after the dialog has closed.
9. All text is in the EN and PL catalogues; shortcuts are written "Ctrl Shift A" or "⌘ ⇧ A" by platform.
10. The palette follows the app theme (F2.5c, ADR-0047), as in the design's "Command palette · light":
    every colour is a theme token, the backdrop uses the shared `--scrim`, and the shadow is lighter in
    the light theme.
11. The shell has one shortcut listener for every app chord: the palette's, plus F2.5c's Ctrl/Cmd+,
    (Settings) and Ctrl/Cmd+/ (the Keyboard shortcuts window). A dialog that is animating out does not
    block them. The Keyboard shortcuts window lists the palette, New run, Open a graph, Review
    approvals and G I, and the profile menu closes on any of the app's chords.

## Data / API contracts affected

None. The palette reads `GET /runs` and the approvals list through the existing bridge and only navigates.

## Failure behavior

- Run list unreachable: the Runs group is absent and a "Runs could not be loaded" line is shown; actions
  and screens still work. Reopening the palette reads the list again.
- A command that needs the engine (Open graph…) fails in the screen it opens, as from the sidebar.

## Acceptance criteria

- [x] Ctrl K / Cmd K match the palette command by platform; the Search button carries its name and
  shortcut (F2.5d-AC1: `desktop/test/palette.test.ts`, `desktop/test/palette-view.test.tsx`).
- [x] Exactly one option is selected and referenced by the combobox; arrows wrap (F2.5d-AC2).
- [x] `>` lists only actions, `#8c1f` only runs whose ID starts with it; Tab cycles the prefix (F2.5d-AC3).
- [x] No match shows the message and no listbox; loading and error states are shown (F2.5d-AC4).
- [x] Stories for every state (`Screens/Command palette`, `UI/Shell/Global bar with search`) render in EN
  and PL with zero axe violations (`make desktop-stories`).

## Required tests

- Unit: `desktop/test/palette.test.ts` (filtering, scopes, bounds, active entry by id, shortcuts and the
  window decision (handled, repeat, open dialog, sequence window), keys inside the palette, the close
  sequence, a failed run read).
- View: `desktop/test/palette-view.test.tsx` (dialog/combobox/listbox markup, groups, hints, states, PL).
- DOM (jsdom): `desktop/test/palette-dom.test.tsx` (the component and hooks: Enter/Escape/chord and the
  close order, animationend vs fallback vs reduced motion, reopen during the exit, IME, focus return,
  active entry when runs arrive, Tab, scroll into view, mouse focus and backdrop rules, live region,
  run reads per opening, global shortcut suppression).
- Browser: `desktop/scripts/stories-smoke.cjs` renders the eight palette stories; it waits for the
  render phase `finished` and finite animations before running axe, and fails a story whose play
  throws (`playFunctionThrewException` from the preview channel, not only the console). Each palette story's play asserts the state
  it ends in.

## Security / trust considerations

Run IDs and graph IDs are shown as text only. The palette adds no route, no storage and no network access;
shortcuts never act inside text fields except the explicit chords.

## Observability

Not an execution path: no events. Behaviour is visible in the stories and in the real app.
