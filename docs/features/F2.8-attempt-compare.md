# F2.8 - Attempt Compare

**Status:** F2.8a implemented (desktop only); F2.8b accepted in direction, not implemented. Decisions D1-D6
decided by the owner on 2026-11-15 (see "Decisions").
**Priority:** P1
**Target phase:** Phase 2 - Local IDE
**Depends on:** F1.6 / F1.6a (attempts, ADR-0014, ADR-0018), F1.5 (Check Results, ADR-0013), F1.8
(changed-files scope, ADR-0016), F1.2 (Git-observed evidence, ADR-0010), F2.9 / F2.5 (run store, loopback
API and event reduction, ADR-0019). Roadmap dependency F2.7 (Node Detail) is specified in
`F2.7-run-inspector-node-detail.md` (accepted for implementation, 2026-11-17); F2.8a uses the existing desktop
node panel as its entry point, and F2.7 adds a "Task input" row to the Compare view.
**ADR:** ADR-0026 (attempt diff capture), proposed for the F2.8b part; owner decisions recorded

## Problem

A node with a correction loop can run up to ten attempts (ADR-0014, default three). When attempt 2 succeeds
after attempt 1 was rejected, the user needs to know whether the retry fixed the reason the Gate gave, or
only changed the result in some unrelated way, and whether it touched files it did not touch before. Today
the desktop shows attempts one at a time: outcome, check result and log per attempt. It cannot put two
attempts side by side, it ignores the Git-observed changed files that the engine already records
(`node_evidence` is not reduced), and nothing anywhere records file contents, so no attempt can be diffed.

What the engine on `main` (event schema 9) records per attempt, verified in code:

| Fact | Where | Coverage and limits |
| --- | --- | --- |
| Number, budget | `attempt_started` (`number`, `max_attempts`) | All loop producers |
| Feedback linkage | `attempt_input` (`previous_attempt_id`, `previous_check_id`, task fingerprint, intended scope up to 32 entries / 1 KiB) | All loop producers; no raw task |
| Feedback content | `gate_check` of the previous attempt | The retained `CorrectionFeedback.CheckResult` is a clone of that event's payload, so the feedback is exactly reconstructible from the stream |
| Check result | `gate_check` (CheckResult v1: verdict, reason, up to 32 evidence items, 32 KiB, `duration_ns`) | All checked attempts |
| Outcome | `attempt_finished` (`accepted`, `rejected`, `needs_intervention`, `execution_error`, `cancelled`) | All attempts |
| Duration | event timestamps of `attempt_started` and `attempt_finished` | All attempts; wall clock, not monotonic |
| Changed file paths | `node_evidence` with `attempt_id` (`changed_files[]{path, provenance: observed}`) | Agent producers only, and only when the producer succeeded. Paths changed during this one invocation (before/after snapshot, ignored files excluded, ADR-0010). Shell producers emit none |
| Out-of-scope paths | `gate_check` evidence of a `changed_files_scope` Gate (ADR-0016) | Only when that Gate kind is configured; cumulative since the first attempt's baseline; out-of-scope paths only, bounded |
| Provider-reported file events | normalized progress `file_changed` (ADR-0011) | Provider claims, bounded and droppable; not evidence |

File contents before or after an attempt are not recorded anywhere. `gitstate` keeps only index entries and
SHA-256 digests of working files, in memory.

## Goal

From a loop node in a run (live or replayed from the store), a person opens Compare, picks two attempts, and
sees side by side: outcome, verdict, reason and evidence, duration, changed file paths with "new in this
attempt" and scope badges, and the feedback that started the later attempt. When attempt diff capture
(ADR-0026) was enabled for the run, the person also sees what each attempt changed in each file. When it was
not, the view says that contents were not recorded and never shows an empty diff in its place.

## Non-goals

- Semantic or LLM-based comparison of attempts (roadmap P2; AGENTS.md rule 5).
- Comparing attempts across different runs, or nodes against each other.
- Rolling back, re-running, or accepting an attempt from the compare view; the view is read-only.
- Workspace isolation or snapshots for restore (F3.1). Captured diffs are evidence, not a restore point.
- Recording attempt inputs or outputs as values (ADR-0023 records accepted outputs only).
- Re-implementing scope policy in the UI (see FR6).
- A Git client or a general diff editor.

## Phasing

The feature is split so that the part that needs no new contract is not blocked by the capture decision.

- **F2.8a - Compare recorded facts.** Desktop only. No engine, event or API change. Works for every stored
  run with event schema 6 or later.
- **F2.8b - Attempt diffs.** Engine capture contract from ADR-0026, a new event type and the desktop diff
  panel. Starts only after ADR-0026 is accepted.

## Functional requirements

### F2.8a - Compare recorded facts

1. **Entry point.** The node panel of a node with two or more `attempt_started` events offers "Compare
   attempts". A node with fewer attempts offers nothing. The entry point exists for running and finished
   runs, and for runs replayed from the store.
2. **Attempt selection.** Two selectors, "From" and "To", list every attempt as `Attempt N . outcome`
   (`running` while unfinished). Default: From = the first `rejected` attempt (else attempt 1), To = the last
   attempt. A swap control exchanges them. Selecting the same attempt on both sides is allowed and shows
   identical columns. Selection is view state of the node panel: it is kept while the node stays selected
   (including switching to another panel tab and back) and resets when another node is selected.
3. **Side-by-side table.** One row per fact, one column per attempt:
   - Outcome (from `attempt_finished`; `running` before it arrives).
   - Verdict and reason (from that attempt's `gate_check`; "not checked" when the attempt has none, for
     example `execution_error` or `cancelled`).
   - Evidence: the check's evidence items rendered as the existing check view does, including omitted counts.
   - Attempt duration (timestamp difference of `attempt_started` and `attempt_finished`) and check duration
     (`duration_ns`).
   - Changed files: count and sorted list from that attempt's `node_evidence`. When no `node_evidence` exists
     for the attempt the cell says "not observed" with the reason: Shell producer, producer failed, or event
     schema older than the field. Never "0 files" in that case.
   - Feedback: "none" for an attempt without `previous_attempt_id`, otherwise "from attempt N".
4. **Feedback section.** For the To attempt, when `attempt_input.previous_attempt_id` is set, show the
   previous attempt number, the `previous_check_id`, and the reason and evidence of the referenced
   `gate_check`, labelled as the typed, bounded feedback the producer received. If the referenced attempt or
   check is missing from the stream (truncated log), say so.
5. **"New files" badge.** A path listed in one attempt's `node_evidence` and not in the other's is badged
   "not in attempt M" (M = the other attempt), in either column, so the wording stays true after a swap.
   With the default pair this marks what the later attempt touched that the earlier did not. This is a
   plain set difference of recorded observed paths. It is shown only when both attempts have
   `node_evidence`. Because edits persist between attempts (ADR-0014, no rollback), the per-attempt lists
   describe what each invocation touched, not cumulative state; the view says this in one line.
6. **"Outside scope" badge.** A path is badged "outside allowed scope" only when the attempt has a
   `changed_files_scope` check result whose evidence lists that path. When no such check ran for the
   attempt, the scope cell says "scope not checked". The UI does not evaluate `allowed_paths` itself, so it
   cannot disagree with the engine's ADR-0016 matcher.
7. **Accepted marker.** When the node succeeded, the accepted attempt is marked as the node's accepted
   output for the run.
8. **Live behaviour.** While a run is active, the view updates as events arrive, using the same reducer as
   the rest of the desktop. No polling and no second read path.
9. **Contents placeholder.** Without F2.8b data the diff area states "File contents were not recorded for
   this run" and links to the setting described in F2.8b (once it exists). It never renders an empty diff.

### F2.8b - Attempt diffs (blocked on ADR-0026)

The requirements below assume the recommended option of ADR-0026 (engine-rendered, bounded, redacted patch,
opt-in, inline events). If the team picks another option, this section is rewritten before implementation.

10. **Opt-in capture.** `agentplane run --record-diffs` and `agentplane serve --record-diffs` enable
    capture; the desktop passes the flag only when the user enables "Record file changes for attempt
    compare" in Settings, off by default. `serve` must support `--redact-env` before the desktop can enable
    the setting (same precondition as ADR-0023). Default event streams are unchanged.
11. **Scope of capture.** Capture applies to attempts of loop producers that have a declared Git workspace
    accepted by `gitstate.CanonicalWorkspace` (Agent nodes today). Non-loop nodes, Shell producers and
    Gates are not captured in this iteration.
12. **Snapshot points.** The engine records the workspace state immediately before the first attempt and
    immediately after each attempt's producer finishes (before the Gate runs). Attempt N's diff is the
    difference between the state before attempt N (after attempt N-1, or the initial state) and the state
    after attempt N. Ignored files are listed by path only, never read for diff content.
13. **Event.** A new event `attempt_diff` (event schema 12, additive; schema 10 is ADR-0023's
    `value_recorded` and 11 is F3.1's workspace events)
    per changed file per captured attempt, emitted after the producer's `node_evidence` and before
    `attempt_finished`. Payload per ADR-0026: path, change kind (`added`, `modified`, `deleted`, `mode`),
    `binary`, `before_sha256`, `after_sha256`, `before_size`, `after_size`, `added_lines`, `deleted_lines`,
    `patch` (unified diff hunks, 3 lines of context), `truncated`, `redacted`, `omitted_reason`
    (`binary`, `too_large`, `ignored`, `budget`, `unreadable`). One summary `attempt_diff` with `path` empty
    carries totals and the count of files omitted by the budget.
14. **Bounds.** At most 16 KiB of patch per event, at most 256 KiB of patch per attempt, at most 4 MiB per
    run. Files over 1 MiB on either side, or detected as binary, carry hashes and sizes but no patch.
    A file beyond a budget is still listed with `omitted_reason: budget`, so absence never reads as "no
    change".
15. **Redaction.** Patch text passes the run's redactor (configured secret values) before it is emitted or
    stored; `redacted: true` marks changed text. Matches across a truncation cut are handled as for logs.
16. **Failure is not a verdict.** A capture failure (Git inspection error, timeout, unsupported entry) emits
    a summary `attempt_diff` with `omitted_reason: unreadable` and a safe diagnostic code, and never changes
    the attempt outcome, the Gate verdict, retry or acceptance.
17. **Diff panel.** For a compare with captured data, the view shows per file: the From attempt's patch,
    the To attempt's patch, and "new in attempt N" / "outside scope" badges from FR5-FR6. For consecutive
    attempts the To patch is already the change from the From attempt's result, and the view says so. For
    non-consecutive attempts the view lists the intermediate attempts' patches for the same file instead of
    composing them. Truncated patches say how much was omitted.
18. **Platform statement.** On a platform where Git inspection is unavailable (see Security / trust), the
    capture emits `omitted_reason: unreadable` with code `E_DIFF_GIT_UNAVAILABLE`; the view says diffs are
    not available on this platform.

## Data / API contracts affected

- **F2.8a:** none. Desktop reducer gains reduction of `node_evidence` (by `attempt_id`) and `attempt_input`
  (feedback linkage) into the existing `Attempt` view model, plus a pure compare model. Event schema 9 and
  the loopback API (ADR-0019) are unchanged.
- **F2.8b:** new event type `attempt_diff` and event schema 12 (ADR-0023's `value_recorded` is schema 10, F3.1's
  workspace events took 11);
  new CLI/serve flag `--record-diffs`; `serve --redact-env`
  (shared with ADR-0023); a desktop setting. No new HTTP route (D4: diffs are inline events).
  Graph schema and CLI envelope versions are unchanged. Stored JSONL logs of older schemas remain readable
  and show "not recorded".

## Failure behavior

- Fewer than two attempts: no entry point; a direct route shows "Nothing to compare" with a way back.
- An attempt referenced by the route does not exist in the run: fall back to the defaults of FR2 and say so.
- Truncated or interrupted store log (ADR-0019): attempts without `attempt_finished` show `interrupted`, not
  `running`, once the run is known to be terminal or interrupted.
- Live stream connection lost while the run was still running: the run status stays `running` (as in the
  rest of the run view), so an unfinished attempt keeps showing `running`, not `interrupted`, until the
  run is reloaded and known to be terminal or interrupted.
- `changed_files_scope` check that could not inspect Git (warn mode, reason
  `changed_files_scope_indeterminate`, evidence reference `state: unavailable`): the verdict is green, but the
  scope row shows "Scope could not be determined", never "All changes within allowed scope".
- `node_evidence` missing for an attempt: "not observed" with the reason (FR3), never zero.
- Feedback reference points to a missing check: FR4 message; the rest of the view still renders.
- F2.8b capture failure, budget exhaustion, binary or oversized file: listed with its `omitted_reason`;
  execution semantics unchanged (FR16).
- F2.8b event with an unknown `omitted_reason` or invalid hashes: the decoder rejects the event as it does
  other invalid payloads; the desktop reducer ignores unknown fields and shows the file as "unreadable".

### F2.8b (after ADR-0026 is accepted)

- [ ] Without `--record-diffs`, no `attempt_diff` event appears in the stream of any demo graph.
- [ ] With `--record-diffs` in a temporary Git repository: attempt 1 modifies `a.txt`, attempt 2 modifies
      `a.txt` again and adds `b.txt`; attempt 2's events contain exactly the attempt-2 changes (not the
      cumulative change since HEAD), and pre-existing dirty files untouched by either attempt are absent.
- [ ] A configured secret written into a changed file by an attempt never appears in any event or in
      `events.jsonl`, including when it straddles the 16 KiB cut; the event has `redacted: true`.
- [ ] A 2 MiB text file and a binary file are listed with hashes, sizes and `omitted_reason` and no patch.
- [ ] Per-attempt and per-run budgets are enforced; files beyond them are listed with
      `omitted_reason: budget` and the summary count equals the number omitted.
- [ ] A changed ignored file is listed by path with `omitted_reason: ignored`, and its content is never
      read (test with an unreadable ignored file).
- [ ] A forced Git failure during capture leaves the attempt outcome, Gate verdict and retry count equal
      to the same run without capture.
- [ ] No configured Git hook, clean/smudge filter, textconv or external diff driver runs during capture
      (test repository with each configured to write a marker file; no marker appears).
- [ ] The compare view shows both attempts' patches for `a.txt` and marks `b.txt` "new in attempt 2".
- [ ] Capture writes nothing into the repository's `.git` (object count, refs and index mtime unchanged)
      and its temporary copies are removed when the run ends.
- [ ] Event streams of schema 1-10 still decode and render "not recorded".

## Required tests

- **Unit (desktop, vitest):** reducer tests for `node_evidence` and `attempt_input` per attempt; compare
  model tests for defaults, swap, missing evidence ("not observed" reasons), new-files set difference,
  scope badge from `changed_files_scope` evidence only, missing feedback reference, interrupted runs.
- **Unit (Go, F2.8b):** snapshot-to-snapshot change set per attempt; patch rendering and line counts;
  binary and size detection; redaction across the cut; budgets and omitted counts; event validation
  (bounds, kinds, hashes, schema gating); decode of old schemas.
- **Integration (Go, F2.8b):** temporary Git repositories covering tracked, staged, untracked, ignored,
  deleted, renamed (old-path deletion plus new-path addition, as in ADR-0016) and mode-only changes,
  pre-existing dirt, two attempts touching the same file, hooks/filters/textconv markers, Git failure with
  unchanged loop semantics; `go test -race ./...`.
- **CLI/e2e:** store a recorded shell-loop demo run and replay it in the desktop e2e (`make desktop-e2e`):
  open Compare from the node panel and assert the side-by-side values. F2.8b adds a run with
  `--record-diffs` and asserts the diff panel. `make check` and `make desktop-check`.

## Security / trust considerations

- Every displayed value is untrusted run data (paths, reasons, evidence, patches). The desktop renders it as
  text, never as HTML, and never follows paths on disk.
- F2.8a adds no new data exposure: it shows what the store already holds.
- F2.8b stores repository content in `events.jsonl`. Contents can include secrets the explicit-list
  redactor does not know (ADR-0023 has the same limit), which is why capture is opt-in and the setting must
  say so. Ignored files (where `.env` usually lives) are never read for content. Store permissions stay
  0700/0600 (ADR-0019); there is still no retention tool (F3.2).
- Capture runs Git with the controlled environment of `gitstate` (no global/system config, hooks disabled,
  fsmonitor disabled, optional locks off) and must not run clean/smudge filters, textconv or external diff
  drivers. It must not write to the user's repository (no objects, refs, index or stash in `.git`).
- Platform: `gitstate` invokes `/usr/bin/git` with `/dev/null` paths. It works on Linux and macOS (where
  `/usr/bin/git` is the Command Line Tools shim) and in WSL; it does not work for a native Windows engine.
  Native Windows capture needs a Git discovery seam, tracked separately (D5 decided: accept the limit). This limit already
  applies to Git-observed changed files and to `changed_files_scope` today.
- Nothing is sent to a remote service; no new listener.

## Observability

- F2.8a emits nothing new; it is a pure reduction of existing events.
- F2.8b: every captured attempt emits at least the summary `attempt_diff`, including on failure, so "not
  captured" and "captured, no changes" are distinguishable in the trace. Capture never writes only to logs.

## Decisions

Decided by the owner on 2026-11-15:

- **D1 - Phasing.** Ship F2.8a (compare of recorded facts, desktop only) first. Decided: yes.
- **D2 - Capture mechanism.** Decided: ADR-0026 option A (engine-rendered bounded patch) for F2.8b.
- **D3 - Default.** Decided: opt-in, off by default, with a switch separate from ADR-0023's value
  recording.
- **D4 - Storage.** Decided: inline bounded events; no new HTTP route.
- **D5 - Native Windows.** Decided: accept "diffs not available" on a native Windows engine; Git discovery
  is tracked separately.
- **D6 - Shell producers.** Decided: Agent producers only.
- **Budgets.** Decided: 16 KiB per event, 256 KiB per attempt, 4 MiB per run, 1 MiB per file.
- **Entry point.** Decided: the current desktop node panel is the entry point for F2.8a. F2.7 (node detail) now
  has a spec and extends the same panel with Activity and Data tabs and a Compare "Task input" row.
- **Schema number.** ADR-0023's `value_recorded` is schema 10 and F3.1's workspace events are schema 11, so
  F2.8b's `attempt_diff` is schema 12 (updated 2026-11-17; earlier drafts said 11).

No open questions remain for F2.8a. F2.8b starts when ADR-0026 is accepted for implementation.

## Out of scope for this iteration

- Cross-run attempt comparison, compare of more than two attempts at once.
- Restoring a workspace to an attempt's state, or exporting a patch to apply.
- Diff capture for non-loop nodes, Gates and Shell producers.
- Retention, deletion or export tooling for captured diffs (F3.2).
- Native Windows Git discovery.
- LLM-based or semantic comparison.
