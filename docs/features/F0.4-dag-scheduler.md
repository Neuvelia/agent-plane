# F0.4 - In-memory DAG scheduler

**Status:** blocked by F0.1-F0.3
**Priority:** P0
**Target phase:** Phase 0 - Execution Core

## Problem

Validated graph definitions need deterministic execution ordering while still allowing independent nodes to run concurrently.

## Goal

Execute a validated DAG in memory, track node/run state, and schedule ready nodes subject to a configurable concurrency limit.

## Functional requirements

1. Node states: pending, ready, running, succeeded, failed, skipped, cancelled.
2. A node becomes ready only when all required dependencies/inputs are satisfied.
3. Independent ready nodes may execute concurrently.
4. A configurable global concurrency limit is enforced.
5. F0 behavior is fail-fast for unhandled node failure.
6. A run reaches exactly one terminal state.
7. Scheduler execution is independent of future cloud/UI packages.
8. Executor behavior is abstracted enough for tests to use deterministic fakes.

## Acceptance criteria

- [ ] Two independent nodes can be proven to overlap in running state using explicit test synchronization.
- [ ] A dependent node never starts before all required upstream nodes succeed.
- [ ] Concurrency limit 1 serializes otherwise independent nodes.
- [ ] Failed upstream work prevents invalid downstream execution.
- [ ] Run terminates deterministically on success and failure.
- [ ] `make check` passes.

## Required tests

- linear graph;
- diamond/parallel graph;
- concurrency limit;
- upstream failure;
- terminal state invariant;
- context cancellation seam if introduced.

## Out of scope for this iteration

- durable recovery;
- retry loops;
- human gates;
- distributed scheduling;
- dynamic graph mutation.
