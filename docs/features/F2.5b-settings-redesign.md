# F2.5b - Settings redesign

**Status:** implemented
**Priority:** P1
**Target phase:** Phase 2 - Local IDE
**Registry:** `docs/roadmap/features.yaml` entry F2.5b (derived from F2.5a)
**ADR:** none required (presentation only; no event, API, persistence or trust-boundary change)

## Problem

Settings was two cards (language and "Record run values") with a Save button.
The design canvas "Tarmind Dashboard UX" draws a full Settings screen
(`Settings.dc.html`, `Settings: Agents` in `Agents.dc.html`) with a section
list, grouped rows, switches and an Agents section. Most of its rows have no
local contract yet.

## Goal

The desktop Settings screen matches the dark design boards: the section list,
group headings and descriptions, rows, segmented controls, switch, stepper,
pills and the Agents cards, with motion for every transition. Rows backed by a
contract work; rows without one are drawn in place, disabled, with a "Soon"
label, and never pretend to save anything.

## Non-goals

- A light theme (F2.5a non-goal; the app has no light tokens).
- New preferences in Electron main or flags for `agentplane serve`: graph
  folder, record file diffs (F2.8b), max concurrency, agent workspace default,
  a path chooser for Codex (F2.14). They are shown disabled with "Soon".
- Paths in the renderer: the run store path and agent program paths are not
  shown (the renderer never receives paths, F2.5/F2.12 grants).
- Secrets (F3.8 UI) and Policy (F3.9): disabled section entries.
- Shortcut sheet, profile menu, trust dialog and storage deletion boards.

## Functional requirements

1. A section list in the design's order: General, Recording, Execution,
   Agents, Engine, Secrets (Soon), Policy (Soon), About. A sliding marker
   follows the active section. General, Recording, Execution and Engine are
   groups of one page: choosing one scrolls to it and rings it once; while
   scrolling, the group nearest the top becomes active. Agents and About are
   panes; the breadcrumb shows `Settings / Agents` or `Settings / About`.
2. General: language (Polski / English) applies immediately; the selected
   segment's thumb slides. Graph folder: Soon.
3. Recording: "Record run values" is a native checkbox drawn as a switch and
   saves at once with the saved variable names (ADR-0023) and leaves a typed,
   unsaved names draft as it is, marked "Not saved yet". The names row saves
   the draft with the saved switch. While a save runs the controls are
   aria-disabled, so keyboard focus stays where it was. Recording state lives
   above the panes: switching panes keeps a save in flight and a draft. Every save reports saved (applies after
   restart), invalid name or failure; the session line reports on, off or off
   because names are unset. The full explanation stays one click away. Record
   file diffs: Soon.
4. Execution: max concurrency shows the engine default (2) in a disabled
   stepper (Soon); retry budget shows the loop default (3 attempts, the first
   one included, for nodes with a loop; `max_attempts` in the graph changes
   it), read only; agent workspace shows Shared, disabled (Soon).
5. Engine: status from the capability report: Connected for any HTTP answer,
   Not connected when the engine cannot be reached, Checking while reading.
   Run store "Show in folder": Soon.
6. Agents: one card per agent row of the F2.11 report (adapters and CLIs),
   known agents in the order Codex, Claude Code, Cursor Agent, Gemini CLI,
   unknown ones after them as received. Each card shows the status word and
   glyph, the version whenever the engine reports one, the reason code as received, the meaning and what still
   works, and a "Check again" button that asks the engine to probe again. An
   available agent lists the three probe checks and when the check ran. Load
   failure and an unreachable engine say so, with Retry.
7. About: app version, engine version and platform, number of stored runs
   (unknown, not 0, when the list cannot be read) and "Copy diagnostics",
   which copies only versions and tool statuses, on click.
8. All motion is CSS and is removed under `prefers-reduced-motion`, including
   pseudo-elements (the switch thumb); scrolling to a group is instant then and
   the group is not ringed.

## Data / API contracts affected

None. Reads `GET /capabilities`, `POST /capabilities/check`, `GET /runs` and
the existing recording preference bridge.

## Failure behavior

A failed recording read shows an error instead of controls. A failed save never
shows "saved". A capability failure shows its HTTP status with Retry; an
unreachable engine shows "Not connected" and Retry. A failed run-list read
shows the count as unknown.

## Security and privacy

No new data leaves the main process. Diagnostics carry versions and statuses
only, no paths, environment or run content, and are copied only on click.

## Acceptance criteria

| Criterion | Text |
| --- | --- |
| F2.5b-AC1 | The section list has the design's eight entries in order; Secrets and Policy are inert "Soon" entries. |
| F2.5b-AC2 | Rows without a backing contract render disabled with "Soon"; the retry budget shows the engine default. |
| F2.5b-AC3 | "Record run values" is a native, labelled checkbox; save results map to saved, invalid and failed, never saved on failure. |
| F2.5b-AC4 | Agents shows only agent rows, in the design's order with unknown agents last, and an available agent lists its probe checks. |
| F2.5b-AC5 | Diagnostics contain versions and statuses only. |

## Validation

`desktop/test/settings.test.tsx`; the switch, draft, focus and invalid-name
path in the real app (`desktop/e2e/demo.cjs`, F2.5b-AC3); stories
`Screens/Settings` rendered by `npm run stories:test` in EN and PL with axe and
no external requests, after each story's play function has finished.
