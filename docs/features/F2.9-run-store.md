# F2.9 - Local run store (minimal, JSONL)

**Status:** implemented (ADR-0019)
**Priority:** P0
**Target phase:** Phase 2 - Local IDE (vertical slice)
**Depends on:** F0.6
**ADR:** ADR-0019 (accepted)

## Problem

Events exist only in memory and on stdout. After a process exits there is no
history, so a UI cannot list past runs and a run cannot be inspected later.

## Goal

Every run is persisted as an append-only event log plus a graph snapshot under
a local directory, and past runs can be listed and read back after restart.

## Non-goals

- SQLite or any index (full F2.9 and F3.2 later), retention, search, filters.
- Resume or recovery of an interrupted run (F3.3).
- Artifact store (F3.5), cloud sync, multi-process locking beyond one writer per run.

## Functional requirements

1. Layout: `<store>/<run_id>/events.jsonl` and `<store>/<run_id>/graph.yaml`
   (byte copy of the graph definition executed). Persistence is opt-in for
   `agentplane run`: it happens only with `--store-dir DIR`, so no run silently
   writes history into the working directory. `runs list/show` default to
   `.agentplane/runs`; the local server (F2.5) always stores. Run IDs are
   runtime-generated UUIDs; only that exact shape is accepted on read and write,
   so path separators and `..` can never name a run.
2. Each retained event is appended as one JSON line exactly as emitted
   (already redacted). Lifecycle facts are `fsync`ed before the emitter returns;
   `log_chunk` and normalized progress are written but synced with the next
   lifecycle fact, so a killed process never loses an acknowledged lifecycle
   fact but may lose trailing log chunks. The stored log equals the in-memory
   retained event list (progress is bounded with an explicit `progress_omitted`
   marker), not an unbounded copy.
3. Persistence is a sink on the existing emitter. It must not change event
   content or ordering and must not block the scheduler beyond the write.
4. `agentplane runs list [--json]` lists runs newest first with run ID,
   graph ID, start time, status and event count. A log without a terminal
   event is reported `interrupted`.
5. `agentplane runs show RUN_ID [--json]` replays the stored events in sequence
   order; `--json` returns the CLI document with the same `events` array as
   `run --json` plus `status`, `graph_id` and `truncated`.
6. A corrupt trailing line is reported as truncation, not a crash; earlier
   events remain readable.
7. The store directory is created with mode 0700 and files 0600. A run
   directory is created exclusively; a second writer for the same run ID fails.
8. If the graph file contains the value of a configured `--redact-env` secret,
   in its raw bytes or in any parsed string value (so YAML escapes, folding and
   unicode escapes cannot hide it), a stored run is refused (exit 3) because
   the byte snapshot would copy it.
9. The reader rejects a log whose first event is not `run_started`, that has
   events after `run_finished`, or that contains an unsupported schema.

## Data / API contracts affected

New persistence format (JSONL of existing event schema), new CLI commands
`runs list` and `runs show`, new `--store-dir` flag on `run`.

## Failure behavior

Unwritable store directory fails preflight (exit 1) before any node executes.
A write error mid-run does not stop `agentplane run`, and the result is still
shown in full; the command exits 1 - even if the run itself failed (4) or was
cancelled (130), because it cannot be trusted to be on disk, while the JSON
`status` still says what the run did - and the error names the run ID and the
partial log directory. In `serve` the run is stopped instead. A run whose log
cannot be read is listed as `corrupt` with the reason, never dropped. Persistence
runs under the collector lock, so a blocked sink blocks the run (pinned by a
test); the fsync scope is process-kill, not power loss.

## Acceptance criteria

- [x] After `run`, the directory holds `events.jsonl` and `graph.yaml`.
- [x] Stored sequence numbers are strictly monotonic and equal the retained emitted stream.
- [x] A separate process lists and shows a finished run identically to the live output.
- [x] A run killed mid-flight lists as `interrupted` and its earlier events read back.
- [x] A truncated final line is reported and does not hide prior events.
- [x] Path traversal in a run ID is rejected.
- [x] No configured secret value appears in any stored file.
- [x] `make check` passes.

## Required tests

- Unit: sink append/fsync ordering, truncated-tail reader, ID validation, permissions.
- Integration: run then read back from a fresh reader.
- CLI/e2e: `runs list/show` after a real run and after a killed run.

## Security / trust considerations

Stored content is whatever the emitter already redacted; the store adds no new
data. Run IDs and paths are untrusted. Directory and file permissions are
owner-only.

## Observability

No new event types. Write failures surface as a structured internal error.

## Open questions

- None blocking.

## Out of scope for this iteration

SQLite, retention, index, resume, artifacts, export CSV.
