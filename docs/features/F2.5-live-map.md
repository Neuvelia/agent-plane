# F2.5 - Live execution map and local API (minimal vertical slice)

**Status:** implemented (ADR-0019); desktop verified by an automated Electron end-to-end run
**Priority:** P0
**Target phase:** Phase 2 - Local IDE (vertical slice)
**Depends on:** F2.9, F2.10
**ADR:** ADR-0019 (accepted)

## Problem

Execution is only observable in a terminal. The product thesis is a debugger
for agent runs: a live graph, per-attempt evidence and an approval inbox.

## Goal

A desktop application (Electron renderer over a Go sidecar) lists stored runs,
shows a live read-only graph of a running or finished run, shows attempts with
reason/evidence/log per node, and lets the user start a run and approve or
reject a waiting human node.

## Non-goals

- Graph editing, drag and drop, edge mapping editor (F2.1-F2.3).
- Hosted web, accounts, runner fleet, mobile approval, settings, docs screens.
- Attempt compare, analytics, packaging/installer (dev mode only).
- The UI implementing scheduling, retry or state rules.

## Functional requirements

1. `agentplane serve` starts a local HTTP API bound to `127.0.0.1` on an
   ephemeral port, prints one JSON line `{"port":N,"token":"..."}` on stdout,
   and exits when stdin closes or on SIGINT/SIGTERM, cancelling active runs.
2. Every request needs `Authorization: Bearer <token>` (32 random bytes,
   constant-time compare) and a `Host` header of `127.0.0.1:<port>`. No CORS
   headers are emitted.
3. Endpoints: `GET /runs`; `GET /runs/{id}` (graph snapshot + status);
   `GET /runs/{id}/events` (replay then live stream, `text/event-stream`);
   `POST /runs` (`{graph_path, inputs}` -> run ID); `POST
   /runs/{id}/decisions/{node_run_id}` (`{decision, comment}`; idempotent,
   409 with the original decision on repeat); `POST /graphs/validate`.
4. Event streams replay stored events from sequence 0 then follow new ones with
   no gaps or duplicates when a client connects mid-run.
5. (API detail) Decision bodies are `{"decision":"approved"|"rejected","comment":"..."}`;
   comments over 2048 bytes are refused with 400. Request bodies are limited to
   64 KiB and unknown JSON fields are rejected. `serve` exits 0 when stdin closes.
6. The renderer derives all node/run/approval state by reducing the event
   stream with a pure function. No node state lives in component state.
7. Screens (from the Tarmind interface design): Dashboard (runs list),
   Run Inspector (graph with node pills, timeline, node panel with attempts,
   reason/evidence and log), Approvals (inbox with Approve/Reject + comment),
   Run Configuration (pick `graph.yaml`, preflight result, Run), a YAML view of
   the run's graph snapshot (a toggle; a side-by-side split is deferred).
8. Electron main spawns the sidecar and is the only process that knows its port
   and token. The renderer reaches the API through a narrow preload bridge
   (`request`, `subscribe`, `pickGraph`); main forwards only `/runs`,
   `/approvals` and `/graphs` paths. *Amended by ADR-0021 (graph editor):* main
   forwards only an exact list of routes, never `/graphs/grants`, and the preload
   also exposes the graph-file calls (`openGraph`, `newGraph`, `recentGraphs`,
   `openRecentGraph`, `touchRecent`, `closeGraph`); `pickGraph`, which returned a path, was removed when
   New run moved to grants (issue #56). `contextIsolation` on, `nodeIntegration`
   off, `sandbox` on, CSP `default-src 'none'` with no network from the page.
9. After restarting the application, a finished run is listed and its
   inspector view is reconstructed from the stored events.

## Data / API contracts affected

New local HTTP API (loopback, bearer token), SSE event stream format, new
`serve` command. Event and graph contracts are unchanged beyond F2.10.

## Failure behavior

If the store cannot be written during a served run, the run is stopped, clients
are not sent events that are not on disk, the stream ends with an `error` event
and the run is listed with an explanatory `error`. When a stream ends for any
reason other than the server's `end` event, the inspector shows "Connection
lost" with a Reconnect button and keeps the last received node states; it never
shows "interrupted" for a connection problem, and decisions are disabled.

Wrong or missing token: 401. Wrong Host: 421. Unknown run: 404. Invalid
graph: 422 with the validator's diagnostics. Sidecar crash: the renderer shows
a connection-lost state and does not invent node status.

## Acceptance criteria

- [x] The API binds only to loopback; a request without the token returns 401 (every endpoint tested).
- [x] A stream opened mid-run yields every event exactly once in sequence order.
- [x] Two parallel branches appear `running` simultaneously in the reduced state of a recorded demo run.
- [x] A red-then-green node shows two attempts with the red reason/evidence.
- [x] Approve through the API behaves as F2.10; a repeated decision returns 409 with the original decision; a decision for another run returns 404.
- [x] Reducer unit tests reconstruct identical state from the stored log and from the live stream.
- [x] After app restart the previous run is listed and viewable.
- [x] Renderer has no direct filesystem or process access.
- [x] `make check` and the renderer test suite pass.

## Required tests

- Unit (Go): token/Host checks, handler status codes, stream replay/follow ordering.
- Unit (TS): event reducer fixtures including retry, human wait, reject.
- Integration: demo scenario through the API against a temporary store.
- Manual: documented checklist in `docs/validation/` for the desktop shell.

## Security / trust considerations

The token is a local capability; never logged or placed in a URL. `graph_path`
is chosen by the signed-in local user and read by the sidecar with the user's
own permissions; the API accepts no remote bind address. A graph executes the
commands it declares, as in the CLI.

## Observability

API decisions are recorded through `approval_decided`. Server errors are
structured JSON with a code and message; no stack traces to the renderer.

## Open questions

- Streaming with `fetch` (not `EventSource`) because EventSource cannot send the Authorization header. Accepted.

## Out of scope for this iteration

Hosted web, editing, installer/signing, auto-update, analytics, runner fleet.
