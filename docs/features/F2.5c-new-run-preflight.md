# F2.5c - New run with preflight (desktop redesign, step 2)

**Status:** implemented
**Priority:** P1
**Target phase:** Phase 2 - Local IDE
**Registry:** `docs/roadmap/features.yaml` entry F2.5c (derived from F2.5)
**Depends on:** F2.5, F2.5a, F2.5b, F2.11 (reads the F3.1 `isolation` setting as written)
**ADR:** ADR-0047 (replaces F2.5a requirement 17; presentation only, no event, API, persistence or trust-boundary change)
**Design source:** Tarmind Dashboard UX canvas, artboard "New run with preflight (target)" (dark). The
light variant is not implemented (light theme stays a non-goal of F2.5a).

## Problem

The F2.5a New run screen is a stepped form: a file picker with a Validate button, a free-text
`key=value` box for inputs and a preflight card that lists diagnostics. The person must know the
graph's input names, validate by hand, and learns about Agent-specific risks (no Codex, the agent
writing into the working tree) only after the run started.

## Goal

Choosing a graph immediately shows what it asks for and what will go wrong before it does. Left:
the graph, one field per declared input, the run options. Right: a preflight that reacts to every
choice, a one-line summary and the one primary action.

## Non-goals

- Any change to the Go sidecar, HTTP API, event schema, run store or Electron preload surface.
- Per-run max concurrency (#209) and per-run Agent workspace (#210): shown disabled, see requirement 6.
- The count of uncommitted files in the preflight (#211); templates and project-folder graphs in the
  graph list (#212, after F2.13).
- Light theme; the page header and Sidebar (F2.5b).
- Any graph rule, input validation or start decision in the renderer.

## Functional requirements

1. Layout: full-bleed under the F2.5b page header; a setup column (32px/40px padding, max 760px,
   32px between groups) and a 380px preflight column with a hairline on its left; below 1000px the
   preflight stacks under the form. Typography, spacing, hairlines, radio, stepper and segmented
   control follow the artboard, mapped onto the existing design tokens. Buttons are the F2.5b canvas
   buttons (flat, 8px radius, one silver primary).
2. **Graph**: a radio list of the recently opened graphs (`recentGraphs()`) plus the file chosen
   with "Choose a graph file…" (the native dialog; the graph is held by grant only, ADR-0021). A
   graph passed from the Inbox ("Open graph") is chosen on arrival. Choosing a graph validates it
   (`POST /graphs/validate` by grant) and opens its document (`POST /graphs/open`); answers for a
   graph that is no longer chosen are dropped and the previous grant is released. The chosen row
   shows "N nodes · kinds" from the engine's definition (kinds as received).
3. **Inputs**: one labelled text field per declared graph input, with "Required/Optional · type ·
   passed to <nodes>" from the definition's `graph_input_bindings`. The run starts with
   `name=value` for each non-empty field. Without a readable definition the group says so.
4. **Preflight rows**, in this order: the graph (engine status, "N errors, M warnings", then every
   diagnostic with code, node, message and suggestion); for a graph with an Agent node, Codex from
   the capability report (`GET /capabilities`, read once; "found" with its version, otherwise the
   F2.11 meaning text); required inputs filled ("k of n"); for a graph with an Agent node, the
   workspace: "Agent writes into your working tree" (warning) unless every Agent node declares
   `isolation: worktree`, then "Agent works in its own worktree" (not a sandbox).
5. Headline and summary: "Choose a graph", "Checking…", "Not checked", "Ready to run",
   "Ready, N warnings" or "Blocked by N errors"; the footer says "N checks passed, M warnings, K
   failed". Only the engine's validation status enables Run (`preflightState`); missing inputs and
   Codex warn and never block, because the engine decides when the run starts. A refused start adds
   "The run did not start" with the engine's message and diagnostics.
6. **Options** (Max concurrency, Agent workspace) are shown as on the artboard but disabled, with
   where the value comes from today (engine start flag; per node in the graph file). The workspace
   switch reflects what the graph file declares. Enabling them is #209 and #210.
7. All text is EN/PL; machine values (file names, node IDs, kinds, types, codes, engine messages)
   are shown as received.

## Data / API contracts affected

None. The screen consumes `POST /graphs/validate`, `POST /graphs/open`, `GET /capabilities`,
`POST /runs` and the preload's `openGraph`, `recentGraphs`, `openRecentGraph`, `closeGraph` as before.

## Failure behavior

- Engine unreachable while checking: the graph row says the graph could not be checked, with the
  error; Run stays disabled.
- Document unreadable (parse error): no input fields; the engine's diagnostics explain why.
- Capability report unavailable: the Codex row warns that it could not be checked.
- Start refused: message and diagnostics in the preflight; nothing else changes.

## Security / privacy

No new data leaves the engine. Paths stay in the main process; the renderer sees grants and file
names. Diagnostics, file names and engine messages are rendered as text only.

## Acceptance criteria

- [x] Inputs, node summary, Agent workspace, preflight rows, tally and headline are pure functions
      tested over recorded engine answers (`desktop/test/new-run.test.tsx`).
- [x] The screen never shows or accepts a path, shows a graph passed from the Inbox as chosen, and
      cannot start before a graph is chosen (`desktop/test/new-run.test.tsx`).
- [x] Stories cover no graph, recent graphs, the artboard (Agent graph, Codex found, input filled,
      shared workspace), Codex not configured, checking Codex, ready, input required/filled,
      warnings, blocked, validating, engine unreachable and start refused, recorded from the real
      engine (`graph-open-fix-issue.json`, `graph-validate-fix-issue.json` added), and pass the story
      smoke in EN and PL with zero axe violations.
- [x] The real-Electron e2e (`desktop/e2e/demo.cjs`) chooses a graph, waits for "Ready to run" and
      starts the run; Open graph on the Inbox lands on New run with the file chosen.
