# F1.2 - First coding-agent adapter

**Status:** draft for review
**Priority:** P0
**Target phase:** Phase 1 - Agent Loop
**Depends on:** F1.1

## Problem

F1.1 proves an Agent node with a mock. It does not prove that a real coding
agent can execute against a repository or that the adapter boundary handles a
real process lifecycle.

## Goal

Execute one installed coding-agent CLI through the F1.1 contract, modify a
temporary Git repository, and report observable result/evidence. Codex CLI is
the initial target in the roadmap; its actual command and output protocol must
be verified against the installed version during implementation planning.

## Non-goals

- A second provider, cloud execution, secrets management, scope enforcement,
  unified event vocabulary, correction loops or workspace isolation.

## Functional requirements

1. Detect absent CLI, installed version and relevant capabilities without a
   provider branch in `internal/runtime`.
2. Pass task, explicit workspace and advisory scope to the CLI. Use structured
   argv/process APIs and an explicit environment; no implicit repository
   upload or full parent environment forwarding.
3. Forward bounded text/status progress through the existing log/event seam
   until F1.3 defines provider-neutral streaming.
4. Derive changed paths from Git in the execution workspace, independently of
   model self-report. Define how pre-existing dirty files are distinguished
   from this invocation's changes. Preserve normalized summary and artifacts
   when the provider supplies them.
5. Make changed paths visible in the run trace with run/node correlation.
   Any new durable event payload requires an ADR before implementation.
6. On context cancellation, terminate the agent process/session and its
   spawned work, wait a bounded interval, then return a cancellation cause.
   Specify platform behavior and timeout in the implementation ADR.
7. Allow CLI users to select the installed adapter through explicit local
   configuration without changing Shell-only graph behavior.

## Data / API contracts affected

F1.1 adapter input/output and Agent config; CLI adapter selection; process
ownership; changed-file result/evidence event. F1.3 owns normalized progress
event types and retention. The trace must not include task text or raw provider
metadata by default.

## Failure behavior

Missing CLI/version detection, unsupported capability, invalid workspace,
process start/exit failure, malformed provider output, Git inspection failure
and cancellation have distinct actionable errors. A failed invocation never
publishes accepted graph outputs. An untracked or dirty baseline must not be
silently presented as an agent-made change.

## Acceptance criteria

- [ ] A hermetic fake CLI changes a file in a temporary Git repository; the
      Agent output and correlated trace show the Git-derived path.
- [ ] A self-reported path absent from Git does not become a changed path.
- [ ] A dirty pre-run file is handled according to the documented baseline
      rule and does not create a false agent change.
- [ ] Missing CLI and bad workspace produce node-scoped errors without panic.
- [ ] Cancellation of a fake CLI with a child process leaves no process owned
      by the invocation running after the bounded shutdown interval.
- [ ] Existing Shell CLI integration tests still pass; no provider-specific
      branch is added to the scheduler.
- [ ] `make check` and `go test -race ./...` pass.

## Required tests

- Unit: detection, version parsing, argv and environment construction,
  changed-path baseline/diff handling, redaction and output parsing.
- Integration: fake CLI in temporary Git repo; missing binary, nonzero exit,
  cancellation with child and baseline dirty file.
- CLI/e2e: one Agent graph runs via explicit adapter selection; Shell graph
  behavior remains unchanged. An optional manual smoke test may use a real
  installed CLI but is not the deterministic acceptance gate.

## Security / trust considerations

CLI output, paths and Git state are untrusted. Never log secrets, private
reasoning or raw task text. `allowed_paths` remains advisory; Git-derived
changed paths are evidence, not yet F1.8 enforcement. Do not silently grant
network or filesystem permissions.

## Observability

Record adapter identity/version when safe, process lifecycle, bounded progress,
correlated changed paths and terminal failure category. Preserve F0.6 event
ordering. Define any new trace event in an ADR.

## Open questions before implementation

- Verify the installed Codex CLI protocol and choose an explicit, supported
  noninteractive invocation mode.
- Specify the Git baseline rule for modified, staged and untracked files and
  the platform-specific process-tree termination contract in an ADR.

## Out of scope for this iteration

F1.3 normalized streaming; F1.4-F1.7 gates and loop; F1.8 enforcement; F3.1
isolated workspaces.
