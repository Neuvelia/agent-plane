# F2.10 - Human node and local approval (minimal)

**Status:** draft
**Priority:** P0
**Target phase:** Phase 2 - Local IDE (vertical slice)
**Depends on:** F0.4, F0.6, F1.5
**ADR:** ADR-0017 (proposed)

## Problem

The graph can only fail or succeed on deterministic evidence. A consequential
step (for example applying an accepted change) has no way to stop the run and
wait for an explicit human decision, and no auditable record of that decision.

## Goal

A `human` node pauses its branch in a visible `waiting_human` state until a
local approve or reject decision arrives, emits both facts as events, and lets
the rest of the graph continue or stop deterministically.

## Non-goals

- Blast-radius scoring, reviewer roles, multiple approvers, approval expiry.
- Web/hosted approval (F4.8), push notifications, identity of the approver.
- Reject routed to an alternative path (this iteration: reject fails the node).
- Approval timeouts (the wait ends only by decision or run cancellation).
- Resume of a waiting run after process death (F3.3).

## Functional requirements

1. Node `type: human` is valid in graph schema 0. Optional `config.prompt`
   (string, max 1024 bytes, shown to the approver). Optional declared string
   inputs are carried into the approval request as bounded context.
2. A `human` node declares output port `decision` (string). On approve it
   publishes `decision: "approved"` as its accepted output; downstream nodes
   depend on it through an ordinary data binding. No ordering-only edge is added.
3. When all dependencies are accepted the node enters `waiting_human`, emits
   `approval_requested` and does not consume a concurrency slot while waiting.
   Independent branches keep running.
4. A decision `{approve|reject, comment?}` (comment max 2048 bytes) is
   delivered through a runtime `DecisionProvider` seam. The first decision for
   a given node run wins; any later decision is rejected without effect
   (idempotent, returns the original decision).
5. Approve: emit `approval_decided`, node `succeeded`. Reject: emit
   `approval_decided`, node `failed` with failure kind `rejected` and safe code
   `human_rejected`; dependents are skipped; run fails; CLI exit 4.
6. Cancellation while waiting ends the node `cancelled`, emits no decision
   event, and does not hang the run.
7. CLI provider for tests and terminals: interactive stdin prompt when stdin is
   a TTY, and explicit `--approve NODE` / `--reject NODE` flags for
   deterministic tests. Without a provider a graph containing a `human` node
   fails preflight with an actionable error instead of waiting forever.

## Data / API contracts affected

Graph node type `human`; runtime node state `waiting_human`; new event types
`approval_requested` and `approval_decided` (event schema 9, additive; decode
of schemas 1-8 unchanged); runtime `DecisionProvider` interface; CLI flags.

## Failure behavior

- `human` node without a path to a decision provider: preflight error naming
  the node.
- Comment over limit or unknown decision value: decision refused, node keeps
  waiting, no event emitted.
- Decision for an unknown or already-decided node run: refused, no state change.

## Acceptance criteria

- [ ] A graph with `human` is valid; a missing provider fails preflight, exit 3 or 4 as documented, naming the node.
- [ ] The node reports `waiting_human` and an `approval_requested` event before any decision exists.
- [ ] Independent branches complete while another branch is `waiting_human`.
- [ ] Approve publishes `decision: "approved"` and downstream runs exactly once.
- [ ] Reject fails the node with code `human_rejected`, skips dependents, exit 4.
- [ ] A duplicate decision for the same node run changes nothing and emits no second `approval_decided`.
- [ ] Cancellation while waiting terminates the run without leaked goroutines.
- [ ] Events carry run/node-run IDs, bounded prompt/comment, and no secrets.
- [ ] Schema 1-8 event streams still decode.
- [ ] `make check` passes.

## Required tests

- Unit: decision validation, idempotency, state transitions.
- Integration: parallel branch completes during wait (explicit barrier, no sleeps), approve, reject, cancel.
- CLI/e2e: `--approve` and `--reject` flags, preflight failure without provider.

## Security / trust considerations

Prompt, inputs and comment are untrusted text: bound, redact configured
secrets, never interpret. A decision does not widen filesystem or process
permissions. The local API (ADR-0019) must authenticate decisions.

## Observability

`approval_requested` (prompt, bounded context, node run ID) and
`approval_decided` (decision, comment, node run ID, timestamp) are append-only
facts with sequence numbers.

## Open questions

- None blocking. Reject-to-alternate-path is deferred explicitly.

## Out of scope for this iteration

Roles, expiry, blast radius, web approval, resume, notification.
