# F0.2 - Graph Validator and lint

**Status:** implemented
**Priority:** P0
**Target phase:** Phase 0 - Execution Core

## Problem

A parseable graph may still be impossible or unsafe to execute because references are missing, ports are invalid, types do not match, or the graph contains a cycle.

## Goal

Provide deterministic semantic validation before execution and return diagnostics suitable for both CLI and future UI presentation.

## Non-goals

- No auto-fix.
- No LLM-based linting.
- No runtime execution.
- No advanced optimization suggestions.

## Functional requirements

1. Validate required graph fields and stable IDs.
2. Validate source/target node references.
3. Validate source output and target input references.
4. Validate basic port type compatibility.
5. Detect cycles.
6. Detect required node inputs with no graph input binding, edge, or allowed default.
7. Return multiple independent diagnostics in one validation pass where practical.
8. Distinguish blocking errors from non-blocking warnings.

## Diagnostic contract

A diagnostic should be able to carry:

```text
severity
code
message
graph_id
node_id optional
edge index/id optional
source location optional when available
suggestion optional
```

## Acceptance criteria

- [x] Valid Phase 0 example graph returns no blocking diagnostics.
- [x] Missing node reference is reported with the offending reference.
- [x] Missing port reference is reported with node and port context.
- [x] A cycle causes blocking validation failure and identifies nodes in the cycle.
- [x] Incompatible bound port types are rejected.
- [x] Independent errors can be returned together rather than only first-error behavior where implementation cost is reasonable.
- [x] Validator behavior is deterministic.
- [x] An edge whose target node does not read the delivered input (for example a Shell input with no
  `input_env` entry) yields the non-blocking warning `W_EDGE_INPUT_UNUSED` on that edge; inputs read by
  configuration or a loop binding, and a human `decision` edge (ADR-0017), do not (#180, see
  `docs/graph-spec.md` "Warnings").
- [x] `make check` passes.

## Required tests

- valid graph;
- missing node;
- missing input;
- missing output;
- incompatible types;
- simple two-node cycle;
- longer cycle;
- multiple independent validation errors.

## Security / trust considerations

Validation must remain pure with respect to graph content: no command execution, file reads outside the provided graph source, environment expansion, or network access.

## Observability

No runtime events yet. Diagnostics are the evidence contract.

## Out of scope for this iteration

- possible parallelism suggestions;
- unreachable-node optimization;
- automatic graph rewriting;
- policy enforcement.
