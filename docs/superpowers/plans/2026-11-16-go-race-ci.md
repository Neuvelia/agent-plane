# Go Race CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the full Go race suite an independent push/PR CI result.

**Architecture:** Add one Go job to the existing workflow and update the
development gate description. Leave product code and existing jobs alone.

**Tech Stack:** GitHub Actions, Go 1.23 from `go.mod`, existing tests.

**Spec:** `docs/superpowers/specs/2026-11-16-go-race-ci-design.md`.

## Global Constraints

- Keep existing `push` and `pull_request` triggers and Go/desktop jobs.
- No secrets, `pull_request_target`, third-party test dependency or product
  code change.
- Checkout in the new job must not persist credentials.

## Review Focus

- Exact command and independent job status versus existing Go check/build.
- Go setup/cache correctness on Ubuntu and race-detector prerequisites.
- CI cost and honest limits of test coverage.
- Read-only fork-PR execution boundary.

`docs/development-workflow.md`; create this design/plan pair.

**Interface:** A CI job named `race` reports `go test -race ./...` on pushes
