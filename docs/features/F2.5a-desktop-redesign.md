# F2.5a - Desktop interface redesign (Tarmind design, local subset)

**Status:** implemented (R0-R3 merged: #26, #27, #28, #29); approved by the product owner 2026-11-14
**Priority:** P0
**Target phase:** Phase 2 - Local IDE (vertical slice)
**Depends on:** F2.5, F2.9, F2.10
**ADR:** none required (presentation only; no event, API, persistence or trust-boundary change)
**Plan:** `docs/superpowers/plans/2026-11-14-desktop-ui-redesign.md`

## Problem

The F2.5 desktop shell proves the contracts but is a visual sketch: system font, flat panels, a
table-only run list, no shared components, no derived run insight (timing, retries, event log) and English
only. The Tarmind interface design (canvas "UX-IA-1.0 R1" and its design system) defines the intended look
and information architecture, but much of it is cloud-first and cannot be backed by local contracts.

## Goal

The desktop renderer implements the local subset of the Tarmind design on top of the unchanged F2.5 API:
a token-based design system, a global-bar and Sidebar shell, redesigned Dashboard, Run Inspector, Approvals and
New run screens, insight derived purely from events and API lists, and a Polish/English interface.

## Non-goals

- Any change to the Go sidecar, HTTP API, event schema, run store or Electron preload surface.
- Graph editing (F2.1-F2.4), attempt compare (F2.8), onboarding (F2.11).
- Projects, Workspaces, Runners, Docs, hosted/mobile approval, accounts, sync, notifications,
  global search, environment switcher. Projects, Runners and Docs appear only as disabled navigation
  entries. Settings is a real screen but holds only the interface language (execution policy, effective
  configuration and privacy/sync are later features).
- Cancel run, rerun failed, export, blast radius, token usage (no backing contract).
- Visual-regression screenshot tooling, hosted/published Storybook, Storybook docs pages.
- Light theme, user-selectable accent, installer/packaging. (The light theme and the profile menu
  were added later by F2.5c, ADR-0047.)
- UI-owned scheduling, retry or state rules.

## Functional requirements

### Design foundation (R0)

1. A committed `desktop/src/design/tokens.css` defines the colour, type, spacing, radius, size and shadow
   tokens of the design system (dark theme only). Components reference tokens, not literal values.
2. Geist and Geist Mono are bundled as local font files with their licence; no font is requested over the
   network. The fallback stack is `ui-sans-serif, system-ui, sans-serif` / `ui-monospace, monospace`. The
   bundled subset renders Polish diacritics.
3. Shared primitives in `desktop/src/ui/`: Card (with header), Pill (tones neutral, brand, ok, bad, warn),
   Tag, Button (default, primary, danger; sizes), SegmentedControl, HelpTip, KPI, list row, Field,
   CodeView, EventLog, DotChart, DotTimeline, Sidebar, IconRail, TopBar, and an inline SVG icon set. Icons
   are inline SVG, no icon font.
4. *(Sidebar layout and the profile position superseded by F2.5b / ADR-0046.)* Shell: a full-width expanded Sidebar (224px) on every screen, full window height; the Sidebar
   never collapses (product-owner decision; the IconRail component exists but no screen uses it). The
   Tarmind logo and name sit at the very top of the Sidebar, right-aligned. A bar above the page content
   shows the connection indicator and a profile avatar at the right. The avatar shows hard-coded initials ("KW") until accounts exist; it is not interactive. (F2.5c, ADR-0047: the profile row in the sidebar foot opens the profile menu.)
   Sidebar entries: Dashboard (the landing screen), Runs (the full list), Approvals (pending count badge), New run; then Projects, Runners and Docs
   (disabled); Settings last (enabled).
5. A disabled navigation entry has `aria-disabled="true"`, is not a link or tab stop, shows a localised
   "Soon" tag, performs no navigation and no request.
6. The global bar's connection indicator (connected / connection lost) comes from existing stream/request
   state. A breadcrumb (a `nav` landmark; the global bar is the page's only `banner`) sits above the page
   content. The language switch is not in the bars; it lives in Settings.
6h. macOS: the window has no native title bar (`titleBarStyle: 'hidden'` on darwin, black background), so
    the window is black edge to edge. The global bar and the Sidebar's brand strip are the drag area; the
    traffic lights sit in the Sidebar's top-left corner, which the right-aligned brand leaves free, and
    controls stay clickable. Other platforms keep the native frame.

### Storybook (R0, extended in every phase)

6a. Storybook (React + Vite builder) is added to `desktop/` as a **development-only** tool to build and
    review the UI without Electron or the sidecar. Scripts: `npm run storybook` (dev server, loopback only)
    and `npm run build-storybook` (static build). Storybook is never part of the packaged app or the
    renderer bundle.
6b. Every primitive in requirement 3 has stories covering its states (default, hover-independent variants,
    disabled, long Polish text, empty).
6c. Screens have stories per state, not only components: Dashboard (empty, busy, needs attention),
    Run Inspector (running, waiting for human, failed after retries, succeeded, connection lost, run not
    found), Approvals (empty, one pending, many pending, decision error), New run (no file, ready, warnings,
    blocked). Screen stories drive the real components, reducer and selectors from recorded event fixtures
    (`desktop/test/fixtures`, plus new fixtures for states the demo does not produce), never hand-written
    node state.
6d. A story decorator installs an in-memory stub of `window.agentplane` (`request`, `subscribe`,
    the graph-file calls) that replays fixtures. Stories make no network request and never start or contact a
    sidecar.
6e. A toolbar global switches language (en/pl) and a second one switches viewport width; the language
    switch uses the same i18n provider as the app.
6f. The accessibility addon (axe) runs on every story; violations fail the story test run.
6g. `npm run check` additionally runs `build-storybook` (with telemetry disabled) so a broken story breaks
    the check, as OpenBot does in CI. Visual-regression screenshot comparison is out of scope.

### Localisation (R0)

7. Two typed message catalogues (`en`, `pl`) with an identical key set. A `t(key, params)` function
   resolves messages; plural forms use `Intl.PluralRules` for the active locale. No i18n dependency.
8. Initial language is the system locale if it is `pl` or `en`, otherwise `en`. The user can switch in
   Settings; the choice persists in renderer `localStorage` and applies without restart. Dates, times and
   numbers are formatted with `Intl` for the active locale.
9. Machine values are never translated: event types, node ids, run ids, paths, commands, YAML, check ids,
   diagnostic codes. Diagnostic `message`/`suggestion` text from the sidecar is shown as received.
10. Sentences are parameterised messages, never concatenated fragments.

### Screens (R1, R2)

11. *(Superseded by F2.5b / ADR-0046: the Inbox triage queue is the landing screen.)* **Dashboard** (replaces the runs table as the landing screen) shows: *Needs attention* (pending
    approvals plus runs whose status is `failed` or `interrupted`, newest first, at most 5 with "Show more"),
    *Active runs* (runs with status `running`), *Outcomes* (one dot per run for the last 7 days, coloured by
    status, empty slots visible), and *Quick actions* (New run, Open graph YAML via the New run picker). A
    full runs list remains reachable from the Sidebar.
12. **Run Inspector** keeps the live map, node panel, attempts, check reason/evidence, log, YAML view and
    connection-lost banner with Reconnect. Added: header with status pill, graph id, failure kind, live
    marker and event count; KPI row; DotTimeline; EventLog with All / Failed / Retried / Human filters;
    attempt SegmentedControl; Visual / YAML / Split switch (Split = map beside read-only YAML).
13. **KPIs** are computed by pure functions over the reduced run view: wall clock (`startedAt` to
    `finishedAt`, or to the last event while running), node time (sum of node durations), time saved
    (node time minus wall clock, never negative), retries (count of correction attempts). Tokens always
    shows "unknown" because events carry no usage. A missing value renders as unknown, never `0`.
14. **DotTimeline** has one dot per second of wall clock, per node row; a second is filled when the node
    was active in it. It is capped at 600 columns; longer runs are bucketed and the bucket size is shown.
15. **EventLog** shows the most recent 200 events (sequence, time, type, node, short detail), newest first.
    `log_chunk` events are not rows (node output has its own Log view) but still count toward the event
    total. The filters are decided from the event itself: Failed (red gate check, failed node or run),
    Retried (attempt number above 1, rejected attempt) and Human (approval requested or decided). Machine
    names are rendered literally in mono; unknown event types are listed by name with no filter kind.
16. **Approvals** is a two-pane inbox/review: pending approvals on the left; on the right the prompt,
    context items, comment (max 2048 bytes, as today), Reject (danger) and Approve (primary). The decision
    is shown as applied only when the `approval_decided` event arrives; a 409 is treated as already decided,
    as today. Buttons are disabled while the stream is lost.
17. *(Superseded by F2.5e / ADR-0049: New run with a live preflight.)* **New run** is a stepped form: graph file (choose / type path, Validate), inputs (`key=value` lines),
    preflight (one row per diagnostic with code, message, node, suggestion; overall `Ready`, `Warnings` or
    `Blocked`), Start run (primary, disabled unless the graph is valid). Preflight covers graph validation
    only; no runner, capability or secret rows.
18. Status wording follows the design vocabulary and is localised: run (Running, Succeeded, Failed,
    Cancelled, Interrupted), node (Pending, Running, Retrying n/m, Human, Succeeded, Failed, Skipped),
    gate (Green, Red, Unknown), approval (Pending, Approved, Rejected). Status is never colour-only.

### Polish (R3)

19. All interactive elements are native `button`/`input`/`a`; icon-only buttons have `aria-label`; keyboard
    focus shows the 2px focus outline (solid `brand`, see `overrides.css`); the Sidebar, segmented controls,
    list rows and the runs table are keyboard operable (a table row is opened by a real button that stretches
    over the row). The first Tab stop is a "Skip to content" link, and after navigating, focus moves to the
    page content.
20. Motion (colour transitions, tooltip fade, the flowing-edge animation) is removed under
    `prefers-reduced-motion`.
21. Empty, loading, error and connection-lost states exist for every screen that reads from the engine and
    use the same components (`StateMessage`). A failed list read (sidecar not running, non-200 answer) is an
    error state with Retry, never an empty list, and stale data is not shown as current. Any screen that
    cannot reach the engine makes the global bar say "Connection lost". UI text produced by the app itself,
    including the stream-lost explanation, is localised; engine diagnostics are shown as received.

## Data / API contracts affected

None. The renderer reads the existing `GET /runs`, `GET /runs/{id}`, `GET /runs/{id}/events`,
`GET /approvals`, `POST /runs`, `POST /runs/{id}/decisions/{node_run_id}` and `POST /graphs/validate`
through the unchanged preload bridge (`request`, `subscribe`, the graph-file calls). Event schema 9 is unchanged.
The reducer remains the only source of node/run/approval state; new derived values are pure selectors in
separate modules that take a `RunView` or a run list.

There is no security-relevant configuration change: the renderer CSP (in `index.html`) already contains
`font-src 'self'`, which is what bundled fonts need. `default-src 'none'`, no network access from the page
and the forwarded path allowlist (`/runs`, `/approvals`, `/graphs`) are unchanged.

## Failure behavior

- Sidecar unreachable or stream ended abnormally: connection indicator shows lost, the inspector keeps the
  last received node states under the existing banner, decisions are disabled, and derived values (KPIs,
  timeline) are labelled as of the last event, never extrapolated.
- A run with missing durations or timestamps renders unknown values as unknown.
- A malformed or unknown event type does not break derived views; it is shown in the EventLog by its type
  and ignored by selectors.
- A missing translation key in a development build fails the key-parity test; at runtime it falls back to
  the English message and, if absent, to the key.
- `localStorage` unavailable: language falls back to the system locale for the session without an error.
- A very long run: EventLog, DotTimeline and logs stay bounded (requirements 14, 15; the node log cap is
  unchanged), so rendering cost does not grow with run length.

- Storybook: story index completeness, smoke/a11y run of all stories (EN/PL), bundle-scan test.
- Component: Pill/Sidebar disabled entries, SegmentedControl keyboard use, DotChart slot count, EventLog

- Integration/e2e (`desktop/e2e/demo.cjs`, real Electron and sidecar under xvfb): navigation, the demo

- Manual: update `docs/validation/F2.5-desktop-demo.md` with a per-screen visual checklist in both
  languages.

## Security / trust considerations

- Untrusted inputs shown in the UI: graph paths, node ids, prompts, approval context, diagnostic text,
  logs and evidence. They are rendered as text, never as HTML; no `dangerouslySetInnerHTML`.
- The preload surface, token handling and path allowlist are not widened. The token and port never reach
  the renderer or the DOM, logs or screenshots.
- Fonts are local assets; no remote fonts, scripts or images.
- Comments entered in the approval form are sent only through the existing decision endpoint.
- Localised copy must not embed secrets or file contents; context values are shown as received.

## Observability

No new events. The UI is an observer: every number it shows is derivable from the event stream or the API
lists. Derived values are labelled as computed from events and carry no authority over run state.

## Open questions

- Polish copy for all catalogue entries needs product-owner review before release.
- Exact source of the committed design tokens (script versus manual export of the design system) to be
  settled in R0; the parity test makes drift visible either way.
- Storybook and addon versions are chosen at implementation time (current stable, pinned) and justified
  in the PR per the dependency policy: development-only, not shipped, telemetry off, no network at runtime.
- Whether Dashboard "Active runs" should show the latest event type: needs a run-summary enrichment
  (`last_event_type`) that is outside this feature; until then it shows status and elapsed time only.

## Out of scope for this iteration

- Visual graph editor, node inspector and edge-mapping editor (F2.1-F2.4).
- Attempt compare (F2.8), onboarding (F2.11), templates (F2.12).
- Cancel/rerun/export, blast radius, token usage, handled-approvals history, graph library listing; each
  needs its own contract.
- Projects, workspaces, runners, settings, docs, hosted web, mobile approval, accounts, sync.
