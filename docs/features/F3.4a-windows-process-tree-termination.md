# F3.4a - Windows Process-Tree Termination

**Status:** draft (spec only; no implementation yet)
**Priority:** P0 (Windows is supported in the first release; owner decision)
**Target phase:** Phase 3 - Local Production Ready
**Depends on:** F3.4 (termination contract), issue #87 (Windows test failures)
**ADR:** ADR-0028 (proposed; same ADR as F3.4: Job Objects as the Windows
process-ownership model)

Product name: Tarmind (in code today: agentplane).

## Problem

On Windows today:

- The Codex adapter rejects the platform (`internal/agent/codex/process_other.go`,
  `unsupported_platform`).
- The Shell executor kills only the direct child, so descendants survive.
  Cancelling an already exited child fails with "TerminateProcess: Access is
  denied"; `execute` reports an exit failure, so the CLI exits 4 instead of 130
  (`docs/development-workflow.md`, "CI matrix"). The executor carries a
  `runtime.GOOS == "windows"` special case for this.
- The command Gate needs `/usr/bin/diff` and `/dev/fd/3`
  (`internal/gate/command.go`); evidence code runs `/usr/bin/git`
  (`internal/gitstate/snapshot.go`, `internal/runtime/workspace.go`).
- `check (windows-x64)` is `experimental`, so regressions are invisible.

## Goal

On Windows, cancel and timeout of a Shell, Codex or Gate-owned process end the
whole process tree with the same F3.4 guarantees as Unix, and the Windows CI job
becomes a blocking check.

## Non-goals

Sandboxing (a Job Object here controls lifetime only), Windows on Arm and
Windows before 10 / Server 2019, WSL (treated as Linux), the desktop shell
(issue #23), resume (F3.3).

## Functional requirements

### Ownership: Job Objects

- Each owned child is placed in a Job Object created with
  `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and without breakaway permission, so
  descendants inherit membership and cannot leave. Terminating or closing the
  job kills the whole tree.
- KILL_ON_JOB_CLOSE also makes the OS reap the tree when the runner crashes, so
  Windows gets crash-orphan safety without F3.2.
- Nested jobs are required (CI runners and some terminals already run us inside
  a job); the supported floor guarantees them.
- **Assignment race.** A child must not spawn before it is in the job. A short
  spike picks between (a) `CREATE_SUSPENDED`, assign, resume the primary
  thread, and (b) `PROC_THREAD_ATTRIBUTE_JOB_LIST` at creation. Test W2 decides.

### Graceful request, then force

- Start with `CREATE_NEW_PROCESS_GROUP`; request exit with
  `GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT, group)`, scoped to our group only.
  This needs a console. With no console (desktop sidecar, service) or on error,
  skip to force after a short fixed wait. Graceful is best effort on Windows;
  forced termination is guaranteed.
- `SIGTERM` is never delivered on Windows and `signal.NotifyContext` there reacts
  to `os.Interrupt` only; the `syscall.SIGTERM` in `cmd/agentplane/main.go`
  stays harmless and is not a Windows cancel path.
- Force: `TerminateJobObject` with a fixed exit code that is never used for
  classification; wait for the leader; poll `ActiveProcesses == 0`
  (`JOBOBJECT_BASIC_ACCOUNTING_INFORMATION`) within the F3.4 verify bound.
- Classification follows F3.4 rule 7 (our own record), which removes the exit 4
  versus 130 discrepancy and the Windows special case.

### Code changes

1. Shared termination helper with `_unix` and `_windows` files behind one
   contract; no `runtime.GOOS` branches in node code. Windows uses
   `golang.org/x/sys/windows` because stdlib `syscall` has no Job Object API. It
   is already an indirect module (via `x/term`) and becomes direct: no new
   module, runtime dependency, affects the Windows build only.
2. `internal/shell`: use the helper; idempotent cancel; drop the Windows special
   case.
3. `internal/agent/codex`: Windows `runProcess` replaces `process_other.go`;
   remove the Darwin/Linux-only guard in `adapter.go` after proof W6 and W8.
4. `internal/gate/command.go`: Windows has neither `/usr/bin/diff` nor
   `/dev/fd/3`. Recommended (Q1): compare the two already opened regular files
   in-process with bounded reads on Windows, emitting green/red with
   `files match`/`files differ` and no diff text. This is deterministic code
   (AGENTS.md rule 3) and removes a child process there; Unix evidence is
   unchanged. If evidence parity is required instead, the command Gate stays
   unsupported on Windows and F3.4a does not depend on it.
5. Prerequisite owned by its own issue: resolve `git` through `exec.LookPath`
   instead of `/usr/bin/git`, otherwise Codex evidence cannot work on Windows.
6. `cmd/agentplane`: no platform-specific exit codes; confirm Ctrl+C maps to
   `cancelled`/130 through the shared classification.

## Acceptance criteria (tests that count)

All run on the `check (windows-x64)` runner, use a helper built from the test
binary (no `/bin/sh`, no Unix tools) and explicit synchronization (ready file or
pipe), never sleeps.

- [ ] W1 tree kill: a Shell node starts a grandchild that writes a ready marker;
  cancel; both processes are gone within the bound. Red on `main` today.
- [ ] W2 startup race: a child whose first action is spawning a grandchild is
  killed with its descendants, 200 iterations.
- [ ] W3 idempotence: cancelling an already exited child gives `cancelled`, not an
  exit failure, and CLI exit 130. Red on `main` today.
- [ ] W4 runner crash: killing the runner closes the job and the child tree dies.
- [ ] W5 no console: a runner started detached still force-terminates within
  grace plus the verify bound.
- [ ] W6 Codex fake CLI: the Windows adapter mirrors `process_test.go` (no process
  left after cancel; a successful leader with an inherited pipe is bounded).
- [ ] W7 nested job: W1-W3 also pass when the test process is first placed in a
  Job Object.
- [ ] W8 real Codex smoke on a Windows host, recorded in the PR (manual, not CI).
- [ ] F3.4 timeout criteria of layer P pass on Windows.

### Removing `experimental` from `check (windows-x64)`

`experimental: true` and `continue-on-error` may be removed only when:

1. `main` passes the full Windows job three consecutive times, with the issue
   #87 failures fixed by code or by guards that state a reason (file modes, 8.3
   short paths, verifychanges cases), not by deleting tests;
2. W1-W7 are in the job and pass (W8 is a manual check recorded in the PR and does not gate CI), and no Windows skip remains for process
   lifecycle; remaining skips are listed in `docs/development-workflow.md` with
   their owning feature;
3. `go test -race` runs for `internal/shell`, the helper and
   `internal/agent/codex` on Windows, or Q2 records the accepted alternative;
4. a hung test is still capped by the job timeout.

The flag change is its own commit in the PR that completes 1-3.

## Failure behavior

Job creation or assignment failure: the node fails `start` with the Win32
error; the child is not left running. A tree that will not empty returns the
F3.4 `shutdown` error with the leaked count.

## Security / trust considerations

The job handle is the only authority used to terminate; no PID lookup.
`CTRL_BREAK_EVENT` is limited to our own process group. No breakaway means a
child cannot detach from lifetime control; this is not confinement.

## Risks

- Assignment race and nested jobs (spike first; W2, W7).
- `GenerateConsoleCtrlEvent` shares console state; mitigated by group scoping
  and the force fallback.
- Antivirus or EDR hooks may delay termination: the verify bound is reported
  with `elapsed_ms`, not widened silently.

## Open questions (recommended defaults)

1. Windows command Gate without diff text? Default: yes, in-process compare.
2. Race detector on the Windows job (needs cgo and a C toolchain)? Default: run
   it for the three packages if the runner supports it; otherwise keep Linux race
   coverage and require W1-W7 without `-race` on Windows.
3. Fixed wait before force when graceful is unavailable? Default 500 ms.

## Out of scope for this iteration

Sandboxing, Windows Arm and pre-Windows-10, desktop sidecar console handling
(issue #23), Windows `git` path resolution (own issue).
