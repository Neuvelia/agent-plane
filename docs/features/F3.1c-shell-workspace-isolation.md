# F3.1c - Workspace isolation for Shell nodes

**Status:** draft (ADR-0034 proposed; not implemented)
**Priority:** P0 as a remaining part of roadmap F3.1 scope
**Target phase:** Phase 3 - Local Production Ready
**Depends on:** F3.1 (ADR-0024), F1.6a (Shell loop, ADR-0018), F1.7 (units, accept-once)
**ADR:** ADR-0034 (proposed)
**Closes:** issue #189; replaces the unnamed deferrals in F3.1 Q4 and ADR-0024 decision 5

## Problem

`isolation: worktree` exists only for loop Agent nodes in `units`. Shell producers, including Shell correction
loops, still write into the shared checkout, so parallel siblings and retries can overwrite each other.

## Goal

A loop-enabled Shell producer listed in `units` can opt into `isolation: worktree` and gets the ADR-0024
guarantees: no filesystem race with siblings, rejected attempts never reach the integrated ref, deterministic
integration, conflicts reported as evidence.

## Non-goals

- Isolating standalone Shell, Gate or Human nodes.
- Downstream visibility of integrated files (F3.1b).
- Sandboxing: absolute paths in `command`/`args` escape; confinement is F3.9.
- Windows (same as F3.1).
- Applying results to the user's branch.

## Functional requirements

1. `config.isolation: none|worktree` accepted on Shell nodes (descriptor and validation); valid only for a
   loop-enabled Shell node in `units`, otherwise preflight fails before `run_started` naming the node.
2. Lifecycle, base commit, dirty-source refusal, hygiene, delivery refs, integration and conflict behavior are
   those of ADR-0024, unchanged.
3. `cwd` mapping: resolved against the source repository root, must be inside it, remapped to the same relative
   path inside the node's worktree; outside the repository or missing mapped directory fails preflight.
4. The embedded Gate of an isolated Shell loop evaluates the node worktree.
5. Scheduling: the worktree is the node's effective workspace identity; no new scheduler rule.
6. Descriptors and the F2.2 inspector expose the field for Shell nodes through the generated registry.

## Data / API contracts affected

Shell field registry gains `isolation`; no graph schema bump proposed (`config` is per type). Existing isolation
events are reused; if a node-type field must be added it uses the next event schema number from its owner.

## Failure behavior

Isolation on an ineligible Shell node, `cwd` outside the repository, dirty source, unsupported Git: preflight
error, no events. Conflict: `needs_intervention`, exit 4, unit worktree retained, as ADR-0024.

## Acceptance criteria

- [ ] A graph without Shell `isolation` has identical hash, events and CLI output to before.
- [ ] `isolation: worktree` on a standalone Shell node, or one not in `units`, fails preflight naming the node.
- [ ] Two parallel isolated Shell producers writing the same relative file both succeed with no race; the
      integrated ref reports the clean merge or a conflict with sorted paths.
- [ ] A rejected Shell attempt's files are absent from the integrated ref and the source checkout (asserted on the filesystem).
- [ ] A relative `cwd` of `sub/dir` runs in `<worktree>/sub/dir`; a `cwd` outside the repository fails preflight.
- [ ] The source checkout, index and branch are untouched after a run (same assertion as ADR-0024).
- [ ] A Shell correction loop retries in the same worktree across attempts (F1.6 semantics).
- [ ] The embedded Gate observes the worktree, not the source.
- [ ] Documented non-sandbox test: an absolute-path write escapes and is reported by F1.8 only where Git evidence applies.
- [ ] Linux and macOS only; Windows fails preflight with the existing platform message.
- [ ] `go test -race` passes for every package touched, with the existing Windows/git failures unchanged from baseline.

## Required tests

- Unit: eligibility rule, cwd mapping table.
- Integration: disposable repository, parallel producers, conflict, rejected attempt.
- CLI/e2e: exit 4 on conflict.

## Security / trust considerations

Same Git hygiene as ADR-0024 (no hooks, unknown filter drivers rejected). A worktree is not a permission boundary.

## Observability

Existing isolation events and refs; the node type appears in evidence.

## Open questions

- Confirm Shell loop producers can be enrolled in `units` today (ADR-0018); if not, enrolling them is part of this feature.
- Whether `workspaces list` ships here (see F3.1 Q5).
- F3.9 (ADR-0029, accepted) Open question 1 says that if the Landlock spike fails, enforce mode rejects Shell `paths.write` on Linux because Shell nodes have no isolation-style containment. F3.1c would provide that containment (`contained` state) for loop Shell producers; keep the two specs consistent when either is implemented.

## Out of scope for this iteration

Standalone Shell, Gate, Human isolation; F3.1b; sandboxing; Windows.
