# F1.6b - Tiered model ladder with a tool-less edit adapter

**Status:** draft
**Priority:** P1
**Target phase:** Phase 1 - Agent Loop (derived from F1.6)
**Registry:** `docs/roadmap/features.yaml` entry F1.6b
**Depends on:** F1.1, F1.6, F1.8, F3.8, F3.10
**ADR:** ADR-0047 (proposed)
**Issue:** #203

## Problem

Every Agent attempt today is a full coding-agent session (Codex; Claude Code
in #202). That cost is the same whether the unit is a one-line change in a
known file or an open-ended task. The correction loop (F1.6) can only retry
the same adapter, so a cheap first attempt with a stronger fallback is
inexpressible.

Comparable local tools (the adoption analysis against
`kacwojdev/agent-control-plane`) run small, scoped units on cheap tool-less
models and escalate to a strong model only after deterministic red verdicts.
They report accepted changes at around 0.0015 USD each. Users of such tools
will not move to AgentPlane if every attempt costs an agent session.

## Goal

An Agent node's loop can declare ordered **tiers**. The runtime picks the
adapter for each attempt from the tiers, escalates on exhaustion or on
repeated identical evidence, and keeps the total within `max_attempts`.

A new **tool-less `model` adapter** lets a tier be a single chat completion.
It talks to an OpenAI-compatible HTTP endpoint and applies the returned edits
itself, deterministically and only inside the declared write scope.

## Non-goals

- Model selection from a scoreboard, exploration or ranking. A tier is
  authored explicitly.
- "Repair from the best attempt" ranking (open question 2).
- Tool use, function calling, streaming tokens or multi-turn chat inside one
  attempt.
- Provider-native APIs other than OpenAI-compatible chat completions.
- Budgets and spend limits (F5.11) and cost aggregation UI (F3.10 owns usage).
- An LLM judge of any kind. Verdicts stay with the embedded Gate.

## Functional requirements

### A. Tiers on the loop

1. `loop.tiers` is an optional, nonempty ordered list. Each tier has:
   - `adapter`: a registered adapter ID (`model`, `codex`, `claude`, ...);
   - `attempts`: an integer from 1 to 10;
   - `config`: an optional adapter-specific mapping, for example the
     `model` adapter's `endpoint` and `model`.
2. Without `loop.tiers`, behavior and the graph's semantic hash are unchanged.
   The node's `config.adapter` is the only tier.
3. The sum of `attempts` over all tiers must equal `max_attempts`. A mismatch
   is a validation error (`E_LOOP_TIERS_BUDGET`), so the bound stays visible in
   one number.
4. Attempt *n* uses the first tier whose cumulative `attempts` is at least
   *n*. **Early escalation:** if two consecutive red Check Results on the same
   tier have identical evidence fingerprints, the tier's remaining attempts
   are skipped and the next tier starts. The fingerprint is the hash of the
   bounded, redacted evidence. Skipped attempts are not run and do not count
   as attempts.
5. Escalation carries the latest red Check Result as feedback to the next
   tier, exactly as a correction within one tier (F1.6 FR3).
6. Exhaustion of the last tier ends in `needs_intervention` (exit 4), as F1.6
   does today.

### B. The `model` adapter

7. The adapter implements the canonical interface (ADR-0034): `ID()` is
   `model`; `Detect` reports the configured endpoints; `Execute` performs one
   chat completion.
8. **Endpoints live outside the graph.** The runner receives
   `--model-endpoint NAME=URL` (repeatable). A key comes from a secret
   reference (F3.8) named `--model-endpoint-key NAME=SECRET_REF`. A graph
   names an endpoint only by `NAME` and a `model` string. URLs, keys and
   headers never appear in the graph or its hash.
9. **Prompt contents:** the task, the explicit `config.allowed_paths` file
   contents (required and nonempty for this adapter; directories are rejected),
   optional `context_refs` file contents, and on correction the previous
   attempt's Check Result. Nothing else is sent: no repository tree, history or
   environment.
10. **Reply format:** only `=== EDIT path ===` blocks holding SEARCH/REPLACE
    hunks, or `=== FILE path ===` blocks for files listed in `allowed_paths`
    that do not exist yet. The exact grammar is in ADR-0047.
11. **Application is deterministic and done by the adapter:**
    - every block must name a path in `allowed_paths`;
    - every SEARCH text must occur exactly once in the current file;
    - nothing is written unless all blocks validate;
    - symlinks, `..` segments and paths outside the workspace are rejected.
12. **Format and scope failures are red results, not errors.** An unparsable
    reply, or an edit outside `allowed_paths`, produces a red Check Result of
    kind `edit_format` or `edit_out_of_scope` with bounded evidence. The
    attempt consumes budget (open question 1) and its feedback reaches the next
    attempt. No file is written.
13. The adapter reports `changed_files` with provenance `reported` (the files
    it wrote). F1.8 Git observation, when configured, still runs.
14. The adapter reports `usage` (tokens, model name, provider cost and
    currency) only when the provider returns it. Absent data stays absent:
    unknown is never zero (F3.10-AC1).

### C. Egress and secrets

15. An endpoint whose host does not resolve to a loopback address is
    **remote**. A node may use a remote endpoint only when its tier config sets
    `data_egress: remote`. Without it, preflight fails with
    `E_MODEL_EGRESS_NOT_ALLOWED` before any request.
16. Before a request to a remote endpoint, the adapter runs the F3.8 secret
    scan on everything it would send. A hit fails the attempt as an
    operational error `E_MODEL_EGRESS_SECRET` naming the file and line, never
    the value. No request is made.
17. Requests use the standard library HTTP client with a bounded timeout and a
    bounded response size, and send no cookies. Providers that support it are
    asked not to retain the data. That is a request, not a guarantee, and docs
    must say so.

## Data / API contracts affected

- **Graph schema:** `loop.tiers`; `model` adapter config keys `endpoint`,
  `model`, `data_egress`, `temperature`, `max_output_tokens`; descriptors in
  `internal/fields`.
- **CLI:** `agentplane run --model-endpoint`, `--model-endpoint-key`; `serve`
  takes the same flags for the desktop sidecar.
- **Events (schema bump):** attempt events gain `tier` (index), `adapter` and
  `model`, plus an `escalated` reason (`tier_exhausted` or
  `identical_evidence`). The next free schema number is decided at
  implementation; 15 is current (ADR-0044).
- **Check Result:** new kinds `edit_format` and `edit_out_of_scope`, produced
  by the adapter boundary and not by a Gate. ADR-0047 decides how they are
  attributed.
- **Capability report** (ADR-0025): one `agent_adapter` row for `model`, with
  one row per configured endpoint (loopback or remote, reachable or not).

## Failure behavior

| Situation | Result |
| --- | --- |
| Tier budget sum does not equal `max_attempts`, unknown adapter in a tier, `model` adapter without `allowed_paths` | validation error, no run |
| Unknown endpoint name, remote endpoint without `data_egress: remote` | preflight error, no request |
| Secret found before a remote request | operational error for the node, no request, no verdict |
| HTTP error, timeout, oversized reply | operational error for the attempt; ADR-0047 decides whether a provider error consumes an attempt (recommended: no, with at most one transport retry) |
| Unparsable reply or edit outside scope | red `edit_format` or `edit_out_of_scope`, nothing written |

## Roadmap criteria

F1.6b is a derived entry with no roadmap criteria of its own. It does not
narrow F1.6: without `tiers`, every F1.6 criterion holds unchanged and is
re-run as a regression test.

## Acceptance criteria

- [ ] F1.6b-AC1: With tiers `[model ×2, fake-agent ×1]` and a permanently red Gate, exactly
  three attempts run, on tiers 1, 1 and 2, then `needs_intervention` (exit 4).
- [ ] F1.6b-AC2: Two consecutive red results with identical evidence on a tier with 3
  attempts escalate after the second; the trace records `identical_evidence`.
- [ ] F1.6b-AC3: A reply editing a path outside `allowed_paths`, or a reply that cannot be
  parsed, writes no file and yields red `edit_out_of_scope` or `edit_format` feedback.
- [ ] F1.6b-AC4: A remote endpoint without `data_egress: remote` fails preflight. A fake
  server records zero requests. A loopback endpoint runs.
- [ ] F1.6b-AC5: A scope file containing a resolved secret value with a remote endpoint
  fails the node before any request (zero requests at the fake server); the value
  does not appear in events.
- [ ] F1.6b-AC6: Provider usage is recorded per attempt. A reply without usage records
  none (not zero).
- [ ] F1.6b-AC7: No endpoint URL with credentials, API key, prompt or file content appears
  in events or `summary.json` (searched by test).
- [ ] F1.6b-AC8: Graphs without `loop.tiers` keep their semantic hash and F1.6 behavior.

## Required tests

- **Unit:** tier selection and early escalation; budget validation; the
  SEARCH/REPLACE parser and applier (unique match, all-or-nothing, path
  rules); egress classification.
- **Integration:** a loopback `httptest` fake provider plus the fake agent
  adapter driving the full loop.
- **CLI/e2e:** `agentplane run --model-endpoint local=http://127.0.0.1:PORT`
  with a `test_command` Gate (F1.4b), going red then green.

## Security / trust considerations

- **Untrusted input:** model output is untrusted. It is parsed, never
  executed, and applied only within `allowed_paths`. This is the
  "model output never reaches a shell" property of the reference project,
  enforced by construction.
- **Repository content leaves the machine** only for a remote endpoint, with
  explicit per-node consent and a secret scan. Loopback endpoints keep
  local-first intact.
- **Keys** come only from secret references, and the F3.8 redaction set
  covers them.

## Observability

- Attempt events carry `tier`, `adapter`, `model` and an escalation reason.
- Usage is recorded per attempt.
- `summary.json` shows per node which tier accepted the result. That is the
  metric for whether cheap tiers do real work ("% accepted at tier 1").

## Open questions

1. Should a format failure get one free retry on the same tier that does not
   consume `max_attempts`? The reference project does this and measured it as
   useful. It weakens the "one number bounds the loop" rule. Recommended: no
   for v1.
2. Should a correction start from the last attempt or from the best one
   (most passed criteria)? This needs evidence ranking. Recommended: last
   attempt in v1; ranking is a separate entry.
3. Is egress consent per node (as proposed) or also per run
   (`agentplane run --allow-egress`)? Recommended: per node, with the run flag
   only listing the nodes that will send data.
4. Should `claude` (#202) be usable as a tool-less top tier (no Bash, no
   edits) as in the reference project, or only as a full agent? Out of scope
   here; it follows #202.

## Out of scope for this iteration

Scoreboard and automatic model choice, repair-from-best, free format retry,
budget enforcement, streaming, non-OpenAI-compatible providers, desktop
editing of `tiers` (the inspector shows them read-only until F2.2 gains
descriptors).
