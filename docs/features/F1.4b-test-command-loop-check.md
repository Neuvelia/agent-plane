# F1.4b - Test command as a loop check (addendum to F1.4)

**Status:** implemented (ADR-0042, proposed)
**Priority:** P0
**Target phase:** Phase 1 - Agent Loop
**Depends on:** F1.4, F1.5, F1.6, F1.6a
**ADR:** ADR-0042 (proposed), following ADR-0037 (accepted direction); event schema 15 (ADR-0044)

## Problem

F1.4 AC1 says a failing test produces a red verdict that blocks downstream
work, and the Phase 1 exit criterion and Demo B expect "test fails, the agent
corrects only its unit". The Gate `command` kind accepts only `/usr/bin/diff`
(ADR-0012) and a non-zero Shell exit is fatal and not retried (ADR-0018), so a
real test command cannot be a loop check. The real F1.7 demo used a diff Gate
instead of a test (audit D12).

## Goal

A loop's embedded Gate can run a test command: exit 0 is green, any other exit
is red with bounded evidence, and the red result feeds the existing correction
loop. The side-effect policy is explicit.

## Non-goals

- Read-only enforcement, sandboxing, rollback or workspace isolation of the
  test command (F3.1, F3.9).
- A standalone `test_command` Gate node.
- Parsing test reports, per-test results or retry of flaky tests.
- Changing the diff `command` kind, the non-zero exit rule of Shell producers or
  the event schema number.

## Functional requirements

1. Gate kind `test_command` with config `check_id`, `command` (nonempty, argv,
   no shell), `args`, `cwd` (canonical absolute, existing directory),
   `env_allowlist`, `env`, `side_effects` (required: `none` or
   `workspace_writes`, no default) and `input` (required string or JSON port, the
   checked input). Unknown or foreign keys are rejected. `AGENTPLANE_ATTEMPT` is
   rejected in `env` and `env_allowlist`.
2. Valid only as a loop's embedded Gate for `shell` and `agent` producers
   (`LoopGateKinds`). A standalone Gate node with this kind fails validation
   with `E_NODE_CONFIG_INVALID`; the desktop does not offer it standalone.
3. Bound inputs never reach the command, args, cwd or environment. The child
   environment is empty except present `env_allowlist` values and explicit `env`.
   Under `isolation: worktree` (F3.1) the cwd is moved to the same place inside
   the worktree (`<repo>/service` runs in `<worktree>/service`); a cwd outside
   the source repository fails isolation preflight with `E_ISOLATION_PREFLIGHT`.
4. Exit 0 is green; any other exit status is a red Check Result of kind
   `test_command` with one evidence item: exit code, stdout and stderr bounded to
   8 KiB each after redaction, with omitted-byte counts.
5. Start failure, death by signal, cancellation, timeout (10 minutes by default,
   independent of node timeouts) and a missing cwd are operational errors, never
   a verdict.
6. The Check Result reason records the declared policy, for example
   `command exited 1; declared side_effects: workspace_writes`.
7. In a loop a red result re-runs only the producer node up to `max_attempts`; an
   Agent producer receives the Check Result as correction feedback, a Shell
   producer is re-run unchanged with `AGENTPLANE_ATTEMPT`. Exhaustion is
   `needs_intervention` (exit 4).
8. A Shell producer's non-zero exit stays fatal and is not retried; non-check
   Shell nodes, the diff `command` Gate and existing graphs keep behavior and
   semantic hashes.

## Side-effect policy

The check is not read-only and says so. `side_effects` is an author declaration,
recorded in the trace and not enforced. Side effects of rejected attempts and of
the test command persist; there is no isolation, rollback, network or filesystem
confinement. The command and its configuration are untrusted author input.
See ADR-0042.

## Data / API contracts affected

Gate config (new kind and keys), Check Result v1 (new kind `test_command`, any
non-negative exit code for that kind), `LoopGateKinds`, inspector field
descriptors and node catalogue fixture, graph validation
(`E_GATE_KIND_LOOP_ONLY`), the Gate executor's refusal outside a loop. The
kind exists from event schema 15 (ADR-0044).

## Failure behavior

Invalid or unsafe config fails validation before execution. A runner that cannot
start, is killed by a signal, times out or is cancelled fails the Gate node
operationally with no verdict and no retry.

## Acceptance criteria

- [x] F1.4b-AC1: Exit 0 is green; exit 1, 2 and 9 are red with the exit code recorded.
- [x] F1.4b-AC2: Red evidence is bounded to 8 KiB per stream with omitted counts and is a
  valid Check Result.
- [x] F1.4b-AC3: A Shell-producer loop with a failing then passing test check goes red then
  green with two attempts; exhaustion is `needs_intervention` exit 4.
- [x] F1.4b-AC4: A Shell producer's non-zero exit stays fatal under a `test_command` loop;
  `TestShellLoopNonZeroExitIsFatalNotRetried` is unchanged.
- [x] F1.4b-AC5: A runner that cannot start, times out or is cancelled yields an error, not a
  verdict.
- [x] F1.4b-AC6: The declared `side_effects` appears in the Check Result reason; omitting or
  misspelling it is rejected.
- [x] F1.4b-AC7: A standalone `test_command` Gate is rejected by validation and refused by the Gate executor.
- [x] F1.4b-AC8: Environment is explicit; reserved and mapped-input keys are rejected.
- [x] F1.4b-AC9: Descriptor/executor parity tests pass for the new kind.

## Required tests

- Unit: `internal/gate/test_command_test.go`, `fields_test.go`.
- Integration/CLI: `cmd/agentplane/test_gate_loop_test.go`.

## Security / trust considerations

The command runs author code with the runner's privileges. It must not inherit
secrets implicitly (explicit allowlist only; naming the variable behind a
secret reference is rejected by the ADR-0029 ambient-bypass check), evidence is
redacted with the run's redaction set and bounded,
and nothing weakens the diff Gate's read-only contract.

## Observability

One `gate_check` per attempt with kind `test_command`, exit code, bounded
evidence and the declared policy in the reason.

## Open questions

- A future execution policy (F3.9) may turn `side_effects` from a declaration
  into an enforced capability.

## Out of scope for this iteration

Sandboxing, per-test result parsing, standalone use, git-observed detection of
files the test command wrote.
